## What
Adds the missing SM110 arms to the `CUDA_CTA_RECONFIG_ACTIVATED` macro in
`include/cutlass/arch/reg_reconfig.h`, mirroring the existing pattern for
SM100/SM101/SM103/SM120/SM121. `include/cutlass/arch/config.h` already
fully defines SM110/SM110a/SM110f gated on CUDA 13.0+, and
`include/cutlass/arch/grid_dependency_control.h` already has the
analogous SM110 case for a sibling feature gate — this header was simply
never updated to match, so `warpgroup_reg_alloc`/`warpgroup_reg_dealloc`
compile to no-ops on SM110a instead of emitting
`setmaxnreg.inc/dec.sync.aligned.u32`.

Fixes #3576.

## Verification performed
Compile/PTX-only check with `nvcc -arch=sm_110a -ptx` in a CUDA 13.0.1
devel container (no physical GPU available to us):
- Before this patch: 0 `setmaxnreg` instructions emitted for a test
  kernel calling `warpgroup_reg_alloc`/`warpgroup_reg_dealloc`.
- After this patch: 2 `setmaxnreg` instructions emitted (inc + dec), with
  correct operands.
- Sanity check: the same before/after test was run against `-arch=sm_100a`
  (an already-working target) to confirm the harness correctly detects
  the instruction and that the existing SM100 path is unaffected by this
  change
<!-- upstream-excerpt-end -->
