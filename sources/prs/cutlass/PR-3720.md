## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Both `local_tile` examples in the docstring report the result shape as `(8, 6)`. That is the tile grid — the rest mode of the `zipped_divide` shown on the line above it — not the extracted tile, which is `(2, 4)`.

Verified on nvidia-cutlass-dsl 4.8.0, tiling a `(16, 24)` tensor by `(2, 4)`:

```python
t = cute.make_identity_tensor((16, 24))
cute.zipped_divide(t, (2, 4)).shape                                 # ((2, 4), (8, 6))
cute.local_tile(t, (2, 4), (1, 1)).shape                            # (2, 4)
cute.local_tile(t, (2, 2, 4), (0, 1, 1), proj=(1, None, 1)).shape   # (2, 4)
```

The second one is example 2's projected case, which lands on the same tile shape. Element values of the `coord=(1, 1)` tile are `(2,4) (2,5) (2,6) (2,7) (3,4) (3,5) (3,6) (3,7)`, consistent with a `(2, 4)` tile at tile-grid position `(1, 1)`.

Docstring-only change; comments only, no prose or code touched.
