## Summary

- Track completed CLC work tiles locally in the epilogue warps.
- Rotate TMA-store shared-memory stages using the epilogue's actual tile count.
- Prevent short-K dynamic persistent GEMMs from reusing an SMEM stage while its previous TMA store is still in flight.

## Root cause

`ClcDynamicPersistentTileScheduler` is instantiated independently in each specialized warp. Only the scheduler warp calls `advance_to_next_work()`, which increments that instance's `num_tiles_executed`. The TMA, MMA, and epilogue warps consume the CLC response through `get_current_work()`, so their scheduler-local counters remain zero.

The TMA-store epilogue uses `num_tiles_executed` to select its C-SMEM stage:

```text
c_buffer =
    (num_tiles_executed * subtile_count + subtile_idx)
    % num_c_stages
```

For the reproducer below, each M64xN256 output tile has four M64xN64 epilogue subtiles and a three-stage C-SMEM ring. A counter permanently equal to zero restarts every output tile at stage zero and can overwrite a stage still owned by an earlier asynchronous TMA store. Large K hides the race behind mainloop latency; short K exposes it.
