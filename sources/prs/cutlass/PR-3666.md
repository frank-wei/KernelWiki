## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
The `cutlass.range` docstring says `unroll` "0 or 1 = no unrolling", and the control-flow notebook says `unroll=0`/`1` is the plain staged loop. Only `1` disables unrolling: `LoopUnroll` sets `disable = true` only for `count == 1`, so `unroll=0` becomes `#llvm.loop_unroll<count = 0>` and the compiler picks the factor, as it does when `unroll` is left out. For a global-load loop with a runtime bound on sm_90a, `unroll=0` and no `unroll` give the same PTX apart from symbol names and the printf text (an x16 main loop plus leftover blocks), while `unroll=1` gives one rolled loop.

The same notebook sentence says `unroll_full=True` "would flatten a dynamic loop completely". For the same probe with a runtime `N`, it produces the same PTX as leaving `unroll` out. It only flattens when the trip count is a compile-time constant: `cutlass.range(6, unroll_full=True)` gives six straight-line loads.

It also says the loop "runs `N/K` times". With `unroll=3` or `unroll=4` and `N` not a multiple of `K`, the PTX has an `N // K`-trip main loop followed by a remainder loop for the last `N % K` iterations, so I spelled that out.

Checked with nvidia-cutlass-dsl 4.8.0 (CUDA 13.4) by dumping MLIR and P
