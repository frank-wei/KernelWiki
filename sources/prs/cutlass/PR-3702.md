## Summary

`KEEP=ir` and `KEEP=ir-debug` are how users inspect the IR that CuTeDSL generates, for example when they narrow down a code generation regression. Two problems make those dumps less useful than they should be, and this PR fixes both:

- **The raw IR is not exposed when both dumps are on.** With `KEEP=ir,ir-debug`, both dump paths went into `dump_mlir_path`, so `JitFunctionArtifacts.MLIR` held the clean IR, and the raw IR could only be found by searching the dump directory. The raw dump is now also exposed as `JitFunctionArtifacts.MLIR_RAW` whenever `KEEP=ir-debug` is set. `MLIR` is unchanged: it holds the clean IR with `KEEP=ir`, and the raw IR with only `KEEP=ir-debug`.
- **The clean IR loses its source locations.** The passes behind the clean dump run on a clone of the module, and the clone went through text: `str(module)` drops locations, and the textual form with debug info uses location aliases that some ops' parsers reject. So even with `CUTE_DSL_LINEINFO=1`, the clean IR could not be mapped back to the Python source.
