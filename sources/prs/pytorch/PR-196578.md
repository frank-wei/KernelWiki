## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Adds numerically accurate lowering for nextafter.

> **AI-assisted draft for that independent GitHub review:**
>
> ## Summary
>
> Fix Inductor's `torch.nextafter` lowering so compiled results match eager semantics for fp16, bf16, fp32, and fp64, including exact non-NaN bit patterns, non-contiguous inputs, and signaling-NaN quieting.
>
> Fixes #187340
>
> ## Root cause
>
> The generic numeric pointwise lowering widened fp16 and bf16 operands before taking a one-ULP step. The widened result could round back to the original low-precision value, making compiled `nextafter` a no-op. In addition, the libdevice fp32 path can flush subnormal steps around zero instead of producing the next representable value expected by eager execution.
>
> ## Fix
>
> - Add a dtype-aware lowering shared by ATen and prims, with `NO_OPMATH` dtype propagation.
> - Preserve fp16 and bf16 operands through code generation regardless of the global load-upcast setting.
> - Route Triton through `triton_helpers.nextafter`, using unsigned bit-pattern stepping for 16-bit and 32-bit values, fp64 libdevice handling, and explicit NaN quieting.
> - Remove `nextafter` from the operations expected to require fp32 upcasts.
>
