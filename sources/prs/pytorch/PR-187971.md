## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Stack from [ghstack](https://github.com/ezyang/ghstack/tree/0.15.0) (oldest at bottom):
* __->__ #187971

Adds an opt-in Inductor mode, `config.numerics = "strict"` (env `TORCHINDUCTOR_NUMERICS=strict`), that makes `torch.sum` reductions **bit-for-bit identical to eager** by reproducing eager's **INNER_TREE** reduction order.

Floating-point addition is non-associative, so `torch.compile` and eager normally disagree on the exact bits of a sum. Strict mode makes Inductor emit the same order eager uses: **"tree within a batch, linear across batches"**  each `R0_BLOCK` chunk is tree-reduced with Triton's deterministic `INNER_TREE` ordering, and the per-chunk partials are accumulated **linearly**. Inductor's default is the transpose (linear-accumulate into a tile, then one tree at the end).

When `numerics = "strict"`, Inductor emits:
```python
tl.sum(..., reduction_ordering=tl.constexpr(tl.ReductionOrdering.INNER_TREE))
```
plus a tree-then-linear loop structure and eager's exact `R0_BLOCK` / split.
