## Summary

`LaunchGammaBetaBackwardCUDAKernel`'s huge-M path (`M > 64 * 1024 && N / warp_size < sm_count / 2`) sizes its `dgamma_blocks` / `dbeta_blocks` scratch buffers from `dgamma->size(-1)` instead of `N`. This code sits outside every `#ifdef USE_ROCM`, so it's a shared CUDA/ROCm bug, not ROCm-specific.

`dgamma->size(-1)` is wrong in two cases:
- **Multi-dimensional `normalized_shape`**: `size(-1)` is only the last dim, which can be narrower than `N` (the product of all normalized dims). The kernel writes `N` columns per row into a buffer allocated with too few columns, an out-of-bounds device write.
- **Undefined gamma (`weight=None`)**: `size(-1)` on an undefined tensor silently returns `0` instead of raising, so `dbeta_blocks` (which is otherwise legitimately needed, since `bias` can still be defined) is allocated empty.

Both are reachable on CUDA as well as ROCm, any time `M > 64 * 1024` and `N` is small relative to `sm_count`.
