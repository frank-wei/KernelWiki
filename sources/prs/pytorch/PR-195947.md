<!-- upstream-excerpt-start -->
Partial fix for  #188005 - only for CUDA and NCCL backends.
https://github.com/pytorch/pytorch/issues/196337 is opened to address the NVSHMEM backend.

This PR is a step on the way to implementing per-PG signal pads, which would resolve https://github.com/pytorch/pytorch/issues/192581

Replace the advisory warn_if_multi_stream diagnostic with an RAII GroupStreamGuard that enforces correct stream ordering across all built-in symmetric-memory operations that touch the signal pad.

Signal pad operations use a CAS-based protocol on shared slots. When two operations for the same PG execute on different CUDA streams, the second CAS can find the slot still set by the first, causing deadlock.

The guard holds a per-(group_name, device) mutex across the guarded scope. On stream change, an event is recorded on the previous stream and the current stream waits on it. Same-stream fast path: one mutex acquisition and one pointer comparison, no event overhead. State is validated via weak_intrusive_ptr to detect PG destruction/name reuse, and held via shared_ptr to survive concurrent map replacement. No-op during CUDA graph capture, matching ProcessGroupNCCL's pattern.
