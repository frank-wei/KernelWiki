## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Fixes #200592

`launch_vectorized_layer_norm_kernel` always launches `num_threads() / warp_size` warps per row: (32, 8) on ROCm wave32, (64, 4) on wave64, (32, 4) on CUDA. Each thread reads one `vec_size`-element vector per iteration, so for rows narrower than `num_threads() * vec_size` most warps have nothing to read. They still take part in the `__syncthreads` cross-warp reduction in `compute_stats`, once per row, because the kernel runs one block per row. Per-head q/k norms (N = 64/128) hit this on every call.

This change launches just enough warps to cover `N / vec_size` vectors. The cap stays `num_threads() / warp_size`, so wide rows are unchanged. The kernel itself is untouched:

- every thread still reads the same vectors, and
- the non-empty partial sums are combined in the same order.

Only the merges with empty partials from idle warps go away.

## Results

Measured on a Radeon AI PRO R9700 (gfx1201, wave32). This PR's `launch_vectorized_layer_norm_kernel`, before and after, was compiled from torch 2.11's `layer_norm_kernel.cu` (whose launch code is identical to `main`) with `USE_LAYERNORM_FAST_RECIPROCAL` as in the ROCm build. The original launch reproduces `F.rms_norm`
