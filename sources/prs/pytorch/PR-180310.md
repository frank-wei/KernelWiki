## Problem

On ROCm/HIP, the HSA AQL dispatch packet stores global work sizes as `uint32_t`, imposing the constraint:

> `gridDim.{x,y,z} * blockDim.{x,y,z}` must be `< 2^32` per dimension

For large spatial outputs in `upsample_nearest2d` forward, this constraint is violated and HIP returns `hipErrorInvalidConfiguration`, manifesting as `torch.AcceleratorError: HIP error: invalid configuration argument`.

This is distinct from the per-dimension `gridDim.y <= 65535` limit on NVIDIA that `test_upsamplingNearest2d_launch_fail` / `test_upsamplingNearest2d_launch_rocm` already document: ROCm is more permissive on per-dimension grid size, but enforces a separate constraint that the total thread count (`gridDim * blockDim`) must remain below `UINT32_MAX`.

The affected launch path in `aten/src/ATen/native/cuda/UpSampleNearest2d.cu` is the NHWC (channels-last) 1D grid: `grid = ceil_div(output.numel(), num_threads)`. When `output.numel()` approaches `2^32`, `grid * num_threads >= 2^32`, hitting the HIP limit.

The NCHW (contiguous) 3D-grid path is not affected in practice: `grid_x`/`grid_y` are derived from the int-typed `output_width`/`output_height`, so each per-dimension grid is bounded
