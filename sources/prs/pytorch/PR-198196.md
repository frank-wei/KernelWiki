## Summary

The contiguous `upsample_nearest2d_backward` path derives its launch grid from
`grad_input.numel() / nbatch`. Large inputs can make
`gridDim.x * blockDim.x` exceed HIP's `UINT32_MAX` x-dimension work-size limit,
causing the launch to fail with `hipErrorInvalidConfiguration`.

On ROCm, clamp the launch grid to HIP's work-size limit, as the forward path
does. When the full grid cannot be launched, the kernel uses a grid-stride loop
to cover the remaining output. A compile-time flag preserves the existing
one-element-per-thread path for normal-sized inputs. CUDA keeps its current
launch and does not instantiate the grid-stride variant.

The batch offset is applied at the output store so the grid-stride cursor is
not modified inside the batch loop. This completes the backward-path TODO from
#180310.
