## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
hipify's `MATH_TRANSPILATIONS` rewrites `std::max(` and `std::min(` to `::max(` and `::min(` across entire `.cu`/`.cuh` files, including host code and AT_DISPATCH lambdas (which HIP compiles as `__host__ __device__`). On the host, clang's HIP headers only define `int max(const int, const int)` and `int min(const int, const int)` unless `__HIP_DEFINE_EXTENDED_HOST_MIN_MAX__` is defined (ROCm 7.2+, off by default), so 64-bit, unsigned and `size_t` arguments are silently narrowed to `int`. CUDA's host `::max` has 64-bit overloads, so this only breaks on ROCm.

This is the root cause of #199198. In `_bincount_cuda_template`, `std::max(self_max.item<input_t>() + (int64_t)1, minlength)` became `::max(...)`, so `nbins` = INT_MAX + 1001 wrapped negative and the max with `minlength = 0` returned 0. `CUDA_tensor_histogram` then took the shared-memory path and divided by `nbins * multiProcessorCount` on the host (SIGFPE). An audit of the ROCm build found 79 host-executed call sites passing non-`int` arguments through this rewrite.
