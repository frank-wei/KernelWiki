Human Notes:

Shared infrastructure we'll build on for the rest of the stack
* How we define an operator in a reasonably general manner -- per-element transforms, reduction specifics, etc.
* How we will launch a given generated kernel, wrap read-only inputs, etc.
* How to query the launch device and derive useful quantities for the eventual kernel definitions/launches.

Centralise all of this logic and re-use for everything that comes afterwards.

Codex:

capabilities, dtype mappings, and an instrumented plan cache used by the
remaining stack. Generic CuTeDSL helpers live in `torch._native.cutedsl`;
reduction traits live with their consumers in `torch._native.ops.reductions`.
