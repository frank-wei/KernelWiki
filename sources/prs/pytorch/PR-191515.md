> Enable shared Loop IR to CuTeDSL lowering for dense NVGEMM epilogues. The
> scheduler selects generated CuTeDSL source when the complete captured
> expression is supported and retains CUTLASS EVT lowering as the fallback.
>
> Preserve captured input dtypes and broadcast layouts, compose bias through
> the same epilogue plan, reuse common subexpressions, and reject unsupported
> operand swaps or reduction layouts before selecting the direct path.
>
> ## Example
>
> ```python
> result = (a @ b).float()
> return torch.relu(result), result + bias
> ```
>
> Both stores are generated from one captured Loop IR program. Expressions that
> cannot be represented by the direct path continue through EVT.
