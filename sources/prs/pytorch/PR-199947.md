## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
gatherMedian, shared by CUDA and ROCm, lets every thread that finds a value equal to the median write its index to the same output, so median(dim) and nanmedian(dim) return whichever index lands last, which can change from run to run when the median value repeats. #165762 fixed the same race in gatherKthValue.

This applies the same fix: matching threads take an atomicMin on a shared index and thread 0 writes the result after a barrier, so CUDA returns the first occurrence of the median value, as kthvalue does. The shared index is 64-bit because median, unlike kthvalue, allows slices longer than INT32_MAX.

Since the op is now deterministic, this removes its nondeterminism alert and its entry in the use_deterministic_algorithms docs, and replaces the alert test with one that checks the first-occurrence index. The alert is removed from the eager path and from the meta function, which is shared with mode; CUDA mode never had an eager alert, so that was a meta-only over-alert. The median docstrings now say CUDA returns the first occurrence and describe how the full-reduction gradient differs from median(dim).
