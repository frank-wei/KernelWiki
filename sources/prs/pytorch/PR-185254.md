## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Mostly used Codex to go and find and replace them. Manually reviewed them.

TLLDR: you almost always want to std::move on calling ctor on return statement because not doing so edits the order and content of the RAII of dtor. 99.999% of the time, you want the return type to consume / move it's inputs though. The compiler is unable to copy elide or move elide values which are consumed by a ctor in a return statement.
