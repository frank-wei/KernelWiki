## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Fixes #197673

`block_work_size * blockIdx.x` in `elementwise_kernel_with_index` is `int * unsigned int`, so it's computed in 32 bits and wraps before widening to `index_t`. For N >= 2**32, threads meant for index `2**32 + k` write to index `k` instead, and the tail is never written. The fix casts to `index_t` before multiplying. This affects arange, range, linspace and logspace, since they share this helper.

Test: the >2**32 cases in `test_range_factories_64bit_indexing` were ROCm-only; they now run on CUDA too. Changed `2**32 + 1` to `2**32 + 3` because the old expected tail `[-2, -1, 0]` also matches unwritten memory, so it couldn't catch this bug.

Verified on a T4 (torch 2.10.0+cu128) with a standalone copy of the kernel: the buggy version leaves all 1048576 tail elements unwritten, the fixed one writes them all correctly. I couldn't build PyTorch with CUDA locally, so I'm relying on CI for the full test.

**Disclosure:** The root-cause analysis and pr were drafted with Claude under my review. I ran the reproduction and the before/after kernel check myself on a Kaggle T4 (torch 2.10.0+cu128); the numbers above are from that run.
