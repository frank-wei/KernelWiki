## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
**BC breaking (unsupported-dtype error text only):** the amsgrad non-mixed-precision dispatch label was a copy-paste of the non-amsgrad one; it now carries the `amsgrad` suffix:

- `_fused_adam_amsgrad_cuda_impl_`: `fused_adam_kernel_cuda not implemented for 'X'` → `fused_adam_amsgrad_kernel_cuda not implemented for 'X'`
- `_fused_adamw_amsgrad_cuda_impl_`: `fused_adamw_kernel_cuda not implemented for 'X'` → `fused_adamw_amsgrad_kernel_cuda not implemented for 'X'`

Supported dtypes are unaffected.

Two no-functional-change cleanups in the fused Adam/AdamW CUDA implementations:

- `fused_adam_utils.cuh` redefined `ADAM_MODE`, an exact copy of the canonical enum in `ATen/native/FusedAdam.h`. Drop the copy and include that header (adding its missing include guard).
- The four `_fused_adam[w][_amsgrad]_cuda_impl_` files open-coded the same dispatch + `multi_tensor_apply` body, differing only by `ADAM_MODE` and `amsgrad`. Collapse them into one `template <ADAM_MODE mode, bool amsgrad>` launcher in `fused_adam_utils.cuh`; each `.cu` keeps two thin public overloads. `AT_DISPATCH` stays in the template body, so each `.cu` still instantiates only its own kernel set. Net ~300 fewer lines.
<!-- upstream-excerpt-end -->
