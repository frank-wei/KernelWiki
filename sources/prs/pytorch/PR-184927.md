## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Stack from [ghstack](https://github.com/ezyang/ghstack/tree/0.15.0) (oldest at bottom):
* __->__ #184927
* #184926

Adds a second cutedsl topk kernel covering K in {16, 32}, where the
radix kernel can't run (K>=64) and one-CTA-per-row's launch overhead
dominates anyway. One warp per row, register-resident keys, no smem
or global staging - only the final K writes hit gmem.

Structurally similar to quack's small-K topk, but lossless: keys carry
the full original index so output is bit-exact to aten on values with
deterministic tie order, at the cost of lower throughput.

Dispatch in cutedsl_impl.py:
  * K=16, N pow2 in [64, 2048]: register kernel
  * K=32, N=256:                register kernel
  * K in {64..1024} with existing radix N gates: radix
  * else: aten

On B200: K=16 2.24x geomean (1.16-4.45x), K=32 1.04x geomean
(1.00-1.45x), no regressions across the eligible (K, N, M) grid.

Test plan:

    python test/python_native/test_topk_cutedsl.py
