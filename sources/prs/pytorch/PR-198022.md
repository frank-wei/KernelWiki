## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
`_efficient_attention_forward` with zero heads fails on ROCm with hipErrorInvalidValue under the AOTriton backend and with the fp16/bf16 dtype check under CK, because the ROCm branch hands empty tensors straight to the backend; the CUTLASS path returns early for zero heads. This adds an early return to the ROCm forward whenever the output is empty (zero heads, zero query length, zero batch or zero value dim), producing the empty output, a zero-filled logsumexp of the shape the AOTriton path uses (it is non-empty when only the value dim is zero), and the seed/offset tensors as already constructed; and to the ROCm backward when grad_out is empty, returning zeroed gradients. Empty keys with a non-empty query are left to the backends as before.

The rest of the diff is `test_transformers.py`.
