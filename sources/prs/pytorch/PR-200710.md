## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Summary:
Vendored quack relied on upstream's `quack.dsl.mixed_constexpr_if`, which monkey-patches the global CuTe `DSLPreprocessor` so `if const_expr(S) and/or D:` folds the static term at trace time. The install is guarded by a class-level flag shared by every quack copy. When another copy loads first, it sets that flag, torch's install is skipped, and torch's quack kernels are traced without the rewrite. Inductor's sm100 `X @ X.T` -> quack symmetric GEMM path then fails with `NameError: cannot access free variable 'split_idx'` in `epilogue_split_k`, which killed GB300 GRPO jobs.

The unscoped patch also rewrites every non-quack CuTe kernel traced in the process, such as FA4.

Fix this in the source instead of at runtime: a new vendoring patch (`0010-explicit-constexpr-if.patch`) rewrites the seven mixed tests into explicit `if const_expr(S): ... elif D: ...` nesting. That is the same AST the rewrite produced, so codegen is unchanged. The patch also drops the `mixed_constexpr_if` import from `dsl/__init__.py`, and `vendor.sh` no longer vendors the module. Torch's quack no longer touches global DSL state, so import order with other quack copies does not matter.

`test_quack_vendor`
