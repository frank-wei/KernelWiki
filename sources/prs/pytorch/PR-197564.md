The BLAS bypass for `add(S, S, out=T)` on sparse compressed tensors (`only_sparse_compressed_binary_op_trivial_cases`, from #95293) hands `T` the same crow/col index tensors as `S`, not copies. Any later out-of-place `add(C, D, out=T)` then rewrites `S`'s indices in place. In `test_sparse_add`, `add(S0, S0, out=S1)` and `add(S0, S0, out=S2)` leave all three operands sharing one `crow_indices` buffer. With int32 indices, every later `csrgeam2` call then runs with `csr_row_ptr_C == csr_row_ptr_A == csr_row_ptr_B`. rocSPARSE forbids that overlap, and cuSPARSE doesn't document it as supported. rocSPARSE's `csrgeam_nnz` writes `row_ptr_C[row]` while other wavefronts still read `row_ptr_A[row + 1]`, so under load rows collapse and the test returns wrong values (#167783). With int64 indices the library works on int32 copies, but the result is copied back into the shared buffer, so `S` is corrupted on every backend.
