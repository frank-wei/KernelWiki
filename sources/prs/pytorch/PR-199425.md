## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Since #171940, ROCm's single-block `gatherTopK` reserves output slots with a per-warp `atomicAdd`, so warp arrival order decides the gather order. With `sorted=False`, topk can return its indices in a different order from run to run, for any dtype; with `sorted=True`, tied values can come back in varying order, and phase 2 can keep different tied k-th elements. CUDA's prefix-scan gather is stable. Slices of 256 or fewer take ROCm's warp-level topk path, which is already deterministic, which is why reports start at 257 columns.

This keeps #171940's per-warp ballot counting but replaces the atomic with an ordered exchange: each warp publishes its count to shared memory, one `__syncthreads()`, then a shuffle scan gives each warp its offset. On MI355X (gfx950) the output was bit-identical to the prefix-scan gather across 384 configs. With #171940's benchmark, the single-block path is about 4% slower than the atomic version and about 1% faster than the pre-#171940 prefix scan.

Fixes #196177
