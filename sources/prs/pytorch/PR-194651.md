Human commentary: ModelOpt NVFP4 linear layers multiply `_scaled_mm` output by a scalar dequantization factor. Folding that factor before QKV fan-out removes one standalone scale launch per layer and lets autotuning consider the GEMM implementation that applies it directly.

AI-assisted content:

> ## Problem
>
> Fixes #198173
>
> ModelOpt NVFP4 linears materialize a separate pointwise multiply after `_scaled_mm`. That launch is especially visible during decode. Waiting until scheduler fusion is too late for two reasons: GEMM candidates have already been constructed, so native NVGEMM output scaling cannot participate in autotuning; and a QKV split/view fan-out no longer looks like one simple pointwise suffix that the scheduler can attach to a single producer.
>
> ## Summary
>
> Fold eligible NVFP4 output scaling into the selected scaled-matmul implementation while preserving semantically equivalent ATen fallback choices and tensor-parallel transformations.
>
> ## Architecture
>
> Two post-grad graph patterns recognize `aten._scaled_mm(...) * output
