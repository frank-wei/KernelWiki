## Agent details (if applicable)

> Prepared with an AI assistant (Cursor agent).

> **Root cause.** On ROCm, `launch_vectorized_layer_norm_kernel` splits launches whose `gridDim.x * blockDim.x` would exceed `UINT32_MAX` into chunks of `UINT32_MAX / warp_size` rows. Between chunks it advanced `X` and `Y` by `N * blocks.x`, where `N` is `int` and `blocks.x` is `unsigned int`, so the offset was computed in 32 bits and wrapped once `N * rows_per_launch` reached 2^32 (`N >= 65` on wave64). Later chunks normalized the wrong rows, the trailing output rows were never written, and `mean`/`rstd` for those rows held other rows' statistics, which also broke the backward. `_fused_rms_norm` shares the launcher and was affected the same way. #186956 changed only the non-vectorized fallback (used for `N % 4 != 0`), so it did not cover this path.
>
> **Fix.** Compute the offset in 64 bits. Inputs with at most 67,108,863 rows on wave64 never enter this loop and are unaffected.
