This PR addresses beta user feedback on `fold_in(key, data)`:
* Tightens up the support regarding dtype for `data`; we now explicitly support ints in the range `[-2**63, 2**64 - 1]` (i.e. all signed int64 AND uint64 values) with negative values reinterpreted as two's complement of uint64 values, following the precedent set by [`manual_seed()`](https://docs.pytorch.org/docs/2.13/generated/torch.manual_seed.html). This requires some python-side gymnastics since we utilize the standard ATen op parsing logic that treats ints as int64. Docs were also updated to indicate this.
* Adds a Tensor `data` ATen op overload that can be used to avoid baking in `data` to captured CUDAGraphs. Note that, for simplicity, we only allow a single item Tensor `data` for now. In the future, if necessary, we can support folding broadcastable data across a batched set of keys.
