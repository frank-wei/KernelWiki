## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Fixes #134607

### Summary

`torch.angle` supports `float16`/`bfloat16` on CPU but raised `"angle_cuda not implemented for 'Half'/'BFloat16'"` on CUDA — an unnecessary CPU/CUDA parity gap.

```python
torch.angle(torch.tensor([-1.0, 1.0], dtype=torch.bfloat16))          # CPU: [3.14, 0.0]
torch.angle(torch.tensor([-1.0, 1.0], dtype=torch.bfloat16).cuda())   # before: RuntimeError
```

### Fix

The real-dtype branch of `angle_kernel_cuda` used `AT_DISPATCH_FLOATING_TYPES` (float/double only). Switch it to `AT_DISPATCH_FLOATING_TYPES_AND2(kHalf, kBFloat16, ...)`, matching the CPU kernel which already uses `AT_DISPATCH_FLOATING_AND_COMPLEX_TYPES_AND2(kBFloat16, kHalf, ...)`. Also updated `angle`'s OpInfo `dtypesIfCUDA` / `backward_dtypesIfCUDA` to list the newly supported dtypes (which enables the existing dtype-coverage tests for them).

### Test Plan

```
python test/test_ops.py -k test_dtypes_angle
python test/test_unary_ufuncs.py -k angle
```

Verified on an **A100**:
- `angle` for `float16`/`bfloat16` on CUDA now matches CPU exactly (forward and backward)
- `float32`/`float64` and complex dtypes unchanged
- `test_dtypes_angle_cuda` passes; 291 `angle` unary-ufunc tests pass
