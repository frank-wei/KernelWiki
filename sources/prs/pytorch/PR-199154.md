Part of the set of changes the two-phase precompile workflow needs at pytorch tip, on top of the open precompile stack that ends in #198558. Second of two changes that let precompile carry Triton's runtime JIT cache itself; the previous PR adds the export side.

**Why precompile needs this.** A serving process loads a captured artifact under `precompile.no_compilation()` and should launch the user's `@triton.jit`/`@triton.autotune` kernels without compiling or benchmarking. That only works if Triton's cache directory already holds the capture's entries before the first launch, and holds exactly those entries. A partly written directory, a bundle from a different Triton build, or a directory that already holds something else would make Triton silently recompile or reuse the wrong binary.

**What.** Adds `import_runtime_cache(bundle, context=...)` to `torch/compiler/_triton_runtime_cache.py`:
