## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
`torch.cuda.get_device_properties(i).clock_rate` and `.memory_clock_rate` ignore the properties object and call `cudaDeviceGetAttribute` for `c10::cuda::current_device()`, so they return the current device's value for every `i`. Callers that pass a non-current device get the wrong clock on a host with mixed GPU models: the CUDA branch of `max_clock_rate`, and `torch.cuda._device_limits.GPULimits`. This came up in review of #198202.

Only `_get_device_properties` hands these objects to Python, as references into the per-device cache behind `at::cuda::getDeviceProperties`, so the binding now finds the device by comparing the object's address against the cached entries and queries that device. Binding the struct fields directly would be simpler, but `cudaDeviceProp` in CUDA 13.1 has no `clockRate` or `memoryClockRate` field.

This also removes the two `with torch.cuda.device(...)` workarounds for the bug, in the ROCm branch of `max_clock_rate` (#198202) and in cutedsl's `HWCaps`.
