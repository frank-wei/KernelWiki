## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Performance improvement for topK on ROCm.

#199425 made ROCm's single-block gatherTopK deterministic with an ordered per-warp exchange that costs a barrier and a shuffle scan per gather iteration. On MI355X that left the path 2 to 4% behind the old atomicAdd kernel.

This makes the exchange cheaper and less frequent while keeping the output order and tie choice unchanged. The cross-warp scan uses readlane broadcasts on all non-SPIR-V targets, plus DPP row adds on GFX9; wave32 and SPIR-V keep a shuffle scan. Slices longer than the block run four block-strided sub-iterations per barrier, with two 16-bit counts per LDS word. Elements equal to the k-th value are ranked during phase 1, so phase 2 skips its second pass over the slice unless a thread holds more than two of them.

The kernel was generated with AMD's GEAK optimization workflow driving Claude, against a harness that required output bit-identical to #199425 and compiled every candidate for gfx950, gfx1100, gfx1151 and amdgcnspirv.
