Fixes #188545

## Summary

Preserve eager-mode semantics for infinite inputs in the Triton lowering of

- `torch.special.bessel_j0`
- `torch.special.bessel_j1`
- `torch.special.bessel_y0`
- `torch.special.bessel_y1`

Previously, the Triton lowering called libdevice directly. For ±inf inputs,
libdevice returns the mathematical limit, whereas eager mode returns NaN,
leading to an output mismatch between eager execution and torch.compile.

This change explicitly returns NaN for ±inf before calling libdevice,
matching eager behavior while leaving all finite inputs unchanged.

## Testing

Added a regression test covering:

- `torch.special.bessel_j0`
- `torch.special.bessel_j1`
- `torch.special.bessel_y0`
- `torch.special.bessel_y1`

for both float32 and float64, verifying that compiled execution matches
eager mode for infinite inputs.
