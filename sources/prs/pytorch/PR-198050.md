# Problem
Inductor uses a helper function called `user_defined_triton_kernel_transitive_closure_source_code` to pull in any source code for helper functions called by user-defined Triton kernels. One issue with this approach is it may also pull in large libraries which are already imported. For example, if we have
```
import foo
import triton

triton.jit
def kernel():
    foo.bar()
```

This helper would pull in all the source code for the `foo` module, even though it is already imported.

This is not a problem for OSS Inductor per se, but it ends up causing some inconvenience to closed-source extensions which have large helper kernel libraries. This ends up bloating log files, kernel source code, etc.

# Solution
This PR refactors the helper into two components.
- `user_defined_triton_kernel_transitive_closure`: extracts a list of modules called by the Triton kernel, and their source code. Contains most of the original implementation.
 - `user_defined_triton_kernel_transitive_closure_source_code` : the original API. Calls the former, collects the modules then formats them.
