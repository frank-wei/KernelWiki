Human commentary: Short NVFP4 inference GEMMs need a small automatic candidate set and measurements that reflect transformer decode execution.

AI-assisted content:

> ## Problem
>
> Fixes #198172
>
> `nvMatmulHeuristics` does not cover several Blackwell NVFP4 decode winners, while an unrestricted supplemental pool adds substantial compile and profiling cost. The related shape rules were also split between code generation and candidate filtering, which made the policy difficult to audit.
>
> ## Summary
>
> Add a bounded, shape-aware NVFP4 candidate policy for Blackwell decode workloads and centralize every NVFP4 shape decision in the NVGEMM heuristics module.
>
> ## Architecture
>
> `torch/_inductor/heuristics/template/nv_universal_gemm.py` is the single policy boundary. It identifies the NVFP4 1x16 recipe, decides when to expose swap-AB, chooses the CUDA-graph replay count and cold-weight scope, applies the profiling cap, and returns the shape-scoped primary and prefetch candidate keys. The codegen integration passes problem metadata to these help
