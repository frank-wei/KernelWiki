## Human Note
For batch and head dims that exceed the grid cap, we just launch multiple kernels

used some features found in https://github.com/pytorch/pytorch/pull/177985

## Agent Report
> ### Agent details
>
> Prepared with AI assistance. CUDA grid.y/grid.z cannot exceed 65,535 blocks. Chunk the
> memory-efficient forward/backward launch grids while retaining full tensor dimensions and
> logical batch/head offsets. Kernels write directly into final outputs, preserving GQA mapping,
> dropout RNG indexing and CUDA-graph support without tensor-chunk copies.
>
> CUDA bypasses the old batch-copying wrapper and its dropout restriction; ROCm behavior is
> unchanged. Dense flash attention declines oversized batch/head dimensions so default SDPA
> reaches a supported backend. The existing cuDNN size guard is unchanged.
>
