## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
`avg_pool2d_backward_out_cuda`'s channels_last (NHWC) kernel variant needs more registers per thread than the plain NCHW kernel for its extra index/stride math. On sm10x+ (Blackwell/Rubin) devices this overflows the register budget at 1024 threads/block and fails with `"too many resources requested for launch"` -- independent of dtype.

The existing sm10x thread-count reduction (768 threads, #145669 / #150640) was scoped to `scalar_t == double` only, which happened to mask the issue for double (the sole dtype getting the reduced count) while leaving float32/bfloat16/half still broken.

Confirmed on NVIDIA Rubin hardware (sm_107): channels_last backward fails for float32/bf16/fp16 but passes for float64, while plain contiguous backward is fine at 1024 threads for every dtype -- i.e. this is a kernel-variant x architecture issue, not a dtype issue.

| dtype | contiguous | channels_last |
|---|---|---|
| float32 | OK | **FAILED** |
| float64 | OK | OK |
| bfloat16 | OK | **FAILED** |
| float16 | OK | **FAILED** |
