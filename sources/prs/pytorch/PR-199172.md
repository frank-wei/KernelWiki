Barebones unsigned types (e.g uint64) are not supported today in `torch._foreach_copy_` fused kernels. This is a problem when passing a stateless RNG API key to a compiled function while using CUDAGraphs, as the expected key dtype is uint64 and `_foreach_copy_` is invoked:
```python
import torch
import torch.func._random as r

def f(key):
    return r.uniform(key, (2, 3))

compiled_f = torch.compile(f, fullgraph=True, mode="reduce-overhead")
key = r.key(42, device="cuda")

# NotImplementedError: "foreach_tensor_copy" not implemented for 'UInt64'
compiled_f(key)
```

The fix in this PR is to fallback to the slow, iterative path for barebones unsigned types. An alternative fix could add proper foreach support for such dtypes.
