nn.Embedding backward with at most 3072 indices and scale_grad_by_freq=False runs embedding_backward_feature_kernel, which is meant to be deterministic: contributions to the same row are serialized in shared memory by an elected leader warp. But each batch iteration overwrites the shared indices_batch buffer before any barrier, while warps still finishing the previous batch's last chunk read that buffer to compute their match mask. A warp delayed between the chunk's second __syncthreads() and its match compare, which is what time-slicing against another process on the same GPU produces, reads the next batch's indices, elects the wrong leader or peer set, and the row's gradient is dropped or double counted. Solo runs almost never hit the window; with a co-tenant on the GPU the embedding gradient changes run to run, and so does everything trained from it, even under torch.use_deterministic_algorithms(True).
