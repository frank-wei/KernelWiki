## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
`ROCmConfigHeuristic` can emit GEMM configs with `kpack=2` whose `BLOCK_K` is smaller than `kpack * kdim`, the K extent of the packed MFMA operand (e.g. `BLOCK_K=16`, `matrix_instr_nonkdim=16`, `kpack=2` for fp16). With Triton 3.5.1 (torch 2.9.0) such configs produced incorrect results. The Triton pinned on main (3.8) instead clamps kWidth back to the `kpack=1` value, so there they only duplicate `kpack=1` configs and add autotuning time.

This PR:
- prunes configs whose explicit `kpack > 1` underfills the MFMA operand, checking `BLOCK_K >= kpack * kdim` against a per-arch, per-dtype `mfma_kdim` table (dtypes not in the table are not checked). A defaulted `kpack` that would underfill is lowered to 1 instead, so small-K shapes still get a valid config.
- only generates `kpack=2` where it changes codegen (gfx908/gfx90a/gfx942, `kpack_supported()`): Triton forces `kpack=1` on gfx950, and RDNA/gfx1250 compile identically for 1 and 2.
- removes the unused `_prune_exhaustive_configs`.
