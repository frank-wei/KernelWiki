Summary:
Context

PyTorch issue #199553 reports a severe CUDA cumsum performance cliff for tensors with short innermost dimensions and many rows. get_log_num_threads_x_inner_scan was instantiated with uint32_t, so subtracting a larger log_num_threads_y from log_num_threads_x underflowed. For a 4097 x 8 tensor, the wrapped value was clamped to 9 and selected a 512 x 1 block instead of processing 32 rows per 16 x 32 block. The same helper is shared by CUDA cumsum, cumprod, cummin/cummax, and logcumsumexp.

Change

Make the launch-configuration helper accept signed int64_t dimensions and perform all logarithm, difference, balancing, and clamping arithmetic in int64_t. Convert to uint32_t only after the result is constrained to the valid [4, 9] range. This makes unsigned underflow impossible at the helper boundary while preserving the existing launch heuristic for unaffected shapes.

Add a focused CUDA unit test covering the 4096/4097 transition and the reported 95760 x 8 workload. Register the test in the upstream CMake CUDA test suite and keep the fbcode/xplat source mirrors byte-identical.
