## Summary

- When `C10_USE_ROCM_KERNEL_ASSERT` is enabled on ROCm, device-side **`CUDA_KERNEL_ASSERT`** builds the full message at the **macro call site** via `constexpr rocm_assert_concat(RoCmAssertLit<...>, ...)` (compile-time `%` escape + exact buffer sizing) and emits it with a single merged **`__host__ __device__ inline`** OCKL helper (`rocm_assert_one_shot`, `always_inline` + `flatten`).
- Device path is gated on **`#if defined(USE_ROCM) && defined(__HIP_DEVICE_COMPILE__)`**; host pass uses stock **`__assert_fail`** (correct call-site `__func__`, no runtime wrapper).
- **`CUDA_KERNEL_ASSERT_MSG`** still uses stock `__assert_fail` on ROCm.
- **`CUDA_KERNEL_ASSERT_PRINTF`**: `#cond` passed as **`%s`** (not spliced into the format literal), fixing the same `%`-in-condition corruption class as `CUDA_KERNEL_ASSERT`.
- Device message format matches stock HIP: ``file:line: __func__: Device-side assertion `cond' failed.\n`` (backtick + condition + single quote before ` failed.`).
- **CMake default is ON for this branch** through final CI (assert path exercised by default). **Before merge:** revert to **OFF** (enable-on deferred to #192542).
