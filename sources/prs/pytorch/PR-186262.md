Fixes https://github.com/pytorch/pytorch/issues/186220.

TritonTemplate, CuteDSLTemplate, and ExternKernelChoice register themselves
into process-global registries at module-init time, guarded by hard asserts
that forbid any name that is already present. If the registering module is
initialized twice in a single process (e.g. a double-import path, reported on
the 2.11.0+cu130 Blackwell build), the second initialization re-runs the same
registration and the assert turns a benign duplicate into a fatal crash during
import -- before any compilation runs.

Relax each guard so that re-registering under an existing name is tolerated as
long as it is equivalent to what is already registered (matching template source
hash for templates, matching wrapped callable for extern kernels), while a
genuine name collision between different templates/kernels still raises. The
assignment that follows is unconditional so the registry and the module-level
symbol that constructed the instance continue to refer to the same object.
