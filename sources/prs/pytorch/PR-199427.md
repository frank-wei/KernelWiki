## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Summary:

Stop the parent Inductor process from importing the Triton 3.8 TLX registry when TLX is off: the import replaces `config.inductor_choices_class`, which changes the PT2 FX graph cache key (S713810). Replaces D122693730 with a smaller fix.

- **Parent gate**: `tlx_only_cuda_options` / `tlx_only_hip_options` return `[]` without importing the registry when `tlx_mode` is off in the top-level process.
- **Workers ungated**: compile workers don't inherit a `config.patch`'d `tlx_mode`, so they still read the registry, and enabled `ctas_per_cga` is never dropped.
- **Cached import**: `_tlx_registry()` caches the import result or failure; the mode check sits outside the cache, so turning TLX on later still works.
- **3.8 vs beta**: `getattr(registry, ..., [])` keeps 3.8, which has no `tlx_only_hip_options`, returning `[]`.
- **No `async_compile.py` change**: the default worker path is untouched.

Test Plan:
CPU-only, Triton-3.8 tests: no registry import in the parent while TLX is off, stable `FxGraphHashDetails`, `["ctas_per_cga"]` after switching to `tlx_mode="allow"`, HIP options stay `[]`, and workers keep the options.
