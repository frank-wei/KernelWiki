### Summary

The spatial softmax backward kernel still indexes with 32-bit math, so it
produces wrong gradients on tensors that the forward pass already handles
correctly.

`cunn_SpatialSoftMaxBackward` runs whenever softmax/log_softmax is taken over a
non-last dimension (`inner_size != 1`). It hardcodes `uint32_t` for the sizes
and for every offset:

```cpp
const uint32_t outer_stride = inner_size * dim_size;
...
gradInput[data_offset + d * dim_stride] = ...
```

The forward kernel `cunn_SpatialSoftMaxForward` was already templated on
`index_t` and picks 32- vs 64-bit indexing at launch via
`canUse32BitIndexMath`, but the backward kernel was left on `uint32_t`. Once a
tensor crosses `2**32` elements, `outer_stride` and the per-element offsets wrap
around, so the gradient is silently corrupted (and can fault) on exactly the
large spatial inputs the forward path supports.

### Fix

Template `cunn_SpatialSoftMaxBackward` on `index_t` and wrap its launch in
`AT_DISPATCH_INDEX_TYPES(... canUse32BitIndexMath(grad, INT_MAX) ...)`, mirroring
