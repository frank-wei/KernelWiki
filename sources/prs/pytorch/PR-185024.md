* __->__ #185024

reflection_pad1d forward was already updated in #165942 to avoid encoding large plane or batch counts directly in the CUDA grid. The backward kernel still launched dim3(ceil(output_w / 256), nplane, nbatch), so a tensor with 65536 planes or batches exceeded the device y/z grid limit and failed at launch with cudaErrorInvalidConfiguration before doing any work.

This changes backward to mirror the forward launch policy: use the existing 3D grid when it fits the current device limits, and otherwise use a flat grid-stride kernel over all output elements. The flat path keeps indexing in int64 and accumulates into grad_input with the same reflection mapping. The legacy 1D x index is also made explicitly int64 so the fast path does not overflow before the limit checks matter.

The alternative was to cap y/z and loop over chunks on the host. A flat grid-stride fallback matches the forward fix, avoids extra launches, and keeps oversized-grid handling in one kernel path.

Fixes #167902
