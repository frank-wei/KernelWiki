## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
This is a follow-up as described in the linked issue.  cc @kapilsh



> nccl_put, nccl_get, nccl_put_with_signal and nccl_wait_for_signal take a tensor rather than a handle, so they rendezvous it themselves, on the group named "0"; #195947 also guarded the signal ops on "0", and its review asked for the group to be surfaced instead.
>
>   The ops now take an optional group_name for the rendezvous and the stream guard, so they work on any group. Without one they still use "0", so existing callers are unaffected.
>
>   SymmetricMemory::get_group_name() reports the group a handle was rendezvoused on (hdl.group_name in Python), and the signal ops guard on it. The base class raises NYI, like the other optional getters, so out-of-tree subclasses such as XPU's keep compiling.
>
>   Authored with the assistance of an AI coding assistant.
>
