`native_group_norm` and `native_group_norm_backward` have always assumed contiguity for some tensors, and asserted it for others. The assertions cause unexpected behavior for `vmap`, which may batch in non-contiguous ways. The assumptions (obviously) can cause memory access errors. This PR changes the implementations to instead call `contiguous()` with an appropriate memory format, which fixes vmap and the OOB accesses without using any extra memory in situations where callers have already ensured contiguous inputs.

This does mean that a situation which previously threw an error (non-contiguous X) now succeeds silently with an extra allocation. It's unlikely that anyone is relying on this behavior, however, since most people would have been calling `native_group_norm` through `nn.functional.group_norm`, which already did calls to `contiguous()`.
