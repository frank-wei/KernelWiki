## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
**Problem**: worker_start_method="subprocess" (the default) uses SubprocPool which calls
  pre_fork_setup() → caching_device_properties() → torch.cuda.get_device_properties()
  in the sidecar, initializing CUDA. Workers forked from the sidecar then can't use
  torch.cuda.* operations. CuTe DSL and NV Universal GEMM precompile functions called
  torch.cuda.set_device(), torch.empty(device="cuda"), etc., causing "Cannot
  re-initialize CUDA in forked subprocess".

  **Fix**: Eliminated all torch.cuda.* calls from the precompile path:

  1. cutedsl_cache.py: Added optional device_capability parameter to _make_disk_key,
  disk_cache_get, disk_cache_set — avoids torch.cuda.get_device_capability() in workers
   when the main process provides it.
  2. Scheduling files: Both cutedsl_scheduling.py and nv_universal_gemm_scheduling.py
  now include device_capability in the precompile metadata.
  3. nv_universal_gemm.py.jinja: Precompile uses FakeTensorMode to create FakeTensors
  instead of real CUDA tensors. cutlass_api TensorWrapper already handles FakeTensors
  (sets data_ptr=0, uses make_fake_compact_tensor for compilation).
  4. cutedsl_mm_grouped.py.jinja: Restructured precompile to cal
<!-- upstream-excerpt-end -->
