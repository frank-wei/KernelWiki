## Summary
- `cub::detail::ptx_compute_cap` now verifies (via `_CCCL_VERIFY`) that the queried compute capability is one of `__CUDA_ARCH_LIST__`/`NV_TARGET_SM_INTEGER_LIST`, surfacing a clear diagnostic instead of silently dispatching with a bogus value.
- `cub::detail::dispatch_to_cc_list` now returns `cudaErrorInvalidPtx` instead of `cudaErrorInvalidDeviceFunction` when no compiled policy matches the runtime compute capability, since the latter is too easily mistaken for an unrelated CUDA driver/runtime failure.

Context: nvlink can clamp a kernel's reported PTX version below the architecture it was actually compiled for when relocatable device code links against a translation unit compiled for a lower architecture (#11403). There is currently no CUDA API to recover the true `__CUDA_ARCH__` the compiler used at that call site, so for now this can only be detected, not corrected.
