## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Currently functions in `cuda::__driver` marked as NoThrow can still actually throw in the `dlopen`, `cuinit` or `cuGetProcAddress`. So far it was mostly fine, because the functions that were marked as NoThrow were mostly for destroying things, so they were unlikely to fail in any of those steps.
For we are adding more APIs that can fail in those steps that are marked as NoThrow for post-failure analysis.
This PR refactors the Driver API to return a more rich status object that contain more information about what exactly failed, not just `cudaError_t`. It also adds a function that converts that status structure into an exception and throws it to implement the throwing driver calls.

The status object implicitly converts to `cudaError_t` for compatibility, but follow-up change might remove it once consumers are adjusted.

One easy to miss functional change of this PR is that we will only attempt to load a given function once. The result will be stored and error returned from it on future calls, compared to previously when function loading exception was thrown, next call would attempt to load the function again. There is an extra check now, but I think that should be acceptable
<!-- upstream-excerpt-end -->
