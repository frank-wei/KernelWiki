## What changed
- make `cyclic_shape::size()` use ceil division so it matches the iterator cardinality for strided ranges
- add a regression test for the `[0, 7)` with stride `2` case

## Why
`cyclic_shape::size()` was using floor division while `cyclic_shape::end()` computed the past-the-end index with ceil division.

That breaks a basic invariant for strided tails. For `[0, 7)` with stride `2`, iteration yields `{0, 2, 4, 6}` (4 elements) but `size()` reported `3`.

## Impact
This makes `size()` agree with the number of elements produced by iteration for cyclic shapes with stragglers.

## Validation
- added a focused header unittest for the odd-tail case
- attempted `cmake --preset cudax-cpp17`, but validation is blocked in this environment because `nvcc` / `CUDAToolkit` is not available
