## Description

Next `cuda_safe_call` batch after #11740, #11748 and #11770: graph_ctx.cuh.

Its five remaining `cuda_safe_call` uses are all releases in frames that cannot throw:

- the host buffer (`cudaFreeHost`) and device buffer (`cudaFree`) released in `SCOPE(fail)` when adding the allocation node to the graph throws, with that exception in flight;
- the `cudaGraph_t` and `cudaGraphExec_t` destroyed in the `shared_ptr` deleters of `shared_cuda_graph()` and `graph_instantiate()`.

Same policy as the earlier batches: `cuda_try` under `ON_THROW(notify)`. A failing release leaks the resource and is reported to stderr with its location; the guard or deleter is `noexcept`, so it cannot become a second exception; and a leaked graph handle is not worth ending the program over, which is what `abort()` did.

One deliberate change of mind: the deleter comment from #11643 argued for `cuda_safe_call` so that a failed destroy is not dropped silently, and accepted the abort as "what a shared_ptr deleter needs". `notify` gives the same visibility, with a location, without the abort; the comment now says what the code does.
