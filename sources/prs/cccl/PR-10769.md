## Description

Base of the placement stack — **part 1/4 of the split of #9892** (stack: this → placement evaluation → torch.localized → replication).

- **C API**: the `stf_cute_partition_*` handle family (create from per-dimension specs, `from_leaves`, accessors, `owner`, place offsets), `stf_data_place_composite_cute`, `stf_data_place_allocate_nd`, native `stf_partition_fn_blocked/cyclic`.
- **Python**: the `cute_partition` class (`from_spec`, `from_leaves`, owner/leaves/offsets) under the C-order public contract (axis 0 outermost everywhere; the dim-0-fastest conversion is private to the binding), grid `mapper=`/`data_rank=`, `DeviceArray` shaped allocation on composite places.
- **Typed partitioners**: `partition_fn_blocked/cyclic` return a `native_partition_fn` wrapper (not a bare int), `data_place.composite` dispatches by type and rejects `data_rank` for non-callables, the mapper trampoline detects a provably-too-small `data_rank`, and `allocate()` surfaces mapper errors. The composite docstring documents the two coordinate contracts (shaped allocations = element coordinates; task-backed host arrays = flat byte space).
- **Tests**: partition/allocation coverage in C and Pyth
