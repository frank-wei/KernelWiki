## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Initially I thought that writing `group_by<N>{}` would the prefered way to instantiate `group_by`. However, it has some flaws once you want to take into account exhaustivity. Then you need to do `group_by<N, IsAlwaysExhaustive>{}` which is fine unless you just type `true` or `false`. The problem is that I need to maintain also several constructors for each combinations, because I want `group_by{N, non_exhaustive}` to work, too.

Then there is the thing that it's not consistent with other mappings. For example you can't specify the unit counts for `group_as` as `<...>` parameters, because it's a variadic template, for which must be placed after `IsAlwaysExhaustive` template parameter.

That's why I decided to basically disallow specifying the template parameters by the user. Instead, I took the approach used in `std::span` which inspects the passed extent and if possible, makes the extent static. This is done by using the `__maybe_static_ext` trait. So, after this PR you should always rely on CTAD and constructors to determine the static unit count for `group_by`.

Right now this has some downsides since we can only use `cuda::std::integral_constant` to specify the static unit count
<!-- upstream-excerpt-end -->
