## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
This PR tries to unify the atomic/non-deterministic and two-phase reduction dispatches and kernels. The goal is simplification and elimination of redundancy. ~~But I am not sure the code is actually more readable, not sure.~~ @NaderAlAwar also agrees the direction is good.

- [x] From @NaderAlAwar: How does this affect user defined tuning policies, when the user sets the determinism level? For example, the user can set determinism to not guaranteed, but then disable atomics? Semantically that is fine, but it could be confusing. Or the user could enable atomics but select run to run determinism. We can static_assert fail those cases if the input dtype is floating point I guess.
<!-- upstream-excerpt-end -->
