## Description

Follow-up to a review remark by @caugonnet on #11683: STF code should not use naked `throw`, since `_CCCL_THROW` / `_CCCL_RETHROW` are what keep a header compiling when exceptions are disabled (they print the type and `what()` and abort, or terminate, in that configuration, and are a plain `throw` otherwise).

An inventory of the merged STF headers found all remaining library-level naked throws in one file, `exception_policy.cuh`: 25 sites outside the `UNITTESTED_FILE` regions, none behind an `_CCCL_HAS_EXCEPTIONS()` guard.

- 20 bare `throw;` that decline a policy (catch-only, translate, alternation, fold) are now `_CCCL_RETHROW;`.
- 5 constructor throws are now `_CCCL_THROW(type, args...)`: the three rungs of `translate_t::__throw_translated`, `circuit_open` in the circuit breaker, and the `std::logic_error` in the type check.

No behavior change with exceptions enabled. The unit tests embedded in the header keep plain `throw` (134 sites), which is also what libcu++'s own tests do.
