## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
This PR tightens the rules for optional participation in a group and it's implications:
- a group (both virtual and generic) creation can be done only with threads that are part of the parent group
- `virtual_group` mapping must not produce threads that are not part of the group
- only threads that are part of the group can do non-static queries and synchronization
- only threads that are part of the group can call a collective algorithm

These changes provide some clear rules over what you can/cannot do with groups and should simplify the design of cooperative algorithms and prevent bugs.

If we find out these rules are too strict, we can relax them in the future
<!-- upstream-excerpt-end -->
