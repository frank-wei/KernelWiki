## Description

Follow-up to #11258, which added `exec_place::locality_domains(dev_id[, split])` for one device. This adds the machine-wide form:

- `exec_place::all_locality_domains([split])`: a grid with one execution place per locality domain of every visible device, in device-major order. Devices without locality-domain support (or on the pre-13.4 fallback) contribute a single whole-device place. Per review, this member is the only machine-wide spelling; the single-device pair `exec_place::locality_domains(dev_id)` / `make_locality_domain_grid(dev_id)` is unchanged.

The naming mirrors the device level: `device(i)` scales up to `all_devices()`, and `locality_domains(i)` scales up to `all_locality_domains()`.

## Testing

`cudax.test.stf.places.locality_domain_grid` now asserts that the machine-wide grid is the concatenation of the per-device grids, and that it matches `place_partition(exec_place::all_devices(), place_partition_scope::locality_domain)` in size and place by place. Run locally on a GB300 with the native topology and with `CUDASTF_FAKE_LOCALITY_DOMAINS=2`; `locality_domain_fake` also passes.
