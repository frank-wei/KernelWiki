## Description

Next slice of the `cuda_safe_call` to `cuda_try` migration: the 19 remaining sites in ordinary, non-cleanup code in `graph_ctx.cuh` (17) and `stream_ctx.cuh` (2). A failing CUDA call there aborted the process; it now throws `cuda_exception`, as the surrounding functions already do for their other calls.

Sites: graph node insertion in the graph allocator (`allocate`, `deallocate`, `add_mem_alloc_node`), the node and edge counts in `instantiate()`, `display_graph_info()` and `submit()`, the fence node, and the host synchronize in both backends' `wait()`. Output-parameter calls use the introspected form the file already uses elsewhere (`out = cuda_try<cudaGraphAddEmptyNode>(...)`); the count queries keep the runtime-status form.

Deliberately unchanged, per the scope-guard audit: every `cuda_safe_call` inside a `SCOPE(fail)`/`SCOPE(exit)` body, destructor, `shared_ptr` deleter or `noexcept` function (abort is the contract there), the `SCOPE(success)` bodies (their comments ask for abort explicitly), and the unit tests. That leaves 129 sites, of which about 60 are cleanup contexts that should stay.
