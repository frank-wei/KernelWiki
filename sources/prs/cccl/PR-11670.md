## Summary
- `cub::Uninitialized<T>::storage` is a `DeviceWord[]` array, and `DeviceWord` is capped at 16-byte alignment (`ulonglong2`). For `T` with `alignof(T) > 16`, the storage was under-aligned relative to `T`, so `Alias()`'s `reinterpret_cast<T&>` returned a misaligned reference (UB).
- Fix by adding `alignas(T)` to the storage array, which raises its alignment to `alignof(T)` without changing the `DeviceWord`-based layout.
- Added unit tests in `catch2_test_util_type.cu` covering several `T` (including `int3`, `char3`, `double2`) and an overaligned type.
