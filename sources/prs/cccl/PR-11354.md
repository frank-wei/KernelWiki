## Upstream PR description (verbatim excerpt)

In the past, I thought it would be a good idea to make the threads that are not part of the group know how many groups were created during the split if possible. However, I've reconsidered this approach and I think we should get rid of it.

The reason is that we cannot guarantee that all threads that are not part of the group would have this information. Imagine a scenario like:
```cpp
cudax::this_block block{...};

cudax::virtual_group g1{cuda::warp, block, cudax::group_by<3>{cudax::non_exhaustive}};

g1.count(block); // query_1, ok

cudax::virtual_group g2{cuda::warp, g1, cudax::group_as{{1, 1}, cudax::non_exhaustive}};

g2.count(g2); // query_2, fails for threads that are not part of g1
```
When creating a non-exhaustive group `g1` from an exhaustive group `block`, all threads (even those that are not part of `g1`) would return a valid result in `query_1`.

However, when we would create another group `g2` from `g1`, those threads that were not part of `g1` would `assert(...)` during `query_2`, because they wouldn't be able to get the information that we split `g1` into 2 groups.
