## Description

Closes #11653.

`DeviceFind::FindIf` initializes the not-found index for an empty input, then attempts to launch its search kernel with zero blocks. Skip that search launch when `num_items == 0`, while keeping result initialization and the copy for non-contiguous output iterators.

The new test covers contiguous and transformed output iterators. This PR touches the same dispatch and test files as the open DeviceFind refactor in #9429.

## Validation

- CUB `device.find` empty-input case passed in launch modes 0, 1, and 2 (16, 14, and 26 assertions).
- Existing nonempty `find_if` cases passed in mode 0 (96 assertions).
- `pre-commit run --files` passed with `secret-scan-trufflehog` skipped because its WSL shell is unavailable locally.

## Checklist

- [x] New or existing tests cover these changes.
- [x] The existing `FindIf` documentation already specifies that `num_items` is written when no element matches.
