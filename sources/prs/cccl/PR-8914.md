## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Rework graph_task<>'s stream-capture path to use
cudaStreamBeginCaptureToGraph on CTK 12.3+, replacing the previous
"capture into a fresh per-task graph and embed it as a child-graph
node" scheme. The legacy scheme is kept verbatim for CTK 12.0-12.2.
Motivation: conditional graph nodes created inside a task body (e.g.
Warp's wp.capture_while, available from CTK 12.4) cannot be embedded
through a child-graph node -- CUDA refuses to splice the captured
graph back into ctx_graph. Capturing straight into ctx_graph lets
those nodes land at the top level where they belong.

Implementation notes:
* Two new private helpers encapsulate the new path:
  - begin_capture_into_ctx_graph() wraps
    cudaStreamBeginCaptureToGraph in relaxed mode.
  - end_capture_into_ctx_graph_and_emit_done() snapshots the capture
    frontier *before* cudaStreamEndCapture (the deps_out pointer is
    invalidated by any subsequent capture call), ends the capture,
    and always adds exactly one empty "done" node into ctx_graph
    that depends on that frontier. Emitting a single done node
    unconditionally preserves the done_nodes.size() == captures
    invariant and avoids fragile empty/single-tail detection
<!-- upstream-excerpt-end -->
