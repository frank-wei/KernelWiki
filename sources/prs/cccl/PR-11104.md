## Description

Closes https://github.com/NVIDIA/cccl/issues/11005

The PR adds the following optimizations:

-  1-byte/2-byte types use a shared memory kernel based on padding (not XOR swizzling).
- Prefer following destination order when the destination tensor is not a multiple of the tile size to improve cache locality.
- Add a kernel to handle the case when the destination tensor is contiguous and the source tensor is not.
- Use shared memory kernel instead of vectorized kernel when the strides differs (even if the innermost is 1 for both).
- Instantiate rank-3 and rank-4 kernels for all cases that cannot be optimized in other ways.
- Tuning a few kernel block sizes.


The following cases have been excluded from the optimizations because they would require specialized kernels for each conditions: `transpose_merge_extents:` (rank-20), `transpose_2`, `transpose_3`, `transpose_store_efficieny_0` (shared mem with rank >= 3), `transpose_channels_2` (rank 3).
