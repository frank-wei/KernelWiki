## Description

Fixes the two locality-domain test failures seen in #11991 (forward-compat `cuda-compat-13-4` user-mode driver over an R595 kernel driver, single H100 PCIe):

- `locality_domain_alloc.cu(84): -1 == 0 is false`
- `locality_domain_split_method.cu(153): 2 == 0 is false`

Neither is a driver-version problem the existing waiver (#11837) can catch: under forward compat `cuDriverGetVersion` reports 13.4. Both are the tests over-specifying what a **single-domain** device must return:

- The driver documents that a localized allocation on domain 0 of a single-domain device is a plain device allocation, so the pointer ordinal is -1.
- Asking the driver to split SMs by domain on a one-domain device is pointless, and a user-mode driver without real locality-domain support hands back an unsplit device (114 SMs vs. an alignment of 8) without reporting an error.
