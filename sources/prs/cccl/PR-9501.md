## Summary
- Adds support for calling `ctx.wait()` on a CUDASTF token (`logical_data<void_interface>`).
- A token carries no content, so the existing value-returning `wait(logical_data<T>&)` cannot apply. A non-template `void wait(logical_data<void_interface>&)` overload is added to the stream and graph backends; it only blocks the host until the work the token depends on has completed, returning `void`.
- The generic `context` and the `stackable_ctx` need no dedicated overload: their `auto`-returning `wait()` templates forward to the backend overload and deduce `void`. A `static_assert` guards the value-returning backend templates against accidental instantiation with `void_interface`.
- This enables token-only synchronization over externally owned state (e.g. user-managed device buffers) without introducing a dummy token payload or changing normal logical-data `wait` semantics.

## Testing
- `cudax/test/stf/cpp/wait_token.cu` exercises `stream_ctx`, `graph_ctx`, and the generic `context`: a token-ordered kernel writes an externally owned buffer, `ctx.wait(token)` blocks, and the value is observed on the host. Also `static_assert`s that `wait(token)` returns `void`.
