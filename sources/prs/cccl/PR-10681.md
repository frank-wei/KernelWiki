## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
green_ctx_data_place_impl::allocate called cudaSetDevice(view_.devid) unconditionally and never restored the previous device, leaking the device switch into the caller. In STF, allocations run under the task's exec_place_scope, which guards the *exec* place -- often a different device than the data place -- so a green-ctx allocation silently repointed the current device for the remainder of the scope.

The device switch itself is needed: data_place::allocate defaults to a null stream, and with the legacy default stream cudaMallocAsync placement follows the current device (there is no explicit pool argument to pin it). So mirror data_place_device::allocate/deallocate exactly: conditional set plus SCOPE(exit) restore, in both methods.

Adds a unittest (guarded on two GPUs, since the leak is only observable when the place's device differs from the current one) checking that the current device survives allocate and deallocate.
