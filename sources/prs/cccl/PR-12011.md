Addresses NVIDIA-dev/cccl_qa_agent_findings#524, NVIDIA-dev/cccl_qa_agent_findings#525, and NVIDIA-dev/cccl_qa_agent_findings#526.

The following PR caused regressions in `BlockHistogram`

- https://github.com/NVIDIA/cccl/pull/10084

Switching from `atomicAdd` to `atomicAdd_block` caused the following issues:

- `clang` performance regressions (67% slowdown)
- Potentially, the output can be in global memory, not in shared memory, causing race condition.
- Half, Bfloat16 are no more supported

The PR fixes the previous items. In addition, it redirects all integers 4B, 8B to `atomicAdd_block`, not only `unsigned`, `int`, and `unsigned long long`
