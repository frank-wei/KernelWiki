## Description

closes #10647

Migrates the device `initialize` and `make_copy` APIs to `cudax::cuco::fixed_capacity_map_ref`.

- `initialize` prepares raw storage and can clear an existing map.
- `make_copy` copies all slots into caller-owned storage and can return a ref with a different thread scope.
- The CUDAX API uses a destination span to keep the capacity contract and a template argument to select the returned scope. `make_copy` retains the cuCollections `cuda::memcpy_async` path, with libcu++ selecting an ordinary-copy fallback when an accelerated copy is unavailable.

Tests cover shared and global memory, static and dynamic extents, bucket sizes 1 and 2, reset behavior, sentinel and scope preservation, mixed key and value types, and mutation of copied maps.

### Validation

- CUDA 13 with SM120, C++17 and C++20: 34 assertions in 7 test cases
- Compute Sanitizer memcheck and racecheck: clean
- nvcc and clang 22 SM75 builds: compile-only pass
