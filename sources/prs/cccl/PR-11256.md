## Description

No tracking issue; small ergonomic follow-up to the cudax places partition API.

Adds duck-typed overloads of `make_partition()` and `make_partition_descriptor()` in the cudax places layer that accept any object exposing `dim4 get_data_dims() const` (e.g. STF `shape_of<slice<T,N>>`) in place of the explicit `dim4 true_dims`. The overloads are constrained via a small `__has_get_data_dims_v` trait and forward to the existing dim4 overloads, so the places layer keeps no dependency on any STF shape type and there is no ambiguity with the dim4 spellings.

- `fdtd_mgpu` now writes `make_partition(data_shape, partition_spec{whole, whole, blocked<0>}, where.get_dims())` instead of re-spelling the extents as a `dim4`.
- `cute_parallel_for` gains a small check that the shape overloads produce partitions/descriptors identical to the dim4 ones.

Built and run locally (sm_103, CUDA 13.4, `-Werror`): `cudax.test.stf.places.cute_parallel_for` passes, `cudax.example.stf.fdtd_mgpu` runs.
