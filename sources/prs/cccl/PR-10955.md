## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Adds `store(target)` to the exception-policy vocabulary: a storing effect that puts the active exception into a caller-owned target and lets the chain continue.

Four target families, selected by the target's type:
- `std::exception_ptr`: full dynamic type, rethrowable later, never fails
- `cuda::std::span<char>`: `what()` text, allocation-free (fit for a thread-local buffer at a C ABI boundary where `bad_alloc` may be the exception in flight)
- `std::string`: allocating, best effort; a storage failure leaves the target unchanged rather than replacing the exception being handled
- an exact-dynamic-type `std::exception` derivative: mismatch declines by rethrowing (so `store(&typed) | store(&eptr)` is a ladder whose fallback cannot fail); a throwing copy declines with the *original* exception. The downcast is a `dynamic_cast`, so a type with `std::exception` as a virtual base works too.

`shared_ptr` ownership forms for all but span (a view). The untyped variants are `noexcept`, so the existing dead-arm theorem statically rejects them as non-final `|` arms.
