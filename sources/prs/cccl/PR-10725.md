## Description

`WarpBitonicSort` is showing promising performance results for segmented sorting of small inputs. This PR expands `WarpBitonicSort` scope to support even smaller segments through logical sub-warps.

`cub::detail::WarpBitonicSort` previously required the full architectural warp. This PR lifts that restriction so it works with any power-of-two `LogicalWarpThreads` from 1 up to the warp size, matching what, e.g., `WarpExchange`, `WarpMergeSort`, support. Each logical warp sorts its own tile of `ItemsPerThread * LogicalWarpThreads` items independently of the other logical warps sharing the architectural warp. Non power-of-two widths are rejected with a `static_assert`.

### Implementation

The striped index math already went through a single constant, so it was mostly a matter of pointing that at `LogicalWarpThreads` and switching the lane to `detail::logical_lane_id`.
