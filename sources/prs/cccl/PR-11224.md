Second PR of the scope-guard hardening campaign that began with #11187, from the same audit of all 148 `SCOPE` sites.

**Real defects**

- `01-axpy-places.cu` armed one guard after *two* 256 MB allocations, so a `bad_alloc` from the second leaked the first. Now one guard per resource, each armed immediately.
- The `scalar` test fixture in `stream_ctx.cuh` freed a buffer that was still registered via `cudaHostRegister` when `logical_data` construction threw (freeing registered memory is undefined). A second guard declared after the registration unregisters before the earlier guard frees, relying on reverse-order execution.
