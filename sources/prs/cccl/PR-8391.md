## Description

- add a new warp-wide sorting primitive that implements a bitonic sorting network
- add tests and benchmarks for it
- add device-side benchmark utilities

Intended for warp-wide top-k. So, it's in the `detail` namespace.

## Motivation

For warp-wide top-k implementation, we need a fast sorting algorithm for small input length (N).
`WarpBitonicSort` is efficient for this use case. One reason is it keeps data in registers and exchanges data using warp shuffle instructions, eliminating the need for shared memory.

I compared the performance of `WarpMergeSort` ("Ref" in the following table) and `WarpBitonicSort` ("Cmp" in the following table). The kernels were launched with a single warp to measure latency.
- `WarpBitonicSort` is faster when N <= 224
- `WarpBitonicSort` becomes much slower for larger N due to its high sequential time complexity.

|  KeyT  |  ValueT  |  N  |   Ref Time |   Ref Noise |   Cmp Time |   Cmp Noise |         Diff |   %Diff |  Status  |
|--------|----------|-------|------------|-------------|------------|-------------|--------------|---------|----------|
|  F32   |   I32    |  32   | 104.622 us |       0.25% |  34.056 us |       0.26% |   -70.
