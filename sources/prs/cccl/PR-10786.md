## Description

`place_partition` is the composable mechanism for decomposing an execution place at a chosen granularity, but locality domains were only reachable through the ad-hoc single-device factory `make_locality_domain_grid`. This PR adds `place_partition_scope::locality_domain` so locality domains slot into the same mechanism as devices, green contexts and streams:

- **No handle needed**: locality-domain green contexts live in the process-wide registry keyed by `(device, split method)`, so the scope works with both the handle and no-handle constructors.
- **Machine-wide grids**: grids are flattened, so `place_partition(exec_place::all_devices(), place_partition_scope::locality_domain)` yields every domain of every device — the machine-at-granularity form that previously had no direct spelling.
- **Split method**: an optional trailing `locality_domain_sm_split` constructor argument (default `backfill`) selects the SM split method, mirroring the parameter on `exec_place::locality_domain`.
