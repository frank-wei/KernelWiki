## Description

closes https://github.com/NVIDIA/cccl/issues/2358

cudax applied `[[no_unique_address]]` directly in five places. `_CCCL_NO_UNIQUE_ADDRESS` exists so the attribute is only emitted where it is known to be safe: it is empty on MSVC, whose implementation has caused silent runtime corruption when passing data into kernels, and under clang with nvcc in C++17, where cudafe++ does not honor it (nvbug 5265027). Switching these sites to the macro brings cudax in line with the rest of CCCL and removes the C4848 trigger from cudax's own code.

Sites changed:

| File | Sites |
| --- | --- |
| `__stf/internal/execution_policy.cuh` | 2 |
| `__stf/utility/run_once.cuh` | 1 |
| `__stf/internal/parallel_for_scope.cuh` | 1 |
| `__utility/optionally_static.cuh` | 1 |

A doc comment in `parallel_for_scope.cuh` that referenced the raw attribute was updated to name the macro. The one-line reformat in `optionally_static.cuh` is clang-format realigning `using __state_t` after the macro changed the declaration width.

No new includes were needed: all four headers already reach `<cuda/std/__cccl/attributes.h>` through `<cuda/__cccl_config>`, directly or via `<cuda/std/detail/__config>`.
