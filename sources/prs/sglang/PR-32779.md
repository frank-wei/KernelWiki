## Motivation

DSA prefill on CUDA has no fused Triton path, and the kernels it does dispatch to are a poor fit for the head count the model actually has after TP.

`flash_mla_sparse_fwd` requires `num_heads % 64` on SM90 and `% 128` on SM100+, so `_forward_flashmla_sparse` zero-pads the head dim before calling it. GLM-5.x at TP8 has **8 real heads**, so 7/8 of the tensor-core work on SM90 — 15/16 on SM100+ — is spent on padding, and the split form then writes `O(tokens x splits)` partials to HBM for a second kernel to merge. What main selects on its own for an FP8 KV cache on SM90 today is `flashmla_kv`, which is slower still from 4096 tokens up; both are columns in the tables below.

Neither cost is necessary at this size. The attention tile is small enough that one Triton program per query token, holding the online softmax in registers, beats a wide cooperative block, and it lets the head dim be padded into a 16-row MMA tile (8 -> 16) instead of into the grid (8 -> 128) — no partials, no merge.
