## Motivation

TopK v2 can launch an unsupported 16-block cluster even when the device occupancy probe reports zero capacity. The loader swallows the zero-capacity exception and retains the default C16 capacity of `7`.

On NVIDIA H20, this was reproduced with `batch=4`, `seq_len=65536`, and `topk=512`, which failed with `cluster misconfiguration`.

This PR passes the zero-capacity result into JIT compilation so the unsupported path is disabled and the existing fallback is used.

## Modifications

- Handle the 8-block and 16-block probes in one loop and always emit the corresponding capacity macro after each successful query, including zero-capacity results.
- Distinguish zero schedulable clusters from unexpected probe errors. Zero disables the corresponding cluster path; other errors propagate for both probes.
- Default the optional 16-block path to disabled unless a positive probe result enables it.
- Reuse the existing dispatch guards: a zero C16 capacity falls back to C8 when available; zero C8 capacity skips the persistent pool and permits the existing non-cluster path.
