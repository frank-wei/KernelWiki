## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
**Motivation:** a 4x RTX PRO 6000 Blackwell (SM120) box can hold DeepSeek-V4-Flash, but on
current main the only configuration that starts there is the slow torch fallback — this PR
makes the DeepGEMM and FlashInfer paths work on SM120, cutting decode latency up to 3.4x.

It routes the sparse-MLA indexer to DeepGEMM's paged-MQA-logits kernel, enables batched
sparse-MLA prefill through FlashInfer, and unblocks the DeepGEMM FP4 MoE backend.

## Split out of this PR

Following @Fridge003's review, the changes here that were not SM120 enablement now have
their own PRs:

- #35116 — allocate the page-split buffer outside inference mode (correctness fix)
- #35118 — fuse the hc-prenorm combine into a Triton kernel (arch-independent)

**This PR now depends on #35116**: without it the page-split buffer is allocated under
inference mode during autotune and CUDA graph capture cannot write to it. Will rebase once
it lands.

The E2E tables below were measured with #35118 still in this tree. Measured separately on
the same box with only that kernel toggled (ISL 8K, BS1, TP4, deep_gemm MoE), it accounts
for **3.2% of the TPOT gain** (12.81 -> 12.40 ms, two repeats each, run-to-run spread
0.01 ms)
