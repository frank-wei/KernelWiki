## Motivation

A speculative draft model owns a KV pool of its own, separate from the target's.
That means a second allocator, a second id space, a second set of page tables, and
memory reserved up front for the draft that the target can never use.

Under `--enable-unified-memory` the target's slot entries already have room. This
PR puts the draft's K/V rows **inside** the host entry, after the host's own parts:

```
[ K_0 | V_0 | ... | K_n | V_n | dK_0 | dV_0 | ... | dK_m | dV_m | pad ]
  \___________ host ___________/ \_________ draft _________/
```

One slot id then addresses both. One allocation, one free, and one whole-page
relocation carry the target's KV and the draft's together — a compaction move gets
the draft bytes for free instead of needing a second, separately-indexed move.

**This PR builds that mechanism and leaves it unreachable.** The admission gate is
untouched — `speculative_algorithm in (None, "DSPARK")` — and the fuse decision
