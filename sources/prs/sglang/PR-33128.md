## Motivation

The `deep_gemm` MoE runner can be selected with the standard token dispatcher, but the existing integration assumes the DeepEP weight and activation layouts. Standard MoE layers therefore do not consistently requantize both expert weights to UE8M0, and the standard dispatch path does not provide a compact local-expert layout for DeepGEMM.

This change completes the standard-dispatch integration while preserving the existing DeepEP path.

Co-authored-by: Sam Li (@samuellees)

## Modifications

- Requantize both gate/up and down expert weights when a standard MoE layer uses the DeepGEMM runner.
- Quantize Blackwell FP8 activations directly with their UE8M0 scales instead of rounding the scales after quantization.
- Use the masked DeepGEMM layout when expert parallelism keeps the local expert buffer small.
- Use a compact, graph-static layout for the remaining standard-dispatch cases, including tensor-parallel execution without expert parallelism.
- Ignore non-local expert assignments during scatter and post-permute while preserving CUDA Graph-compatible buffer shapes.
