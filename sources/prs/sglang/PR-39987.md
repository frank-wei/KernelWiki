## Motivation

Qwen3.5-397B has 45 Gated DeltaNet layers. At TP4, each rank runs the recurrent verify kernel with 4 key heads, 16 value heads, and K=V=128, but the shared Triton wrapper always uses a 32-column value tile and one warp. That launch geometry is under-occupied for the 1-32 request batches used by decode and speculative verification on MI355X.

A gfx950 sweep found a consistently faster configuration: BV=8 with four warps for batch 1, and BV=16 with two warps for batches 2-32. The measured kernel improvement is 14-40%, and a GPU profile confirms a 14.4% reduction across all 45 recurrent launches in target verify.

## Modifications

- Add `_select_recurrent_launch_config()` in `python/sglang/kernels/ops/attention/fla/fused_sigmoid_gating_recurrent.py`.
- Select the tuned launch only for HIP gfx95, non-KDA GDN, batch 1-32, H=4, HV=16, and K=V=128.
- Keep the original BV=32 / one-warp launch byte-for-byte for CUDA, KDA, other GDN shapes, and larger batches.
- Extend `test_fused_verify_triton_gdn.py` with the exact Qwen3.5 TP4 shape at batches 1, 3, and 16, plus positive and negative launch-envelope assertions.
