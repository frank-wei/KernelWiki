## Summary

- cache the compact fp32 temporal/height/width RoPE tables across decoder blocks at the same grid
- add a paired BF16 JIT CUDA kernel that rotates Q and K in one launch while preserving the eager fp32 operation order
- guard the fast path with first-sight bit-exact verification and a permanent eager fallback
- add pointer-alignment and shape guards, CUDA correctness coverage, representative benchmarks, CPU cache/fallback tests, registry entries, and kernel docs

## H200 results

Checked-in paired-RoPE benchmark:

| Shape | Eager | JIT | Speedup |
| --- | ---: | ---: | ---: |
| stage 0 | 0.9381 ms | 0.0950 ms | 9.87x |
| stage 4 tile | 2.5454 ms | 0.2467 ms | 10.32x |
| stage 5 tile | 9.3790 ms | 0.8643 ms | 10.85x |

Full decoder-component benchmark used the default 960x544x121 geometry, all 24 blocks, tiled decode, and NATTEN `na3d`:

- median latency: 5379.54 ms -> 4463.80 ms (17.0% faster)
- output SHA256 was identical across baseline/candidate runs: `b3a693021e1251d69847903a772e67dca4046425c576c60ce87bfee6689a6a68`
- peak allocated memory was effectively unchanged: 7,422,371,328 -> 7,422,650,880 bytes
- ptxas on sm_90a: 30 registers, 0 spill stores, 0 spill loads, 0
