## Summary

The trtllm-gen deferred finalize returns its routing weights at the dtype the caller passed in, so K3's unpacked `(topk_ids, topk_weights)` routing yields fp32 weights where the packed form yielded bf16. The fused finalize kernel matched bf16 only and a 72-token decode batch killed the server during CUDA-graph capture. #38588 stopped that by casting to bf16 at the call site. This PR makes the kernel take either dtype instead, and reverts the cast.

`finalize_vec` is templated on the routing-weight dtype, the kernel's `kFinalize` bool becomes `typename FinWeight = void`, and the host dispatches on `expert_weights.dtype()` at the `TensorMatcher` that already validates the tensor.

| | #38588 | This PR |
|---|---|---|
| Weight precision | bf16, rounded before the kernel | fp32 as the router emits it |
| Per call | +2.3 to +11 us | no measurable change |
| Added work per MoE layer | cast launch + alloc before the collective | none |

Per call on 8x B300, best of 3 interleaved repeats of 200 iterations:

| bs | This PR | #38588 | Delta | Spread |
|---|---|---|---|---|
| 1 | 9.35 us | 18.29 us | -8.94 us | 2.6 / 3.0 |
| 8 | 10.13 us | 19.60 us | -9.48 us | 3.4 / 1.7 |
| 32 |
