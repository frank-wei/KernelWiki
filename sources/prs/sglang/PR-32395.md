## Motivation

**Background**
The Triton fused-MoE GEMM consumes tokens in tiles of `block_size` rows, and every row in a tile must belong to the same expert so the tile can load that expert's weight block once. `moe_align_block_size` is what makes that possible: it takes the flattened `num_tokens * topk` (token, slot) pairs, groups them by expert, pads each group up to a multiple of `block_size`, and hands the GEMM three buffers — `sorted_token_ids` (the permutation, with pad slots holding `numel` so the GEMM masks them off), `expert_ids` (which expert each block belongs to), and `num_tokens_post_pad` (how far the GEMM should walk). Under expert parallelism a slot can be filtered out and carries expert id `-1`, so the kernel shifts every id by one: bucket 0 collects the filtered pairs and its blocks are written with `expert_ids = -1`, which `fused_moe`'s `filter_expert` skips. That is the "+1 offset" convention this PR has to reproduce exactly.
