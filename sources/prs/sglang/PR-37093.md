## Motivation

In a long-lived disaggregated prefill worker using DSA with EAGLE, the process ran normally for a long time and then failed while loading a newly JIT-compiled Triton kernel. The batch immediately before the failure contained 16,384 new prefill tokens:

```text
Prefill batch, #new-seq: 1, #new-token: 16384, #cached-token: 0,
token usage: 0.10, #running-req: 0, #queue-req: 1,
#pending-token: 724687, cuda graph: False
```

The prefill server was launched with the following relevant SGLang arguments:

```bash
sglang serve --model-path <model-path> \
  --tp-size 4 \
  --attn-cp-size 4 \
  --enable-prefill-cp \
  --cp-strategy interleave \
  --disaggregation-mode prefill \
  --disaggregation-transfer-backend mooncake \
  --kv-cache-dtype fp8_e4m3 \
  --max-running-requests 64 \
  --mem-fraction-static 0.85 \
  --page-size 64 \
  --speculative-algorithm EAGLE \
  --speculative-eagle-topk 1 \
  --speculative-num-draft-tokens 4 \
  --speculative-num-steps 3
```
