## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Depends on #35233. That PR makes registered host pointers usable from the
transfer kernels on ROCm; this one is the part that decides how much of the KV
cache can actually take that path, and how fast it moves once it does. An
earlier revision of this PR carried its own pointer fix (pin_memory allocation,
an unregister guard, and an io-backend downgrade for storage-owned memory);
those are dropped in favour of #35233, which solves the same problem more
generally and does not have to give up the kernel backend for storage-owned
pools.

## What is left here

**Copy rounds narrower than 128 B.** The JIT transfer kernels tiled each element
in 128 B rounds only, so an element size 128 does not divide could not use them
at all. MLA's fp8 row is 576 B. `pick_group_bytes()` now takes the widest round
of 128/64/32/16 that both divides the element and splits across the lanes into a
package the hardware has (4, 8 or 16 B).

**A block quota that suits ROCm.** 2 on CUDA, 16 on ROCm. The per-layer read path
loses bandwidth below that, which is also why the narrow rounds are worth their
extra instantiations only on ROCm.

**`MHATokenToKOnlyPoolHost` can use the JIT path.** `can_use_jit` accepted
