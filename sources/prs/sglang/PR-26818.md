## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Add the optional verify-token-id capability: cross-check each canary slot's stored input token id against an independently-computed expected token (req_all_ids -> scatter_req_token_ids kernel -> plan.verify_expected_tokens), catching the model placing the wrong token's KV in a slot. Gated by SGLANG_KV_CANARY_ENABLE_VERIFY_TOKEN_ASSERT (default off). The intrinsic token store + chain-hash fold stay in the base kernels; this PR adds the scatter kernel, req_to_expected_token_ids_manager, the plan/forward-batch population, and enables the kernel's compile-time CHECK_VERIFY_EXPECTED_TOKEN compare.
