## Motivation

Eager extend batches ran the ratio-1 and ratio-2 compressors as a chain of torch ops, while decode already had fused kernels.

## Modifications

- **Fused c1/c2 compress for eager extend**:
  - Ratio 1 reuses the per-token c1 kernel.
  - Ratio 2 gets a Prefill mode of the c2 kernel: an odd position pairs with the previous row when that row is the same request's previous position, else with its ring slot; pending rows are skipped.
  - `c2_prefill_store_kernel` then parks each request's last `ring_size` rows in the ring, `ring_size` CTAs per request from `extend_start_loc` / `extend_seq_lens`. It cannot run inside the pooling kernel because a chunk whose first row is odd and last row is even reads and writes the same ring slot.
  - The backend takes this path for extend-without-speculative batches when the compressor has `use_fused_compress`; the prefill CUDA graph and CP paths keep the torch compressor. Decode and prefill share one c2 JIT module.
- **c2 decode**: decode / target-verify rows issue their input and partner loads before a CUDA graph padding row ret
