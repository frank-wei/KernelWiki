Part of #41589 (DeepSeek-V4.1 prefill optimizations, split into smaller PRs).

## Motivation

Before the first decoder layer and after each Engram layer, DSv4.1 prefill ran full-residual elementwise work that is either redundant or can be done in one pass.

## Modifications

- **`hc_broadcast`** (`kernels/ops/layernorm/mhc.py`): builds the initial mHC residual `[T, hc_mult, H]` from the embedding with one Triton kernel instead of `unsqueeze(1).repeat(...)`. Output is identical; non-CUDA tensors and a non-unit last stride fall back to `repeat`.
- **Strided first-sublayer norm** (`DeepseekV4DecoderLayer._hc_combine`): with no previous pre-mix, the copies are all equal, so the CUDA RMSNorm now reads the row-strided copy 0 directly instead of making it contiguous first. Other platforms keep the contiguous copy.
- **Skip the image-token `torch.where` for text-only batches** (`_forward_layers_hc_pre_from_prev`): the full-residual `where` after each Engram layer now runs only when `forward_batch.contains_mm_inputs()`. Behavior change at the edge: a text-only prompt that literally contains the image token id used to skip Engram for that token and now gets it.
