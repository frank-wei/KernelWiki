## Motivation

Simulated expert routing is an existing feature to inject arbitrary expert choices, to isolate the effect of expert imbalance during perf benchmarking. However, the current implementation have two problems:

1) Does not support DP>1. When DP>1, MoE input is scattered across DP ranks, each rank generated expert assignments using the same local token indices, causing different ranks to select duplicate expert sets rather than representing distinct portions of the combined DP input.

  >  For example, with DP=2, one token per rank, eight experts, and top-k=2, both ranks previously selected experts [0, 4]. After this PR, rank 0 selects [0, 4] and rank 1 selects [1, 5].

2) Native pytorch impl issues ~5-7 small element-wise ops per layer (arange x2, mul, add, mod, fill/randint), perturbing timing and cause the result to deviate from runs w/o injecting expert choices, especially at low batch sizes.

## Modifications

1) Make simulated routing DP-aware when MoE input is scattered, by deriving each token’s position from its DP rank and size.

2) Replace them with a single fused Triton kernel.
