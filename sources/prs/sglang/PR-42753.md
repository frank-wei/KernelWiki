## Motivation

On the unified memory pool a KV slot has a virtual id (what the scheduler
allocates and `req_to_token` stores) and a physical id (what kernels index).
The conversion between them was done wherever an id was needed: every
`ForwardBatch` translated its own write window, every attention backend built
its own translated page table (some per forward, some per layer group, some
per captured mode), the multi-step draft kernel translated every id it
gathered, and the speculative KV writers translated the ids they were handed.
Within one speculative iteration the same window was translated three to four
times (draft, verify, draft extend, target-hidden KV writes), and a captured
graph translated its write ids a second time into a private buffer.

Besides the wasted launches, every one of those sites had to agree on which
ids were already physical, and a site that translated twice, or not at all,
silently read or wrote the wrong slot.

**This PR translates an iteration's write window once per sub-pool, in one
place, and gives every read exactly one translation, in one place too
