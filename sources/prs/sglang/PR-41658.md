## Motivation

Two DSv4.1 prefill helper kernels were dominated by launch count or poor parallelism rather than bandwidth.

## Modifications

- **Triton gather for packed fp4 index-K rows**: `get_index_k_fp4` built int64 byte-index tensors and ran a chain of small kernels per call. `gather_fp4_index_k` (`fp4_indexer.py`) reads the paged layout as int32 words (16 payload words plus 1 scale word per slot) in one launch; `deepseek_v4_memory_pool.get_index_k_fp4` uses it on CUDA.
- **Token-blocked `combine_topk_swa_indices`**: the kernel ran one program per (request, worker) with 128 workers, so a single long prefill request had 128 programs walking its tokens serially, and the wrapper filled the whole output with `-1` first. The grid now covers tokens (two per program); each token finds its request by a binary search over `query_start_loc` and writes its whole `-1` padded row, so the output needs no fill pass and preallocated buffers are overwritten entirely. Rows past the last request are `-1` with length 0, as before. Output is unchanged.
