## Motivation
QSA chunk prefill gathers each request's cached K and V separately, concatenates the results, and converts FP8 values inside attention. This adds small operations and host-side request-index materialization.

## Changes
- Gather K and V together with a Triton kernel using the request-to-token mapping.
- Convert to the query dtype during gathering, including FP8 KV to BF16.
- Preserve main's prefill length metadata, attention interface and attention arithmetic.

This PR is now standalone, directly based on main at `2a3655fea1`. It does not include or depend on #41932 or #41934. It retains the rectangular packing launch grid; highly uneven request lengths can launch masked work.

## Validation
The standalone revision passed the complete QSA test file on both H200 and GB300: **93 passed, 1 skipped**. Coverage includes BF16/FP8 packing, strided inputs, dtype conversion, packing-kernel graph replay with changed request IDs, and attention reference comparisons. Repository-configured Ruff checks and formatting passed. The two metadata/max-query graph tests from #41932 are intentionally not included; the attention interface remains identical to main.
