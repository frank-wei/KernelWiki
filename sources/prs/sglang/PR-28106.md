## Motivation

The trtllm_mha backend currently requires seq_lens on the host (CPU): it sizes its attention metadata — specifically the page-table width — from `max(seq_lens)`, so it sets `needs_cpu_seq_lens=True` and the scheduler copies `seq_lens` back to the host every step.

In spec-v2, this host requirement forces a CUDA sync on every decode step. `seq_lens` is only final once the current stage's GPU work completes, so the CPU blocks on the GPU before it can set up the next stage's metadata and launch it (GPU verify i -> CPU -> GPU draft i+1). This prevents running CPU work and issuing kernels ahead of GPU execution, causing GPU idle.


## Modifications

We observe the host's only use of the synced lengths is `max(seq_lens)`, and only to set how wide the page table is (how many KV-page pointers to gather per request), while the attention kernel reads the exact per-request lengths directly on the device side. So the host doesn't need the precise max at all — the page table can be built on the GPU from the device-side lengths.
