## Motivation

Sana's transformer runs the eager adaLN chain `LN(x) * (1 + scale) + shift` at
41 sites per DiT forward (norm1/norm2 in each of the 20 blocks + the final
`SanaModulatedNorm`), as 4 aten kernels per site (affine-free LayerNorm,
`1+scale` row op, broadcast mul, broadcast add) — and because the DiT
propagates the patch-embed/GLUMBConv `permute` layout, the LayerNorm pays a
hidden layout-copy on every call as well. Elementwise ops are ~51% of Sana's
per-step GPU time, and no existing fusion applies: the CuTe-DSL
norm+scale+shift family needs `hidden % 256 == 0`, while Sana's hidden is
2240 (70 heads x 32).

PR #34008 introduced a Triton kernel replicating torch's aten
`vectorized_layer_norm_kernel` numerics bit for bit (serial Welford in aten's
element order, guarded-rcp fast path, shfl.down combine tree, MUFU.RSQ, plus
the per-op bf16 rounding of the modulate chain), so the fusion needs no
quality gate. That kernel assumed `hidden % 512 == 0` (all 128 aten threads
run the same vector count).
