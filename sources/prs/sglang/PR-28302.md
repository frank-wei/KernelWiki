## Summary

Deduplicate the speculative-decoding conv-window intermediate cache (`intermediate_conv_window`) using a sliding-window layout, halving its footprint with no numerical change.

## Motivation

During target verify of hybrid linear-attention models (GDN / Mamba2 / KDA "in the future"), each draft-token position snapshots a conv-state window of the last `K-1` inputs (`K = conv kernel width`). The cache is sized `[num_layers, slots, draft_tokens,
conv_dim, K-1]`, i.e. `D` separate `(conv_dim, K-1)` windows per (layer, slot). Consecutive draft tokens' windows overlap by `K-2` (a sliding window over the same input stream), so storing them densely wastes roughly half the buffer.

This PR applies to any hybrid linear-attention model with a short causal conv under spec decode, GDN today, and KDA automatically once its target-verify path lands.

## Modifications

On CUDA, store one shared `[conv_dim, D + K - 2]` buffer per (layer, slot) and expose an overlapping `as_strided` view of logical shape `[num_layers, slots, draft_tokens, conv_dim, K-1]`, where step `t`'s window is the slice `shared[..., :, t:t+K-1]`.
