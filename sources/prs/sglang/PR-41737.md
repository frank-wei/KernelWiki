## Motivation

The greedy branch of `_selector_walk_kernel` (`kernels/ops/speculative/dflash.py`) takes `best = tl.max(scores)` and then the first offset where `scores == best`. If a whole score row is NaN, `best` is NaN, no element compares equal, and `index` falls through to `top_k`: one past the row, so the walk resolves to a neighbouring row's candidates.

## Modifications

- Greedy branch of `_selector_walk_kernel` now makes the same pick as `torch.argmax` (and `_selector_walk_torch`): the first NaN if the row has one, else the first maximum. `index < top_k` for every row, including all-NaN rows, and mixed-NaN rows match the reference.
- `test/registered/kernels/ops/speculative/test_lilicorr_cuda.py`: `test_greedy_path_matches_the_reference_on_nan_scores` (all-NaN and mixed-NaN rows), comparing tokens and q rows from `lilicorr_sample_path` against `_selector_walk_torch`.

## DSpark

DFlash-only: `DSparkWorkerV2` does not use `candidate_selector` / `selector_walk_triton`, so DSpark is unaffected.
