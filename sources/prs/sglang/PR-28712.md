## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Part 1 of a 4-PR split of #27944 (MiniMax-M3). This PR is purely additive on top of `main`: new compute kernels, their tests/benchmarks, and the config helpers / env descriptors they depend on. It does **not** touch any generic forward / quant / attention runtime path, so it is dead-on-main and green without an e2e run.

## What's in this PR

- `minimax_sparse_ops/**` — decode / prefill / naive sparse attention kernels + unit tests (self-contained, no model/hf_config import)
- `jit_kernel` MiniMax / M3 / `moe_topk_sigmoid` kernels — C++/CUDA headers + Python wrappers + tests/benchmarks, including `store_kv_index` (depended on by split PR2)
- guarded AMD gfx95 MXFP8 MoE kernels + triton config JSONs
- additive MoE-runner changes: `interleaved` dataclass default (`True`), MXFP8 branch in the triton runner (guarded by `use_mxfp8=False` default)
- `model_config`: `is_minimax_sparse` + `get_minimax_sparse_attention_config` and helpers + `mxfp8` dtype registration + piecewise VL guard
- `environ`: 3 MiniMax descriptors needed by the kernels above (`SGLANG_OPT_USE_MINIMAX_DECODE_TOPK_RADIX`, `SGLANG_MINIMAX_M3_FUSED_SWIGLU_MXFP8`, `SGLANG_MINIMAX_M3_FUSED_MOE_COMBINE`)
