## Motivation

#30775 enabled PP x speculative decoding (`SGLANG_ENABLE_PP_SPEC=1`). On hybrid linear-attention targets (KDA / GDN / Mamba-style recurrent state) it is currently incorrect in two independent ways, both found while validating PP + MTP across model families (tracking: #39634):

1. **Non-last PP stages never commit the accepted recurrent state.** The last stage commits KDA/Mamba state inside `run_eagle_verify`; earlier stages only run target verify and relay the result, so their recurrent state stays at the pre-verify value while the last stage advances. GLM-5.3-Flash PP2 + MTP: GSM8K 0.745 vs 0.990 without spec, accept length looks normal (3.5), so the bug is silent.
2. **With more than two stages the relayed accept result is paired with the wrong micro-batch.** The commit hook took its destination slots from the backend's active `forward_metadata`, which on a non-last stage still belongs to the previous forward (slot `(i-1) % N`), and the KDA verify scratch was written at positional rows `0..bs-1` that in-flight micro-batches overwrite before the relay returns.
