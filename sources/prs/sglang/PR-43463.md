## Motivation

For Qwen3.8-Flash-Next B200 BF16 (TP4, NEXTN MTP 3/1/4) the QSA decode indexer takes about 3 ms of a 28.75 ms bs64 decode step. It costs that much even at short contexts, where QSA selects every block anyway. Three pieces of it scale with the max context instead of the live one:

- `tilelang_qsa_mqa_decode` launches a `(rows, max_pages / 4)` grid. The CUDA-graph page table is sized for the max context: 262144 tokens are 65536 compressed tokens, which is 4096 pages of 16, or 1024 CTAs per row. At bs64 verify (256 rows) this launches 262K CTAs per layer, almost all of which exit immediately. Each call takes 137 us, 1.78 ms per step.
- For a row whose compressed length fits the k = 512 top-k, `fast_topk` writes `0..len-1` without reading its scores. So the scoring work on that row is thrown away, and so is the `-inf` pre-fill of the whole `rows x max_model_len` logits matrix, since `fast_topk` never reads past a row's length.
- `_qsa_fused_kv_prepare` writes every row's full packed width: 2112 tokens of K and V at 256 dims, zero-filling the part past the valid count. `trtllm_decode` reads each row only up to `valid_counts`. At 256 rows this writes 537 MB per call, 76 us
