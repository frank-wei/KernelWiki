## Motivation

With the optional HND KV cache layout (`SGLANG_USE_HND_KVCACHE`), `MHATokenToKVPool.set_kv_buffer` writes K/V by advanced indexing (`k_buf[pages, :, offs, :] = cache_k`). That costs several small kernels per layer per step. The existing Triton cache writer can do the same write in one kernel if it is given the destination's real token and head strides.

## Modifications

- `reshape_and_cache_flash` (Triton) takes separate key/value block, token and head strides for the destination, so it can write into a strided view of HND storage. For existing callers with the `[blocks, block_size, heads, dim]` layout, these strides equal the values the kernel previously assumed.
- `MHATokenToKVPool.set_kv_buffer` uses `launch_reshape_and_cache_flash` for HND writes on CUDA when the key and value head dims are equal. Inputs have already been cast and viewed to the pool's store dtype at this point, so the write is a plain copy for any KV dtype. Other cases keep the indexing path.
- The default NHD layout is unchanged.
