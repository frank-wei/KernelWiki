## Summary

`expert_pack_mxfp4` was built with `torch.utils.cpp_extension.load`, whose `FileBaton` waits on a lock **file** and only releases it in a `finally`. A build killed mid-flight leaves the file behind, and every later run against that cache spins on it forever with no output — a 7s test can burn a full CI timeout, and the cache outlives the job. Ported to `load_jit`, which uses `fcntl.flock` (released by the kernel when the holder dies), then fixed three latent bugs the rewritten validation now owns.

| | Before | After |
|---|---|---|
| Build lock | stale lock file wedges every later run, silently | `flock`, freed on process death |
| `records` → `grid.y` (cap 65535) | 16384 tokens × top-k 4 = 65536, the first failing value → launch aborts at stock settings | `grid.x` (cap 2³¹-1); both dims checked |
| `hidden_size % 64` | partial Marlin tile reads a neighbouring slot *inside* the tensor; memcheck clean, no diagnostic | rejected |
| `role_bytes` in repack | unchecked; inconsistent value silently produced wrong output | asserted, as matvec already did |
| `#pragma once` | absent | added (insurance, not a fix) |
