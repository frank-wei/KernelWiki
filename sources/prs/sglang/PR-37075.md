## Motivation

Wan2.2 ModelOpt NVFP4 MLPs currently execute the `fc_in` hot path as three
separate operations:

```text
NVFP4 GEMM -> BF16 bias add -> tanh GELU
```

On GB300, the bias add and GELU are memory-bound and account for a meaningful
part of denoising time. This PR fuses the last two operations while preserving
the eager half-precision rounding boundary.

```mermaid
flowchart TD
    A["DenoisingStage._maybe_toggle_quality_fusions"] --> B{"request quality"}
    B -->|"lossless"| C["unmount_nvfp4_bias_gelu<br/>reference path"]
    B -->|"high"| D["mount_nvfp4_bias_gelu<br/>eligible Wan NVFP4 sites only"]:::changed
    D --> E["ColumnParallelLinear.forward<br/>NVFP4 GEMM returns output and deferred bias"]:::changed
    E --> F["bias_gelu_tanh<br/>fused BF16/FP16 bias add plus tanh GELU"]:::changed
    C --> G["NVFP4 GEMM with bias<br/>then native GELU"]
    F --> H["fc_out"]
    G --> H
    L["Legend: dashed border = added or modified"]:::changed
    classDef changed stroke-dasharray:5 5,stroke-width:2px;
```
