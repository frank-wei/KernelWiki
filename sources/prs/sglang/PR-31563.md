## Motivation


AITER's preshuffle path is a paired writer/reader contract:

Writer: indexer_k_quant_and_cache_kernel(..., preshuffle=True) or an
equivalent writer must place FP8 K bytes in MFMA 16x16 preshuffled layout.
Reader: deepgemm_fp8_paged_mqa_logits(..., Preshuffle=True) or
cp_gather_indexer_k_quant_cache(..., preshuffle=True) reads that same layout.
Scale layout is unchanged: one FP32 scale per token lives after the
block_size * head_dim K-byte region for each block.
For a logical K element (token = block_offset, dim = head_dim_idx), preshuffle
stores it at:

token_tile_id = block_offset / 16
token_in_tile = block_offset % 16
col_tile_id = head_dim_idx / 16
col_in_tile = head_dim_idx % 16

offset =
  block_idx * cache_block_size * cache_stride
+ token_tile_id * (16 * head_dim)
+ col_tile_id * (16 * 16)
+ token_in_tile * 16
+ col_in_tile
