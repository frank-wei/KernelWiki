## Summary

Update `mega_moe_pre_dispatch` to honor the physical row stride of DeepGEMM's MXFP8 scale output instead of assuming packed rows.

DeepGEMM stores one scale byte per 32 hidden elements and aligns each token row to 16 bytes for TMA:

    logical row bytes  = H / 32
    physical row bytes = align_up(H / 32, 16)

Under DeepGEMM's `H % 128 == 0` layout requirement, padding is needed whenever `H % 512 != 0`:

| H | Logical row | Physical row | Padding |
| ---: | ---: | ---: | ---: |
| 2176 | 68 B | 80 B | 12 B |
| 2304 | 72 B | 80 B | 8 B |
| 2432 | 76 B | 80 B | 4 B |
| 2560 | 80 B | 80 B | 0 B |

Packed addressing misplaces scale rows after token 0. Once DeepGEMM exposes the correct physical stride, the existing contiguous-tensor check rejects the view instead.

Accept padded row-major scale views, validate their logical width and alignment, and use `buf_x_sf.stride(0)` when addressing each token row. Already-aligned layouts are unchanged.

## Modifications

- Accept row-major scale views with a contiguous inner dim
