# MiniMax-M3: allocate the lightning-indexer K cache in fp8 on gfx95

MiniMax-M3's sparse attention keeps a second, much narrower KV cache — the
lightning-indexer K cache — whose only job is to produce the per-block scores
that pick which KV blocks the main attention reads. It is sized over every
sparse layer at `head_num=1, head_dim=sparse_index_dim`, and on ROCm it was
allocated in the model dtype (bf16) while the main K/V follow
`kv_cache_dtype`. This PR allocates it in `fp8_e4m3fn` on gfx95 (MI350/MI355)
behind `SGLANG_OPT_MINIMAX_M3_FP8_INDEX_CACHE`, exactly halving that pool. It
is a widening mode — bf16 q against fp8 k in the score kernels — which is the
same contract `m3_fp8_attn_gemm_enabled` already uses for the SM100 fp8
attn-GEMM path; this change makes the same `index_dtype=fp8` choice reachable
on gfx95 without requiring fp8 main KV. The Triton qk-norm-rope kernel now
stores into the index cache in *that cache's* dtype rather than q's, so the
value is rounded once from fp32 instead of twice through bf16 (a no-op cast
when the two dtypes match).
