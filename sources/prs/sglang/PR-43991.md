## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
#42486 switched the default Q/K L2 norm in `fused_sigmoid_gating_delta_rule_update` to "compute `1 / sqrt(...)`, then multiply", but `fused_kda_conv_recurrent_verify` still computes `b_q / sqrt(...)`. `x / y` and `x * (1 / y)` round differently, so the fused verify kernel stopped matching its reference bit for bit, and the ROCm-only `test_glm_fp32_weights_bit_exact_on_rocm[8,9]` fails on MI35x:

```
assert torch.equal(ic_fus[valid], ic_ref[valid])
AssertionError: assert False
```

https://github.com/sgl-project/sglang/actions/runs/38317177892/job/115041491933

The test's `_run_reference` is `causal_conv1d_update` + `fused_sigmoid_gating_delta_rule_update`, so this switches the fused kernel to the same reciprocal form, with the same order of operations. The case only runs on ROCm, which is why #42486's validation reports "2 ROCm-only cases skipped".

The other KDA failure on ROCm (`TestKDAVerifyDecodeParity`) has an unrelated cause and is fixed separately in #44089.
