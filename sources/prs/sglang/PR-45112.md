## Motivation

`python/sglang/kernels/README.md` says to classify kernels by the computation they perform, not by the model that first used them, and never to add a model bundle as a top-level group. An audit of current main found that this had drifted:

- `ops/muse_spark/` (#44665) was a model-named top-level group. It contained 22 files mixing norms, routing, GEMMs, collectives and reductions, with no KernelSpecs and no kernel tests. It had been added to `_GROUPS`, which is the only thing the guard test checked, so the test did not catch it.
- `attention/dsv4/` and `attention/dsa/` had collected quantization kernels, KV-cache stores and copies, a split-K GEMV, collective attention-residual kernels, runtime controllers and config predicates, and test oracles.
- Elsewhere, ops sat in the wrong group: GEMMs in `quantization`, RMSNorms in `elementwise`, attention metadata in `kvcache`, a forwarding shim in `attention/utils.py`, and the same computation implemented in two or three groups.

This PR fixes all of it in one pass. It writes the classification rules into the README and the `kernel-organization` skill, and makes the guard test enforce the README.
