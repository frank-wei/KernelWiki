## Motivation

#36890 added decode context parallelism to the unified memory pool, but gated `--enable-unified-memory --dcp-size > 1` to `--attention-backend flashinfer`. That excludes `cutedsl_mla`, which is the DCP-native MLA decode kernel on Blackwell (flashinfer accepts `enable_dcp=True` for no other backend) and what the B300 hosts run. So the feature was unusable there.

The reason for the gate is that unified memory plus DCP has two read-index production routes, and #36890 converted only one:

1. **flashinfer** — `plan_dcp_decode_metadata` compacts this rank's widened ids in place, then the caller converts them with `KVIndexTranslator.translate_dcp_read_ids`.
2. **the `trtllm_mla` family** (`trtllm_mla`, `cutedsl_mla`, `tokenspeed_mla`) — a block table built by `create_mla_kv_page_table_for_dcp`, which gathers a rank's cyclic slice straight out of `req_to_token`, bypassing `build_index_table` entirely.

Route 2 collapsed the widened virtual id (`// dcp_size`) and stopped there. That is correct on a static pool, where the collapsed page *is* the physical page, but under the unified pool it is still virtual and needs one more hop through the pool's page table.
