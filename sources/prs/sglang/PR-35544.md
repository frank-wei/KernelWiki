## Motivation

ReplaySSM speculative decoding currently materializes the full GDN checkpoint state on every target step, even though most speculative iterations only append a small amount of history. Deferring that work removes repeated state materialization from the decode critical path.

## Modifications

- Store speculative GDN updates in a bounded circular history and materialize the checkpoint once per accepted verify window.
- Preserve recurrent BF16 behavior with compensated high/low representations for the compact update vector and normalized key.
- Keep replay history and cursors request-scoped while keeping the physical checkpoint Mamba-slot-scoped.
- Size ReplaySSM scratch by active request capacity, and preserve reset, donation, retraction, and recovery lifetimes.

The review scope is limited to the ReplaySSM kernel, the request/state ownership and accounting needed by that kernel, and one existing accounting test. The larger experimental compatibility framework and additional defensive abstractions are not part of this PR.

## Accuracy Tests

- Nine targeted GPU tests passed, covering existing accounting/support checks plus BF16 and FP32 64-window recurrent comparisons
