## Summary

Plain softmax routing has no correction bias, but `fused_topk` currently allocates and clears a device-side zero tensor on every call to satisfy the fused router kernel interface. This PR represents the same operation with a compile-time no-bias path, avoiding the allocation, fill, and bias load while preserving the existing sigmoid/correction-bias path.

## Changes

- Allow `moe_fused_gate` to receive `bias=None` for softmax routing.
- Add a `HAS_BIAS` constexpr path so the Triton kernel keeps zero in registers when no real bias exists.
- Pass `None` from `fused_topk` instead of materializing `torch.zeros(num_experts)`.
- Add exact-comparison coverage between `None` and an explicit zero bias for batch sizes 1, 8, and 32.

The change is intentionally limited to zero-bias removal and does not include the separately evaluated selected-expert softmax optimization.

## Validation

### GSM8K accuracy

The standard SGLang GSM8K evaluator used Qwen3.5-397B-A17B-NVFP4-V2, the official test set, eight-shot chat prompting, the checkpoint's default chat template, temperature 0, top-p 1, a 32,768-token generation limit, 32 request threads, and last-number exact match.
