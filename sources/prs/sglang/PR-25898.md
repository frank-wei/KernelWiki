## Motivation

DeepSeek-V4 (DSV4) on AMD MI300X/MI350X GPUs encounters multiple runtime failures when serving inference workloads:

1. **GPU fault (HSA_STATUS_ERROR_EXCEPTION)** — The core `CompressStatePool` is initialized without `swa_page_size`, defaulting to 0. This causes division-by-zero in `translate_from_swa_loc_to_state_loc()`, producing out-of-bounds `state_loc` indices (e.g., 525448 vs buffer size 470528) that trigger a hardware exception during `index_put_`.

2. **Model registration failure** — `fused_softmax_pool_triton` is imported at module level in `compress_hip.py` but doesn't exist in the current `deepseek_v4_rope.py`, blocking `DeepseekV4ForCausalLM` class registration.

3. **JIT kernel incompatibilities** — Wave64 shuffle intrinsics, DLPack device type, FP8 conversion, and kernel launch APIs differ between CUDA and HIP.
