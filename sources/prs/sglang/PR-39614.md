## Motivation

The QSA block selector of Qwen3.8-Flash-Next (`qwen4_exp`) keeps one compressed indexer key per `compress_ratio` tokens and dots every index query against that cache. Both operands are bf16 today. vLLM added an fp8 indexer cache in vllm-project/vllm#54890 (`--attention-config.indexer_kv_dtype=fp8`, GB300: decode 1.0–1.5×, prefill 1.4–1.7× on the indexer). This PR adds the same option to SGLang, implemented in the existing TileLang scoring kernels and JIT prep kernels.

`--qsa-indexer-dtype {auto,bfloat16,fp8_e4m3}`, default `auto` (bf16, no behaviour change).

## Modifications

Data path today: per token the JIT kernel `qsa_index_q_prep` RMS-norms + MRoPEs the index Q and writes the raw index K into a per-request pending ring; every `compress_ratio` tokens `qsa_index_k_compress` averages the ring rows (fp32), norms, ropes and writes one compressed key; the TileLang MQA kernels score Q against the compressed cache (fp32 logits), `qsa_fast_topk` picks the blocks, and sparse attention then reads the main bf16 KV cache.
