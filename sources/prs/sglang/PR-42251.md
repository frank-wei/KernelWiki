## Motivation

A speculative-decoding target verify runs `fused_sigmoid_gating_delta_rule_update` over a chain of candidate tokens in one launch and keeps the recurrent state in FP32 for the whole chain. Decode runs one token per launch and, with a BF16 state pool, persists BF16 after every token. Both compute the same recurrence, but not the same numbers: after a few tokens the verify states no longer match the states the decode path would have produced from the same tokens, so the verified logits drift away from the decode logits. When decode runs on FlashInfer's `recurrent_kda` CuTe DSL kernel (`--linear-attn-decode-backend flashinfer`) the gap widens further, because that kernel forms its gate in base 2 with `ex2.approx`/`lg2.approx`, reduces the Q/K norms lane-striped with packed f32x2 FMA, decays and updates the state through FMA, and receives beta already sigmoided.

This PR gives the shared Triton recurrence an opt-in decode-parity mode so a KDA multi-token verify (the Triton verify is still the only chain-plus-tree KDA verify) can reproduce that decode kernel step for step instead of approximating it.
