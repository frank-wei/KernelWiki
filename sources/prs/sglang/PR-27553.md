## Motivation

In `get_w8a8_block_fp8_configs`, when `BLOCK_SIZE_K < block_k`, it clamps `BLOCK_SIZE_K` to `block_k`, which may cause the error (L40): `triton.runtime.errors.OutOfResources: out of resource: shared memory, Required: 148480, Hardware limit: 101376`.
In fact, on CUDA, when `block_k % BLOCK_SIZE_K == 0`, the value is still valid and does not need to be clamped (PR: https://github.com/sgl-project/sglang/pull/20819).

## Modifications

- Preserve CUDA tuned `BLOCK_SIZE_K` values when `block_k % BLOCK_SIZE_K == 0`.
- Continue clamping non-CUDA configs and CUDA configs whose `BLOCK_SIZE_K` does not evenly divide `block_k`.
- Keep the existing warning behavior for entries that are actually clamped.
