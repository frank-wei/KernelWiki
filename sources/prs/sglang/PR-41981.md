## Motivation

<!-- Describe the purpose and goals of this pull request. -->

When `SGLANG_SIMULATE_ACC_LEN` is set, dspark overwrites `correct_len` with the simulated value right after verify. But the draft and accept steps still go through the full sampling path, and most of that result is thrown away. The only thing we still need from it is the bonus token, which should keep following the request's temperature.

```python
# python/sglang/srt/speculative/dspark_components/dspark_verify.py
# sampling accept
correct_len, bonus, cap_trim_lens = accept_draft_tokens(
    ...
)
# correct_len is overwritten right away
if self._simulate_acc_len > 0:
    correct_len = self._simulated_correct_len(
        bs=bs, dtype=correct_len.dtype, device=correct_len.device
    )
```
