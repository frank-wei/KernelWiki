## Motivation

The fused DeepSeek V4 K normalization/RoPE kernel reads `out_loc` before `PDLWaitPrimary`. Cache locations can be produced immediately before this kernel: [`get_swa_out_cache_loc`](https://github.com/sgl-project/sglang/blob/5aab054ec8ce6b6100fbfb7aafe67d632a7df3aa/python/sglang/srt/layers/attention/deepseek_v4_backend.py#L1633-L1654) falls back to gathering the SWA mapping and converting it to int32, and its result is passed directly to the fused cache-store call.

[CUDA's PDL contract](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/programmatic-dependent-launch.html#api-description) requires the dependency wait before consuming the preceding kernel's results, including when the producer uses an implicit launch trigger. Reading `out_loc` before that wait can select a stale cache slot.

## Modifications

Move only the `out_loc` load after the existing wait. Preserve the early position load and frequency-pointer calculation, retaining their prefetch overlap and the existing assumption that positions are already prepared.
