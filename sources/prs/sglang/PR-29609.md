## Motivation

DeepSeek-V4 online C128 compression keeps per-token compress states in the KV/cache pool. The existing path stores these states as FP32. This PR adds BF16 compress-state support so the online C128 state pool can use less memory or, under auto pool sizing, fit more tokens in the same static memory budget.

This is controlled by:

```bash
SGLANG_DSV4_COMPRESS_STATE_DTYPE=bf16
```

The default remains FP32.

**Next Steps：**
- Split SGLANG_DSV4_COMPRESS_STATE_DTYPE into separate C4 and C128 controls. C4 gains are shape-dependent because it is not consistently memory-bandwidth-bound, while C128 benefits are more stable due to larger state-buffer traffic.

- Add BF16 compute support to reduce BF16/FP32 conversion overhead and further improve kernel performance.

## Modifications

- Add `SGLANG_DSV4_COMPRESS_STATE_DTYPE` to select FP32 or BF16 compress-state storage. The default remains FP32.
- Thread the selected dtyp
