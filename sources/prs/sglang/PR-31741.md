## Problem

The mamba KV-cache JIT transfer kernel (`transfer_kv_mamba_pf_lf` / `transfer_kv_mamba_lf_pf`) is gated to CUDA only, so on ROCm the symbols are never imported. The nightly AMD kernel job (`nightly-*-1-gpu-kernel`, `test/registered/jit/test_transfer_mamba.py`) has been red every run with `NameError: transfer_kv_mamba_lf_pf` (12 subtests) — first seen Jul-16, never-passed on AMD.

## Root cause (two parts)

1. **Import guard.** In `memory_pool_host.py` the mamba JIT import is under `if _is_cuda:` only, while the `sgl_kernel.kvcacheio` import one line above already uses `if _is_cuda or _is_hip:`. On ROCm the two symbols never bind → `NameError` when `MambaPoolHost` drives the `io_backend="kernel"` path.
2. **Runtime device check.** Widening the guard alone is **not** enough: `transfer_mamba.cuh` hardcodes `.with_device<kDLCUDA>()` in three `TensorMatcher`s, which rejects a `rocm:` tensor at runtime:

     at transfer_mamba.cuh:151
