## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
The mamba radix track path snapshots the SSM state at the last chunk boundary of chunk-unaligned sequences so a later prefix-cache hit can restore it. That path read the per-chunk states `h`, which are always stored in the activation dtype (bf16) — so the checkpoint was pinned to bf16 regardless of `--mamba-ssm-dtype`. With the default fp32 pool (and likewise for fp16), a cache hit restored a lower-precision state than a cache miss keeps, making cached and uncached runs numerically diverge. The chunk-aligned path and the in-place final-state path already wrote at the pool dtype; only this intermediate-state path could not honor it.

This PR snapshots the in-kernel fp32 accumulator and casts it once to the pool dtype, so checkpoints on this path faithfully follow `--mamba-ssm-dtype` (float32 / bfloat16 / float16):

- Triton `chunk_gated_delta_rule_fwd_h` gains `track_state`/`track_chunk_idx`: at the tracked chunk boundary it stores the fp32 accumulator into a per-sequence buffer, and `_track_mamba_state_extend` copies that buffer (instead of the rounded `h`) into the track slots, converting to `ssm_states.dtype` once.
- The Helion prefill kernel gets native support for the same snap
