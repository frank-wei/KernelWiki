# [XPU] Enable Gemma 4 E2B / E4B / 31B / 26B-A4B on Intel XPU

## Summary

Enable `google/gemma-4-E2B-it`, `google/gemma-4-E4B-it`, `google/gemma-4-31B-it`, and `google/gemma-4-26B-A4B-it` on Intel XPU with the `intel_xpu` attention backend. Gemma 4 is a hybrid model that interleaves sliding-window attention (SWA, head_dim=256) with full attention (head_dim=512).

**Key changes:**

- Fix `RMSNorm.forward_xpu` to handle >2D tensors produced by Gemma 4's per-layer input projection
- Implement hybrid `SWAKVPool` page-table translation for the `intel_xpu` backend (prefill, decode, page-size > 1 strided path)
- Support cross-layer KV sharing (`is_kv_shared_layer`) on `intel_xpu`
- Admit XPU into the fused `gemma_qkv_rmsnorm` Triton path (A1 norm fusion)
- Admit XPU into `gemma_rmsnorm_residual_scalar` Triton path (A2 norm fusion)
- Self-contained `Gemma4RMSNorm.forward_xpu` (no `forward_cuda` delegation)
- Extend `Gemma4ForConditionalGeneration` accepted backends to include `intel_xpu`
- Add E2B XPU smoke test (`test_simple_code_qa`, `test_sliding_window_long_context`, `test_sliding_window_3k_tokens`)
