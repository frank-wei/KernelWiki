## Motivation

The DeepSeek-V4 (DSA indexer) top-k v2 kernel carried an optional `raw_indices`
output that no production caller ever requests: the c4 indexer routes to the v1
kernel whenever it needs raw indices, so the v2 argument was only ever exercised
by a unit test. Everyone else still paid for it with a per-element
`raw_out != nullptr` branch inside the page-table transform loop.

While removing it, two PDL (programmatic dependent launch) details in the same
kernel turned out to be leaving performance on the table or resting on a
condition the caller was not told about.

## Modifications

**Output modes.** `raw_indices` is gone; `page_tables` becomes optional instead.
`None` selects a `TopKMode::INDICES` template that emits the selected positions
straight into the output, so the transform pass -- and the 8 KB shared staging
buffer it needs -- is compiled out rather than skipped at runtime. Passing a page
table keeps the existing behaviour bit for bit.
