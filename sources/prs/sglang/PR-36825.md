## Motivation

<!-- Describe the purpose and goals of this pull request. -->
Wan2.2-A14B at 720p OOMs on Intel XPU even though peak *allocated* memory is only ~7 GiB on a 24 GiB card. The cause is not capacity but a **vendor string used where a capability check belongs**: several places test for CUDA rather than for the capability they need. XPU therefore takes eager fallbacks that materialise fp32 hidden states (1.44 GiB each at 1280x720x81f, TP=4), a missing `forward_xpu` default aborts the transformer's customized load and falls back to native diffusers (which ignores the offload flags), and the post-eviction cache release never fires. Upstream had already renamed `_module_on_cuda` to `_module_on_supported_device`; XPU was never added to the list.
