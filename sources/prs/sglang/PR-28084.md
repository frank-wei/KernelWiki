## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
On AMD HIP the aiter MoE kernels cannot use topk_ids=-1 to drop CUDA-graph padding rows, so padded tokens are masked by zeroing their routing weights instead. The eager `arange + (>=) + boolean index_put_` path issues several launch-latency-bound kernels per call, twice per MoE layer.


## Modifications

1. Fused masking kernel: Added _fill_padded_rows, a single Triton kernel (one program per row; pad count read from device memory so it is CUDA/HIP-graph safe) that backs both _mask_topk_ids_padded_region and _zero_topk_weights_padded_region. Falls back to the eager path for non-contiguous tensors via _can_fuse_padded_region.

2. Removed a redundant pass: In _post_process_topk_ids, dropped the first HIP weight-zeroing call. The final pass already re-zeros after any shared-expert append/remap, so the earlier call was redundant (zeroing is idempotent) — halving the per-layer masking launches.

3. Opt-in full skip: Added the SGLANG_MORI_NO_PAD_MASK env flag (default off). When set, the HIP padded-token masking is skipped entirely, since padded rows are discarded downstream and the MoE combine is per-token. Gated off by default because it is a numerics-affecting change.

4. Tests: Added
