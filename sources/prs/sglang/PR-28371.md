## Motivation

The chunked SGMV LoRA backend (`--lora-backend csgmv`) can produce **incorrect output under CUDA graph** when a decode batch is replayed with a different number of active segments than were present at capture time.

`ChunkedSgmvLoRABackend` sorts tokens by adapter into contiguous segments, so the number of segments depends on how many distinct adapters appear in the batch. The CUDA-graph capture (warmup) typically sees a single dummy adapter (1 segment), but real decode steps can have several distinct adapters resident (multiple segments). The triton shrink/expand/embedding/kv_b kernels sized their launch grid to the **capture-time** segment count (`num_segments` / `bs`). On replay with more segments than were captured, the extra segments' work is silently skipped, and stale tail metadata from a previous (larger) batch can be read — yielding wrong or garbled LoRA output. This only manifests with multiple resident adapters under CUDA graph, so single-adapter and eager runs look fine.
