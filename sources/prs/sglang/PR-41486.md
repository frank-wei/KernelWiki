## Motivation

Speculative target verify on Gated DeltaNet hybrids (Qwen3.5, Qwen3-Next with MTP / EAGLE / DFlash) runs `fused_sigmoid_gating_delta_rule_update_kernel` once per linear-attention layer. On CUDA, the shared Triton wrapper always launches a 32-column value tile with one warp: `(V / 32) * HV * N` programs. For Qwen3.5-4B (HV=32, V=128) at batch 1, that is 128 single-warp programs on a 132-SM H200, and each program walks the draft tokens sequentially, so the kernel is latency-bound at the small batches where speculative decoding is used.

#39987 tuned this launch for Qwen3.5 TP4 on AMD gfx950 and kept CUDA unchanged. This PR is the SM90 counterpart. Narrowing the value tile to 4 columns (one warp) makes the verify kernel 2 to 3 times faster at batch 1 on H100 and H200, and it is never slower up to batch 64. Value columns are independent and the K reduction stays inside a program, so outputs and cached states are bit-identical.
