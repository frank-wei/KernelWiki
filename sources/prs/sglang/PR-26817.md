## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Add the real-data KV verification capability on top of the naive
(synthetic-only) canary: alongside the synthetic chain hash, hash the model's
REAL KV bytes into canary slot field[3] and verify them, so corruption of the
actual cached K/V is caught (not just the synthetic stamps).

- jit_kernel: RealKvHashMode (NONE/PARTIAL/ALL), RealKvSource descriptors, the
  real_kv fold helpers (canary_common.cuh) and their ABI, and the field[3]
  real_kv_hash store/verify in the write/verify kernels + refs. The synthetic
  chain hash (splitmix64_mix3) is unchanged; real_kv is a separate slot field.
- runtime: CanaryConfig.real_kv_hash_mode (from --kv-canary-real-data),
  CanaryBufferGroup.real_kv_sources_{k,v}, CanaryEndpoint real_kv plumbing,
  the pool-patcher real_kv source construction (buffer_alloc + adapters), and
  real_kv_hash_mode threading through kernel_launcher / single_forward_manager /
  sweep.
- server_args: the --kv-canary-real-data {none,partial,all} knob.
- tests/benches: real_kv coverage for the verify/write kernels and the runtime
  buffer-alloc / endpoint / pool-patcher units.

Gated by --kv-canary-real-data (default none -> dormant). Prereq for the
real_kv perturb self-te
