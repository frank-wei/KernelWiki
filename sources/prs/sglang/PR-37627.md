## Motivation

Under `--enable-unified-memory` a KV slot has two names: the **virtual** id the
scheduler allocates and the **physical** id where the slot currently sits, which
compaction can change. A non-speculative forward already routes every read and
write through `KVIndexTranslator`, so the two stay consistent.

Speculative decoding did not. Verify reads a **widened** window — the request's
live prefix plus the draft tokens being checked — and several backends built that
window's page table straight from `req_to_token` rows, or from a captured graph's
persistent buffer, without translating. On a plain pool that is invisible, since
the two id spaces coincide. On the unified pool it silently reads the wrong KV,
and because speculative decoding *rejects* wrong tokens rather than crashing, it
surfaces as degraded output rather than as a failure.

That is why `--enable-unified-memory` refuses every speculative algorithm except
DSPARK, and DSPARK only on the MLA verify family and Triton.
