## Motivation

`UnifiedMHATokenToKVPool.move_kv_cache` and `UnifiedMLATokenToKVPool.move_kv_cache` relocate whole page envelopes when the allocator compacts the unified pool. They do it with a gather/scatter on a `[num_pages, page_bytes]` view of the raw buffer (`env[tgt] = env[src]`), which materialises a temporary the size of every moved page before writing it back. With MiB-scale envelopes and many pages per compaction that is a payload-sized GPU allocation on the compaction path, taken from the same device the pool was sized to fill.

## Modifications

- Add `sglang/kernels/ops/kvcache/copy_pages.py`: a Triton kernel that copies the listed page envelopes within the pool buffer directly, one program per (page pair, block of words). It views the buffer as int64 words when the page size and storage offset are 8-byte aligned and falls back to a byte view otherwise, so no layout is rejected. The CPU path keeps the existing gather/scatter.
- Both unified `move_kv_cache` overrides call it instead of building the envelope view. Every byte of the envelope moves, including any per-page metadata, exactly as before.
