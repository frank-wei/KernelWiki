## Summary

Keep the existing `translate_loc_to_hisparse_device()` API and use a single Triton kernel for one-dimensional CUDA and ROCm GPU slot lists. The kernel preserves padding, supports strided inputs, and produces a contiguous result for the AITER fused KV-cache writer.

## Why translation is needed

The model’s output locations identify tokens logically. HiSparse maps those locations to rows in its GPU cache, and the fused writer needs those physical row numbers.
