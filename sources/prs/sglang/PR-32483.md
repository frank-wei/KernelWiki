## Motivation

`HiSparseCoordinator.swap_in_selected_pages()` currently clears `top_k_device_locs` with `fill_(-1)` before launching `load_cache_to_device_buffer_mla`.

The fill is needed only because the short-sequence path and CUDA Graph padded rows did not overwrite every output entry. It adds one GPU kernel launch to every HiSparse layer during each decode step.

## Modifications

- Remove the separate `top_k_device_locs.fill_(-1)` call.
- Make the existing JIT swap kernel fully define its output:
  - the short-sequence fast path writes either a valid device location or `-1` for every top-k entry;
  - CUDA Graph padded request rows are explicitly written as `-1`;
  - the long-sequence swap path is unchanged.
- Add regression tests that initialize the output with a nonzero stale value.
- Update the existing HiSparse benchmark to match the production call path.

No public API, configuration option, or dependency is introduced.

## Accuracy Tests

This change does not modify floating-point computation, KV layout, or copied KV values. It only changes initialization of the integer device-location output.
