## Motivation

Some fused QK-norm implementations emit q in a different (same-size) dtype than k — e.g. fp16 q while k stays bf16. The fused RoPE JIT kernels previously assumed a single dtype for q/k, and `RadixAttention` sized its extend output buffer off `q.dtype`, so a mixed-dtype q would change the dtype the attention backend writes.

## Modifications

- `python/sglang/jit_kernel/csrc/elementwise/rope.cuh`: factor the per-head rotation into `rope_rotate_head<T, ...>` and give `fused_rope_kernel` / `fused_rope_store_kernel` a separate `QDType` template parameter (same-size dtypes only, enforced with a `static_assert`). k/v and the KV caches keep `DType`. The k branch of the store kernel now passes the cache pointer into the shared helper instead of duplicating the rotation code.
- `python/sglang/jit_kernel/rope.py`: key the JIT module off both `k.dtype` and `q.dtype`.
- `python/sglang/srt/layers/radix_attention.py`: size the extend attention output buffer off `v.dtype` (the model dtype) when v is present, so a mixed-dtype q does not change the backend output dtype. The existing fp8→bf16 clamp for mxfp8 KV-cache attention is preserved (now applied to the v-derived dtype as well).
