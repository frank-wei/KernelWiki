## Motivation

`generate_draft_decode_kv_indices` and `create_flashinfer_kv_indices_triton` gather each request's token-level KV indices into a flat CSR stream with one Triton program per request (× draft step × topk), and each program crawls the whole context serially in a scalar loop. At long-context speculative decoding this becomes a per-iteration cost that scales linearly with batch context.

## Modifications

Add token-block parallelism to both kernels while keeping the historical launch shapes:

- `generate_draft_decode_kv_indices` gains a `NUM_STEPS: tl.constexpr = 0` parameter. With `NUM_STEPS == 0` (default) the kernel is the historical one: the same 128-wide copy loop and load order, with the token-block branches folded away at compile time. With `NUM_STEPS > 0`, the first grid axis packs `(step, token_block)` as `step + NUM_STEPS * block`, each program copies a strided subset of its request's index range with 512-wide blocks, and the per-step tail (draft-token entries and the `kv_indptr` update) is computed on token block 0 only.
