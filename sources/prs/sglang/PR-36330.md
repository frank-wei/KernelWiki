## Motivation

Qwen3.5 target verification on MI355X uses a short multi-token query (`max_seqlen_q <= 4`) with 16 query heads, one KV head, head size 256, page size 16, and FP8 KV cache. AITER's generic 3D unified-attention configuration processes one query token per workgroup and reloads the same paged KV data for each speculative token, leaving this latency-sensitive path substantially slower than the comparison implementation.

## Modifications

- Add an SGLang-owned Triton 3D unified-attention kernel and segment-reduction kernel specialized for the measured gfx950 Qwen3.5 MTP shape.
- Process two speculative query tokens per workgroup with `BLOCK_M=32` and `BLOCK_Q=2`, reusing each loaded KV tile across both tokens.
- Use `TILE_SIZE=32` and select 8-64 segments using both CU parallelism and per-segment KV work.
- Dispatch to the specialized kernel only for gfx950, BF16 query, FP8 KV, 16 query heads, one KV head, head size 256, page size 16, non-sliding attention, and no softcap or attention sinks. All other shapes retain the existing AITER path.
- Add an AMD unit test comparing the SGLang kernel against AITER for mixed speculative query lengths.
