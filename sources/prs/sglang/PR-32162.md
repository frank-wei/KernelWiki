## Motivation

The existing HiSparse swap path processes speculative decoding steps sequentially. For a four-step MTP request, this requires four independent cache lookups, swap passes, and cache-state updates. It also cannot naturally deduplicate misses shared by multiple speculative steps.

This PR adds a standalone multi-step HiSparse swap kernel. It treats all MTP top-k tensors as one working set and resolves their device locations in one gather/commit launch pair. The scope of this PR is intentionally limited to the swap kernel, its JIT wrapper, correctness tests, and benchmark. It does not include IO prefetching or coordinator integration.

## Design

The implementation uses two kernels:

1. A gather kernel flattens `[batch, steps, top_k]`, resolves extra-page and hot-cache hits, deduplicates host misses across speculative steps, and copies each unique miss into a scratch device location exactly once.
2. A per-request commit kernel updates the CLOCK cache, rotates scratch and hot locations, updates the token-to-slot hash tables, and resolves direct overflow misses.
