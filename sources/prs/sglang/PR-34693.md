## Motivation

`dsv3_router_gemm` is a single-purpose kernel: it only accepts exactly 256 or 384
experts with a hidden dim that is a multiple of 1024, and it is capped at 16 tokens.
The tiny GEMM added for Kimi-K3 solves the same problem — a skinny
`x[m, k] @ w[n, k].T` with a handful of rows — for a strictly larger set of shapes.
Keeping both means two kernels, two test files and two benchmarks for one job.

This PR deprecates the router kernel and routes `MoEGate` through the tiny GEMM.
Along the way the tiny GEMM's N variant gets the block-shape parameter that makes
it beat the router kernel everywhere we measured, on both Hopper and Blackwell.

## Modifications

**`k_unroll` for the N variant.** The block covers the whole K in one pass, so the
number of K vectors a thread owns trades block size for per-thread work. It is
derived in the C++ host wrapper from one constant — a thread owns `kBytes = 32`
bytes of K (`GEMMTraitN`) — which lands on **448 threads for K=7168 on both
architectures**: `k_unroll=2` pre-Blackwell, `k_unroll=1` on Blackwell where the
