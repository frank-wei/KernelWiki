## Summary

- keep the flattened token count `T` as a runtime scalar in the FLA L2-norm Triton kernel
- remove the unused `NB` compile-time argument
- reuse one compiled kernel across variable multimodal prefill lengths instead of compiling a new variant for every random image shape

This is especially visible for VLM serving because image resolution changes the flattened vision/token length from request to request. The launch grid remains dynamic (`cdiv(T, BT)`), while `D`, `BT`, and `BD` stay compile-time constants.

The helper is shared by the GDN and KDA attention paths, so the compile-cache improvement is not Qwen-specific. The measured data below is from Qwen3.6's GDN path; KDA/Kimi K3 performance is intentionally not claimed before public K3 weights and support are available.

## Performance

PR-before vs PR-after on **2x NVIDIA H200, TP2**, `Qwen/Qwen3.6-35B-A3B-FP8`, BCG only. Each request used four seeded random JPEGs in `512x512-768x1024`; cache was flushed before every run. Results are the median of 3 measured repetitions after 3 shape-varying warmups.
