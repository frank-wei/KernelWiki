## Motivation

LFM2-MoE's short-convolution path currently materializes `B * x`, transposes
the result for the generic causal-convolution kernel, and then materializes
`C * conv(B * x)`. On the BF16 TP1 LFM2.5-8B-A1B serving profile, these
separate launches and the transpose are a measurable prefill bottleneck.

## Modifications

- Add SM90 Triton prefill and decode kernels that fuse both gates with the
  width-3 depthwise convolution while preserving the two BF16 materialization
  points and in-place recurrent-state update.
- Dispatch only for the qualified CUDA/BF16/no-bias/width-3/hidden-size-2048
  domain; all other calls retain the existing causal-conv implementation.
- Keep target verification on the existing implementation.
- Add coverage for variable-length prefill, decode, padded slots, dispatch
  guards, recurrent state, and CUDA Graph replay with changed live inputs.
