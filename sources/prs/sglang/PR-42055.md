## Motivation

On the gfx950 MXFP8 dense routes (`--fp8-gemm-backend aiter`, or native), three producers hand their consumer bf16, and the consumer then runs its own per-32 MXFP8 quant as a separate launch (~4.5 us) in every layer.

## Modifications

- Shared expert SwiGLU -> down_proj: an MXFP8 down_proj now uses the Triton `silu_and_mul_clamp` epilogue, which emits fp8 + ue8m0 directly.
- wo_a -> wo_b: add an fp8 epilogue to the gfx950 batched wo_a GEMM and pass wo_b an `Mxfp8Activation`.
- FFN norm -> shared expert gate_up: use the existing `emit_fp8` output of the mHC rmsnorm launch.
- Each is gated by an env flag, default on for ROCm and off elsewhere: `SGLANG_HIP_SHARED_ACT_MXFP8`, `SGLANG_HIP_WO_A_MXFP8`, `SGLANG_HIP_FFN_NORM_MXFP8`.

## Accuracy Tests

Bit-exact against the unfused route (fp8 codes and ue8m0 scales). GSM8K 1319 5-shot, TP2, real acceptance: 0.904.

## Speed Tests and Profiling

MI355X TP2 + DSpark, c1
