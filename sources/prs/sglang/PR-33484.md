## Motivation

A DeepSeek-V4 C4 token is 584 bytes, but it is **not one contiguous range**. A page row holds 64 values of 576B followed by 64 scales of 8B:

```
/// Paged C4 cache layout:
/// VALUE 0, VALUE 1, ..., VALUE 63,
/// SCALE 0, SCALE 1, ..., SCALE 63,
/// [Padding to align to 576 bytes]
```

So the ROCm swap-in copies a token with two `transfer_item_warp` calls, 576B then 8B. On wave64 that is three wavefront passes — 64 value words, 8 value words, then 1 scale word — and only the first keeps the whole wavefront busy.

The passes also do not overlap. `item_size_bytes` reaches `transfer_item_warp` as a runtime argument, so the compiler keeps the value copy as a rolled loop with the wait inside the body. Disassembling the gfx950 code object:

```
global_load_dwordx2 v[30:31], v[22:23]
s_waitcnt vmcnt(0)
global_store_dwordx2 v[24:25], v[30:31]
s_cbranch_execnz ...                       <- second value pass
...
global_load_dwordx2 v[22:23], v[22:23]     <- scale
s_waitcnt vmcnt(0)
global_store_dwordx2 v[24:25], v[22:23]
```
