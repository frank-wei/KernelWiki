## Motivation

Fixes #43331. Since #20283 the GDN state pool uses `[N, HV, V, K]`, but the CuTe DSL decode kernel still indexes it as `[N, HV, K, V]`, so `--linear-attn-decode-backend cutedsl` produces garbage output.

## Modifications

- `cutedsl_gdn.py`: the kernels get a transposed `(pool, HV, K, V)` view of the pool and are compiled for that layout. State loads (128-bit `cp.async`) and stores now run along K, the contiguous dimension, through a K-contiguous shared-memory tile padded to 136 floats per row to keep the compute reads bank-conflict-free. The compute loops are unchanged.
- `test_cutedsl_gdn.py`: re-enable the precision test skipped in #20436 and compare the outputs and the whole state pool against Triton on one shared pool (small and large batch, dense and varlen). It fails on main and passes with this PR.

## Accuracy Tests

Qwen3.5-4B, BF16, TP=1, MTP disabled, `--mem-fraction-static 0.8`, one H200. GSM8K, 200
