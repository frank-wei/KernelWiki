## Motivation

Kimi-K3 uses two attention representations during prefill at TP8 on MI355X:

- Fresh/zero-prefix MHA: 12 heads with QK/V dimensions 192/128.
- Cached-prefix absorbed MLA: 12 query heads, one KV head, and QK/V
  dimensions 576/512.

Current Triton prefill leaves performance on the table for both shapes:

1. The exact K3 kernels use one pipeline stage and natural-exponential
   online softmax.
2. Absorbed 576/512 prefill processes one full 512-wide value accumulator,
   increasing register pressure.
3. FP8 cached-prefix P·V can underflow small softmax probabilities.
4. Aiter supports native FP8 zero-prefix prefill, but Triton lacks an
   equivalent opt-in path.

## Changes

### K3 prefill tuning

- Use two pipeline stages for exact gfx950 K3 192/128 and N32 576/512
  prefill kernels.
- Fold `log2(e)` into the attention scale and use `exp2` for unmodified K3
  logits.
- Convert stored LSE back to natural-log units.
- Preserve current compact ragged-grid scheduling and the generic
  Triton-3.7 fallback.

### 4×128 absorbed MLA kernel

Add a dedicated split-dimension kernel for cached-prefix K3 MLA:

```text
Q/K latent: 4 × 128
Q/K tail:       64
V/output:   4 × 128
```
