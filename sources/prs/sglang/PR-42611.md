## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Part of #41609. This PR fixes the sigmoid part of that issue.

- #39688 moved the beta sigmoid into the `kda_gate_chunk_cumsum` kernel and wrote it as `tl.sigmoid`.
- `tl.sigmoid` does not return exactly the same bits as `torch.sigmoid`, because `tl.exp` and Triton's `/` are approximate on CUDA. KDA feeds its state back into itself, so this small difference grows along the sequence.
- This PR uses `tl.div_rn(1.0, 1.0 + libdevice.exp(-x))` instead. It matches `torch.sigmoid` on all 2^32 fp32 inputs. `tl.sigmoid` differs on 95.7M of them.
- The tests now require exact equality and check every finite bf16 value.
- Not fixed here: the fused KDA projection and the separate projections still give different results (mean |Δlogp| 0.255 in the same test). One concatenated GEMM is not bit-identical to the separate GEMMs. To match v0.5.20 exactly, the projection fusion from #39688 also has to be turned off for these checkpoints.

Test on a B300 with `nvidia/GLM-5.3-Flash-NVFP4`. I feed the same 8 x 2048 tokens to each build (teacher forcing) and compare the logprobs. The reference is main with the `beta.float().sigmoid()` that was used before #39688.
