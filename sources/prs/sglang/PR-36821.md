## Motivation

The fused KDA chain-verify kernel (`fused_kda_conv_gating_verify`, gated by `SGLANG_OPT_FUSED_KDA_VERIFY`) and ReplaySSM spec-verify (`--enable-linear-replayssm` + spec ring) were mutually exclusive: `_can_run_fused_chain_verify` returned `False` whenever `replayssm_rawv` was set, so enabling ReplaySSM silently dropped the verify hot path back to the unfused reference pair (transpose-copy + `causal_conv1d_update` + transpose-copy + recurrence). We could have the ~1.3x fused verify kernel or the ReplaySSM memory win (no `intermediate_ssm` snapshot buffer, the dominant spec scratch), but not both.

On Blackwell the CuTe DSL dspark MTP kernel already composes ring-write with a fused verify, but that path is SM100-only with a fixed Kimi-K3 shape contract. This PR brings the same composition to the Triton fused chain-verify, which is the only fused verify available on Hopper and on non-dspark chain speculation.
