## Motivation

Related to #36207.

SGLang reserves physical KV-cache slot 0 as a finite padding source for CUDA
graph and DP-attention padding. Generic KV stores protect that invariant after
#32477, but MLA-specific writers bypass `store_cache()` and still accept
`loc == 0` as a write destination.

Undefined graph/DP-padding rows can therefore overwrite slot 0 with NaNs. A
later padded attention row may read the poisoned slot and propagate NaNs into
attention output and model logits. During the GLM-5.2 investigation, affected
requests produced short nonsensical output followed by one repeated token.

## Root-cause boundary

This PR fixes the SGLang-owned MLA writers:

| Writer | Covered here |
| --- | ---: |
| BF16 Triton MLA writer | Yes |
| FP8 quantized MLA writer | Yes |
| MLA scale writer | Yes |
| CUDA TMA/JIT MLA writer | Yes |
| AITER fused GLM rope/cat/cache writer | No |

The fused ROCm path through `aiter.fused_qk_rope_cat_and_cache_mla` writes KV
internally and then invokes attention with `save_kv_cache=False`. It bypasses
the writers changed here and requires a separate API-safe integration fix.
