## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Follow-up to #32971 / #32972. Those two made `--enable-unified-memory` work for Kimi-Linear, but the page-major full-attention allowlist still omitted `fa3` — which is exactly what an unspecified `--attention-backend` resolves to for an MLA model on Hopper. So on H100/H200 the feature **failed at startup under its own default configuration**, and you had to know to pass `--attention-backend triton`.

This is the pre-Blackwell counterpart of the same gap #32972 had for `flashinfer`, on the more common hardware.

## What this does

Adds `fa3` to the allowlist and remaps its page table to dense ids. **No fa3 kernel change is needed.** Its absorbed-MLA path reads the pool only through `page_table[b, i]` into `get_key_buffer(l)` reshaped to `(-1, page_size, heads, dim)`, and `build_dense_mla_views` hands out a *contiguous* per-layer view — so the last-dim slices and both reshapes behave exactly as they do on the static pool. The only thing missing was the table in DENSE id space instead of the virtual one `req_to_token` holds.

There is already a precedent for remapping at that site: the SWA pool threads `translate_loc_from_full_to_swa` through the same page-table build.
