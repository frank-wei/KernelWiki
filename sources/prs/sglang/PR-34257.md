## Motivation

Migrate CUDA per-token FP8 activation quantization from the prebuilt `sgl_kernel` path to SGLang's lightweight JIT kernel infrastructure. This reduces the CUDA runtime's dependency on the AOT wheel for this operation while preserving the existing output-buffer contract, numerical behavior, and public compatibility API.

## Modifications

- Add a JIT CUDA implementation of dynamic per-token FP8 E4M3 quantization with the existing CTA and warp dispatch strategies.
- Route SGLang CUDA serving through the JIT kernel registry and a `torch.compile`-compatible custom-op wrapper.
- Preserve the legacy CUDA `sgl_kernel.sgl_per_token_quant_fp8` entry point for external consumers, AOT/JIT differential testing, and performance comparisons. MUSA continues to use its AOT path.
- Preserve padded output support: output buffers may contain more rows than the input, and the kernel writes only the first `num_tokens` rows.
- Preserve the AOT dtype boundary and bit-level behavior, including the legacy dispatch-specific zero-row behavior.
- Move correctness coverage and benchmarking into the registered kernel test layout. The benchmark directly compares JIT and AOT implementations.
