## Motivation

DeepEP v2's `ElasticBuffer` is an NCCL-symmetric-memory all-to-all engine with a
fixed per-rank capacity. Fixed capacity means static communication shapes, which
makes the MoE decode path CUDA-graph capturable under any topology — including
multi-node, where legacy `low_latency` is not available as a graphable path.
This PR adds it as a standalone backend `deepep_v2` alongside `deepep`; only
expert-parallel dispatch/combine is replaced. Validated on Hopper (H20, H200)
and Blackwell (B200 `sm_100`, B300 `sm_103`).

## Modifications

- **`layers/moe/token_dispatcher/deepep_v2.py`** (new): the dispatcher.
  `--deepep-v2-mode direct|hybrid` selects the ElasticBuffer topology — **not**
  the legacy `normal/low_latency` split. Layout is chosen per batch by inference
  phase, not by comm mode: decode uses the expanded layout + masked GEMM (static
  shapes, graph-capturable, available under `hybrid` too), extend/prefill uses
  the contiguous layout. Single-shot `dispatch()/combine()` with a strict handle
  lifecycle; the guards run before the DeepEP import check so the module imports
  cleanly without DeepEP installed.
- **`kernels/ops/moe/ep_moe_kernels.py`**: masked-slab r
