## Motivation

Without sequence parallelism (e.g. MiniMax-H3 on one GPU), each SubBlock attention call routes all heads; Ulysses SP would shard them across ranks. The pool (`S*H*D`), score (`L*Gq*Gk`) and top-k (`row*G`) kernels then compute element offsets past 2^31 in int32, which wrap and crash with an illegal memory access (Xid 13).

Boundary on B200, D=128: at S=491,520, H=34 passes and H=35 crashes; at H=56, S=299,584 passes and S=299,648 crashes.

## Modifications

Compute the overflowing offsets in int64: the program ids in `_pool_kernel` and `_topk_kernel`, and the per-head output base pointer in `_score_kernel` (its per-element offsets stay int32). Add one regression test that fails before the fix.

## Accuracy Tests

- At H=34 (where stock works), scores and index are bitwise equal to stock.
- With the fix at 491,520x56 and 299,648x56, the last heads' scores and index are bitwise equal to the same heads routed alone. Pooled values match torch (max abs err 0.002).
- `test_subblock_sparse_attention.py`: the new test fails on stock (illegal memory access) and passes with the fix. All other tests pass.
