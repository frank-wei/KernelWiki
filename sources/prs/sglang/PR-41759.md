## Motivation

`moe_align_block_size` sizes `sorted_token_ids` as `numel + (num_experts + 1) * (block_size - 1)` int32s. The CUDA align kernels pad that buffer with 16-byte `int4` stores and round the store count *up* to a whole number of vectors, so whenever the length is not a multiple of 4 the last store writes 1 to 3 int32s past the end of the buffer. For top-8 routing over 128 experts (129 buckets with the sentinel) the length is 3 mod 4, so every call overruns by one int32.

The allocator's block rounding usually absorbs the stray write, which is why nothing faults.
