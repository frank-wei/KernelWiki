## Motivation

DeepSeek-V4 on AMD (MI35X, HIP) under high concurrency (TP8 + DP-attention, c512) trails. Per-layer trace analysis (pure-prefill + a c512/ISL8192 mixed trace) showed the gap was **not** the heavy GEMM/MoE kernels but a few avoidable overheads in the prefill / dp-attention path:

- the attention-output (inverse) RoPE kernel was ~2x slower due to a scattered memory access pattern;
- the MoE-gather path did two redundant full-buffer (~940 MB) device-to-device copies before the gate GEMM;
- the replicated (TP1) shared expert was computed on the gathered global buffer, and only in prefill, so decode paid a ~dp_size× cost.

This PR fixes these. All are HIP/DSV4 specific; non-AMD paths are unaffected.
