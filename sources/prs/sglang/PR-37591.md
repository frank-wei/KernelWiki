## Summary

- add a ROCm-specific cooperative top-k implementation for the three DSA indexer entry points
- use an fp32 coarse histogram, exact radix tie refinement, and an overflow rescan
- split long rows across blocks when a low batch size would otherwise leave the GPU underutilized
- preserve the raw, paged, and ragged interfaces and guard launches to the score device
- keep the CUDA implementation unchanged; ROCm tracks the native `topk.hip` source and does not hipify `topk.cu`

## Motivation

The previous ROCm path used `topk.hip` generated by hipifying `topk.cu`. Its fp16 coarse key can collapse a large part of a real indexer row into one bucket, and overflowing the candidate buffer can silently drop valid winners. On captured GLM-5.2 logits, selected-value recall fell as low as 0.53.

The new native HIP kernel keeps the selection exact by refining the full fp32 key and rescanning the row when the tie buffer overflows. It reaches 1.0 selected-value recall against `torch.topk` on the same inputs.
