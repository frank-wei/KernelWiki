## Bug

`RMSNorm.forward_cuda` silently drops the `cast_x_before_out_mul` flag when a residual is provided.

The non-residual path correctly dispatches to the HF JIT kernel (`rmsnorm_hf`) when the flag is set — and even falls back to `forward_native` when the JIT kernel's hidden-size / dtype constraints don't match (see lines 235-248). But the residual-present path falls through to `fused_add_rmsnorm` without any such fallback.

Reproducer (conceptually):
```python
norm = RMSNorm(hidden_size, eps=1e-5, cast_x_before_out_mul=True).cuda()
x = torch.randn(B, S, H, dtype=torch.bfloat16, device='cuda')

# Layer 0: residual is None → cast_x_before_out_mul honored
# (HF JIT kernel, or forward_native fallback if JIT not applicable)
out0 = norm(x)

# Layer 1+: residual provided → flag silently dropped, fused_add_rmsnorm used
out1, _ = norm(x, residual=x.clone())   # ← wrong math
```

For any transformer using the standard residual-stream pattern, every layer ≥ 1 silently produces the wrong math whenever `cast_x_before_out_mul=True`.
