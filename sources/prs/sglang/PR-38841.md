Two independent decode-path changes for MiniMax-M3, measured on GB300 (sm_103), TP4, `MiniMax-M3-NVFP4`, ISL 8192 / OSL 1024, `--context-length 1048576`.

## 1. Sparse-decode K/V tiles by page

`_gqa_share_sparse_decode_kernel` resolved each selected block by gathering its 128 slot ids from `req_to_token` and loading K/V through them, so every K/V address was data-dependent even where the slots were contiguous.

A selected block starts at a multiple of `block_size`, and `PagedTokenToKVPoolAllocator` lays slots out as `page * page_size + offset` (`mem_cache/allocator/paged.py`). So when `page_size >= block_size and page_size % block_size == 0` the block lies inside one page and its slots are contiguous: load only the block's first slot and offset from it, so K/V addressing becomes affine.

Gated on `page_size`, which the backend already tracks. Only `minimax_sparse_decode` passes the backend's `page_size` (M3 defaults it to 128 on SM100 and SM90, so the tile is on by default there); every other caller omits it and gets `page_size=0`, which keeps the gather, so nothing outside this configuration changes behaviour.
