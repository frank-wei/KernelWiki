## Upstream PR description (verbatim excerpt)

## What
Widen `token_id = tl.program_id(0)` to int64 in the three FP8 k-cache kernels that use it to scale pointer offsets:

- `python/sglang/kernels/ops/attention/dsa/quant_k_cache.py`
- `python/sglang/kernels/ops/attention/dsa/dequant_k_cache.py`
- `python/sglang/kernels/ops/attention/dsv4/quant_k_cache.py`

## Why
`token_id` scales pointer offsets into the k/scale buffers, for example `k_nope_ptr + token_id * k_nope_stride_0`. Leaving the program id at the default int32 lets the multiplication wrap after the offset exceeds 2^31. With a typical stride of 512, that can happen at about 4.2M tokens. Casting the program id to int64 keeps the pointer arithmetic correct at large offsets.

## Scope
Three one-line numerical-correctness hardenings. The surrounding kernel bodies and kernel interfaces are unchanged.
