## Motivation

SGLang's HiCache supports Mamba models (e.g., Qwen-Next), but the Mamba state transfer between host and device previously relied on `direct` I/O backend only (pure DMA). This PR introduces a dedicated JIT-compiled CUDA kernel for Mamba KV cache transfer, providing a `kernel` I/O backend option that uses cache-bypass loads/stores with software pipelining for efficient PCIe transfer. The block-cooperative design achieves up to **14x speedup** over the existing MLA kernel at low concurrency.

## Modifications

**New files:**
- `python/sglang/jit_kernel/csrc/kvcacheio/transfer_mamba.cuh` — CUDA kernel implementation with two kernels:
  - `transfer_mamba_load_kernel`: page_first → layer_first (per-layer load)
  - `transfer_mamba_backup_kernel`: layer_first → page_first (all-layer backup)
  - Uses `load_nc`/`store_nc` (cache-bypass) instructions with double buffering to maximize outstanding PCIe transactions
- `python/sglang/jit_kernel/transfer_mamba.py` — Python JIT wrapper exposing `transfer_kv_mamba_pf_lf` and `transfer_kv_mamba_lf_pf`

**Modified file:**
- `python/sglang/srt/mem_cache/memory_pool_host.py` — `MambaPoolHost` integration:
  - Relaxed layout restriction: n
