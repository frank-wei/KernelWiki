## Motivation
On ROCm, the Triton DSv4 KV store kernels (`triton_store_cache.py`) cast `loc` to int32 and compute cache offsets in int32.

DeepSeek-V4.1-Flash's compress-ratio-1 KV pool is ~23.6 GB per layer, so the offsets overflow once `loc` passes ~3.67M tokens: writes land outside the buffer, silently at first, then as a `Memory access fault` at ~7.34M tokens (hit during AgentX warmup at conc >= 16). The CUDA kernel with the same functionality uses int64 offsets.
## Modifications
Load `loc` as `tl.int64` in both kernels (flashmla and indexer).
