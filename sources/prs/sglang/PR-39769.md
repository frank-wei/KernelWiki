## Motivation

On a sliding-window layer, the stage-2 loop in `_fwd_kernel` sweeps the extend KV from 0:

```python
for start_n in range(0, extend_end, BLOCK_N):
```

The window mask inside that loop keeps `(q, kv)` only when `q <= kv + SLIDING_WINDOW_SIZE`, so every tile lying entirely below `cur_block_m * BLOCK_M - SLIDING_WINDOW_SIZE` is fully masked and contributes nothing.

Those tiles do not read K/V and do not run the dot — `SKIP_TILE` already guards that. What they still pay, once per tile, is the cost of establishing that they contribute nothing: building `final_mask` (the causal compare, the window compare, the `&`), and then the `[BLOCK_M, BLOCK_N]` cross-wave `tl.max` reduction that computes `SKIP_TILE` itself.

On a long extend with a small window that is the majority of the loop. At `extend_len = 8192` and `W = 127`, the last M block's floor sits at roughly `8192 - 127`, so almost every iteration is spent proving that the tile is empty.
