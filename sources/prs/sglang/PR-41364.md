## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
> (auto generated by Claude)

Adds `topk_page_transform` to the DeepSelect JIT top-k: for int32 indices without values, each selected column `i` of row `r` is written as `page_table[r, i // page_size] * page_size + i % page_size` directly from the epilogue, so callers get KV slot indices without a separate transform kernel. The vendored kernels gain three small hooks, each marked `[SGLang]`.

Also in this PR:
- Rename `csrc/deepselect` to `csrc/deep_select` to follow upstream naming (first commit, pure rename).
- Tighten the layout contract and reject violations instead of working around them: input base and row stride 128-byte aligned (was 1024), output pointer and row stride 32-byte aligned with `topk * sizeof` a multiple of 32 bytes. The output staging copy (`kernel_output_index`) is removed.
- Python interface: `indices_type` defaults to int32, only `input` and `topk` are positional, signature checks raise instead of assert and run once per cached module.
- Rewrite `test_deep_select.py` as functional checks against `torch.topk`, with fewer JIT signatures to cut CI compile time.

Validated on H200 and B200: `test/registered/kernels/ops/attention/test_deep_select.py` passes.
