## Motivation

By default, top-k v2 launches one block per row, so a long row is scanned by a single block **while most CUs sit idle**. On NVIDIA Hopper+, rows above a length threshold are split across a block cluster that shares DSMEM. CDNA has no clusters or DSMEM, so ROCm do not support top-k v2's cluster path. This happens often in reasoning-model decode: small batch, long context.

This PR adds a row split to top-k v2 for ROCm. It uses two launches: one to build the histogram, one to select the top-k from it, and global memory takes the place of DSMEM.

- **When it engages:** small batch, long context: `batch_size <= 64` and rows longer than a batch-dependent floor (40K at small batch). Everything else runs the existing path unchanged.
- **Kernel speedup:** 1.8–3.0x at batch 1–8 with 128K+ context; 1.56x geomean across all gated shapes.
- **End to end (GLM-5.2-MXFP4, TP4, MI355X):**
    - Single request:
        - TP4, batch 1 and 120K context, the decode top-k kernel is 2.07x faster and median ITL drops 3.8%.
