## Motivation

`_score_kernel` and `_combine_kernel` in `srt/layers/attn_residual.py` read the attention-residual bank `[T, NB, H]` at `bank_ptr + pid_t * stride_bm`. `pid_t = tl.program_id(0)` is int32 and so is the product. With Kimi-K3's `NB = 8`, `H = 7168`, `stride_bm = 57,344`, so the offset passes 2^31 − 1 at `pid_t = 37,450`: any call with **≥ 37,451 tokens** reads at a negative offset and dies with `an illegal memory access was encountered`. The error is reported asynchronously, usually at a later, unrelated launch.

Where this path runs:
- **SM100+ (Blackwell):** the main aggregation uses the int64-safe TMA kernel, but `_mix_fused` still runs for the DSpark aux-hidden capture (`aggregate_stream`). So a DSpark prefill pass with more than 37,450 tokens (e.g. `--chunked-prefill-size` ≥ 40k) crashes.
- **GPUs without the TMA path:** `_mix_fused` is the main aggregation of every layer.
- `attn_res_hip.py`'s `_agg_kernel` has the same `t * stride_bm` pattern.

## Modifications

- Cast the token program id to int64 in `_score_kernel`, `_combine_kernel` (`attn_residual.py`) and `_agg_kernel` (`attn_res_hip.py`). Only addressing changes.
