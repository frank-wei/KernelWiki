# SM100 Native NVFP4 KV Cache

Part of #29913.

## What this implements

- Native packed NVFP4 KV-cache prefill and decode on SM100/SM103 through TRT-LLM GenMHA.
- An optional FlashInfer prefill path that dequantizes the stored FP4 cache into a shared FP8 E4M3 workspace.
- Eager/CUDA Graph execution, normal decode, top-k-1 EAGLE/EAGLE3/NEXTN, and breadth-1 NGRAM.
- FlashInfer NVFP4 quantization plus a fused incremental slot-scatter kernel that writes GenMHA K/V scale layouts directly.

Main modules touched: argument resolution, NVFP4 quantization/storage and KV-pool sizing, FlashInfer/TRT-LLM attention integration, and registered SM100 unit/E2E tests.

## Options

```bash
--kv-cache-dtype nvfp4
--prefill-kv-cache-dequant-dtype {auto,nvfp4,fp8_e4m3}
```

- `nvfp4`: TRT-LLM GenMHA consumes packed FP4 directly during prefill, with no additional dequantization.
- `fp8_e4m3`: FlashInfer dequantizes FP4 into an FP8 prefill workspace.
- `auto`: selects `nvfp4` on SM100 and `fp8_e4m3` on SM120.

The stored cache and decode input remain NVFP4 in every mode. Here `nvfp4` explicitly means that prefill reads the native packed cache without any additional dequantization.
