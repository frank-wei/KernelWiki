# MoE: single-launch small-batch sorting with fused mxfp8 activation quant

aiter's opus MoE sorting kernel is sized for thousands of tokens; at decode batch sizes it
costs roughly 7us/layer of launch and ramp overhead, and the separate
`fused_dynamic_mxfp8_quant_moe_sort` stage1 activation quant costs another ~4us on top. When
the number of routing pairs `P = M * topk` is at most 64, the whole sorting job — stable
sort-by-expert, per-expert block padding, the expert-id table, `num_valid`, and the `moe_buf`
zero-fill — fits into one small Triton program built on `P x P` rank compares, and the stage1
mxfp8 quant rides the same launch on dedicated CTAs that recompute the (cheap) pair math
rather than cross-CTA synchronizing. This is installed as three runtime patch points on the
`aiter.fused_moe` module namespace (`fused_moe`, `_moe_sorting_impl`,
`fused_dynamic_mxfp8_quant_moe_sort`), each falling back to the original aiter function
whenever the fast path does not apply, so a stock aiter install needs no changes; the patch is
