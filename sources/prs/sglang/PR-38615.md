## Motivation

The single-stage radix block top-k is gated on `max_seqblock <= 4096` on CUDA, matching the `kIters` register array in `TopKTrait::forward`. `max_seqblock` is derived from the decode graph's capture-time bound, which is the configured context length — not the live sequence. So `--context-length 1048576` yields 8192 blocks and drops to the two-stage Triton top-k even when the running sequence is a few dozen blocks.

MiniMax-M3's default context is 1M, so this is the default configuration. #36560 lifted the cap to 16384 on ROCm, where the kernel is a histogram select; CUDA still stops at 4096.

## Modifications

Raising the CUDA cap alone is not free: all three size branches share one `__global__` kernel, so a larger `kIters` raises register pressure for every launch, including the short rows that take the cheap branches.

Instead, the CUDA radix path is instantiated per register bucket: `forward` and both kernels take the bucket as a template argument, and the launchers dispatch on `max_seqblock` over `{4096, 8192, 16384}`.
