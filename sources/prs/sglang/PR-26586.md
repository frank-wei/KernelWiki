## Motivation

KDA decode is **overhead-bound** at small batch. The existing flow inside `KDAAttnBackend.forward_decode` is:

```
causal_conv1d_update(mixed_qkv)
  → qkv.split([q_dim, k_dim, v_dim], dim=-1)
  → q.unflatten + q.unsqueeze
  → k.unflatten + k.unsqueeze
  → v.unflatten + v.unsqueeze
  → fused_sigmoid_gating_delta_rule_update(q, k, v, a, b, ..., is_kda=True)
```

For B=1, T=1 the actual math per layer is tiny (a few rank-1 state updates), but the wall-clock latency is dominated by:

1. **Python/PyTorch dispatch overhead** — `split` + 3× `unflatten` + 3× `unsqueeze` cost ~15-20µs of CPU per layer even though they only produce views.
2. **Kernel launch overhead** — one extra kernel launch.
3. **Generic kernel dead branches** — `fused_sigmoid_gating_delta_rule_update_kernel` carries `for T` loop, `IS_VARLEN`, `HAS_EAGLE_TREE_CUSTOM_ATTN_MASK`, `CACHE_INTERMEDIATE_STATES`, `DISABLE_STATE_UPDATE` — five compile-time flags whose dead/degenerate branches still occupy registers and hurt instruction scheduling for the T=1 decode case.
