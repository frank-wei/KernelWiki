## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
GSan currently derives inter-kernel ordering from stream launch order, which cannot represent branches and joins in explicit CUDA graphs. Replace the implicit predecessor selection with per-node launch descriptors: full dependencies acquire completion clocks at kernel entry, while programmatic dependencies acquire them at `gdc_wait`.

Add graph boundary helpers, replay and lifetime handling, and immutable completion snapshots for dependencies established by CUDA events. Eager launches use the same descriptor interface. Tests cover fork/join graphs, PDL, repeated launches, stream transitions, lifetime cleanup, and detection of unordered accesses and missing waits. Stream capture remains unsupported.

### Validation

- Rebuilt the PR source on GB300 and verified the patched test checksum. GSan suite: **421 passed, 2 xfailed** in the main phase; **8 passed, 1 skipped** in the multi-GPU phase. The multi-GPU phase passed on retry after a TCP port collision during process-group setup.
- Repeated both graph PDL failure cases 50 times each across eight workers: **100 passed**. These retain exact diagnostic and source-location assertions.
- All commit hooks passed, including Ruff, YAPF, myp
