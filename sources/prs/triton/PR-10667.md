## Summary

`_keyed_add` (used by the bitmatrix metadata kernels) packs a key in the upper 16 bits of a `uint32` and a running count in the lower 16 bits, combining entries with `x + y - kx`.

For a large key — in particular the `0xffff0000` padding sentinel produced for masked lanes — the intermediate `x + y` evaluates to `2*key + counts`, which **overflows `uint32`**. The final result is still correct via wraparound, but with `TRITON_DEBUG=1` the integer-overflow checker fires a device-side assertion and aborts the kernel:

```
Assertion `int32 overflow detected for operation add` failed.
```

This is what users hit when serving GPT-OSS with `TRITON_DEBUG=1` (#7945).

## Fix

Add only the counts (lower 16 bits) and re-attach the shared key:

```python
z = tl.where(kx == ky, kx | ((x & count_mask) + (y & count_mask)), y)
```

The counts are bounded by `BLOCK_SIZE <= 32768` (enforced by an existing `static_assert`), so their sum stays within 16 bits and `kx | sum` reproduces `x + y - kx` exactly — but the add never overflows `uint32`.

Equivalence was checked exhaustively in Python over all key/count combinations within the `BLOCK_SIZE` bound: the new form is bitwise-identical to t
