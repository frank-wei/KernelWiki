## Problem

GFX1250/CDNA5 adds an asymmetric scaled WMMA instruction with physical shape `[32, 16, K]`. `make_partitioned_dot_layouts()` always created a transposed WMMA result layout, but derived its CTA warp/register bases from the physical `32x16` dimensions.

With `isTransposed=true`, that physical instruction produces a logical `16x32` output tile. Treating it as `32x16` creates CTA bases in the wrong tensor coordinates. When composed with a `128x128` accumulator, the oversized logical N extent is clipped, making the layout non-injective and assigning duplicate accumulator values to each thread.

This doubles the accumulator representation and static WMMA repetitions in the MXFP4 GEMM kernel, causing excessive VGPR pressure and register spilling.

## Fix

- Add a `transposed` parameter to `make_partitioned_dot_layouts()`, defaulting to `True` to preserve existing behavior and the common WMMA use case.

- Keep `instr_shape` as the physical hardware instruction shape.
- Clarify the physical-versus-logical distinction in the helper documentation and diagnostics.
