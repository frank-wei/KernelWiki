## Summary

Import `triton_kernels.numerics` and `triton_kernels.target_info` without loading PyTorch. Defer numerics type annotations and use Triton's native device-property query in `num_sms()`, preserving its device-0 behavior.

Fresh-process import medians versus main (`691a6deec4`):

| Module | Before | After |
| --- | ---: | ---: |
| `numerics` | 708 ms | 7 ms |
| `target_info` | 944 ms | 272 ms |

Measured on macOS arm64 with Python 3.12.9 and PyTorch 2.11.0: five alternating samples per version after warmup. Each import starts with Torch unloaded; savings are not additive.

## Validation

On four NVIDIA GB300 GPUs, the native query returned **152 multiprocessors** per GPU, matching PyTorch. It passed with Torch imports blocked and `TRITON_DEFAULT_BACKEND=nvidia`. Automatic discovery also passed with #11666 applied; backend discovery on unmodified main still imports Torch independently of this helper. No AMD GPU was tested.

Passed on CPU (macOS arm64). This checks both module imports and default numerics metadata while rejecting every Torch import attempt:
