## Summary

Keep persistent Blackwell NVFP4 activation × dense BF16/FP16 matmuls within the 512-column tensor-memory limit by capping the default `block_n` at 128. Keep the existing MXFP `block_k` and warp tuning separate, and preserve explicit planner constraints.

Extend the existing matmul matrix with routed, activation-scale-swizzled `M=256, N=256, K=128` cases for both dense RHS dtypes. No standalone planner-test setup is needed.

## Validation

Tested [Cover NVFP4 dense matmul in the existing test matrix](https://github.com/triton-lang/triton/commit/fc5959b3da31a02bcaec0d673461a107e81ba8ae) on NVIDIA GB300 (SM 10.3), using a compiler built from the merged [Skip test that IMAs on h100](https://github.com/triton-lang/triton/commit/5f1539790306a978b8612e268da38facb471fff1) main revision.

- Main plus the new cases: 12 failures, all tensor-memory exhaustion (8 require 640 columns; 4 require 576).
- Fixed branch, identical cases: 12 passed, 84 skipped. Includes scatter, gamma, and K-ragged variants.
- NVIDIA planner and split-K tests: 16 passed, 4 skipped.
- Related MXFP/NVFP4 × dense matmul cases: 444 passed, 516 skipped.
