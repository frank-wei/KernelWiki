## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
GSan queried the active CUDA driver during compiler option parsing to reserve enough shared memory for one CTA per SM. This made ahead-of-time compilation depend on a live GPU.

Resolve the reservation in `CudaLauncher` and use that size for function loading, eager kernel launches, and native CUDA graph launch descriptors, while keeping compiled shared-memory metadata device-independent. Remove the `set-minimum-shared-memory` pass, its bindings and registration, and the `min_shared_mem` option. Extend the existing regressions to reject driver access during compilation and check the shared-memory size passed to eager and explicit graph launches.

### Validation

- Brix GB300 native rebuild and focused GSan lowering lit test passed.
- 12 focused tests passed: driver-free compilation, eager shared-memory reservation, and all explicit graph fork/join replay combinations.
- Full single-GPU GSan suite: 466 passed, 10 skipped, 3 xfailed using eight workers.
- All applicable pre-commit hooks passed, including Ruff, YAPF, clang-format, and mypy.
<!-- upstream-excerpt-end -->
