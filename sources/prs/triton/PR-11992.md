## Summary

AMD matmul defaults currently apply an eight-way XCD program-ID swizzle to
every HIP target. This is useful on multi-XCD CDNA GPUs, where consecutive
programs may otherwise be distributed across XCDs, but RDNA does not expose
that topology. On RDNA, the permutation instead disrupts the grouped-tile
ordering and reduces cache locality.

Use a single scheduling domain for RDNA3 and RDNA4. The existing eight-way
behavior remains unchanged for CDNA and other AMD targets. The selected XCD
count is also passed consistently to the block-size heuristic.

## Performance

Measured on an AMD Radeon AI PRO R9700 (`gfx1201`) with ROCm 7.2. The workload
is BF16 x BF16 -> BF16 with FP32 accumulation. Each session used three warmups
and ten timed samples per shape. The A/B comparison held all launch parameters
constant (`BLOCK_M=128`, `BLOCK_N=256`, `BLOCK_K=64`, 8 warps, 2 stages,
`GROUP_M=4`) and changed only `XCD_SWIZZLE` from 8 to 1.

Representative session medians:

| Shape (M x N x K) | XCD=8 | XCD=1 | Reduction |
|---|---:|---:|---:|
| 9322 x 21504 x 5376 | 21.500 ms | 19.045 ms | 11.4% |
| 9322 x 5376 x 7168 | 7.355 ms | 6.733 ms | 8.5% |
| 9322 x 28672 x 5376 | 29.108 ms | 25.
