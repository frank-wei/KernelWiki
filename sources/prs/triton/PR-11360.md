## Summary

Fuse Hopper MXFP4 bit packing/unpacking and optional shuffled Blackwell value conversion to remove large intermediates. For the measured 128 MiB inputs, direct conversion uses **50–91% less peak allocated memory** and is **4.24–21.26× faster when warmed**. This improves weight preparation, not the matmul itself.

Launches follow the input device and stream. CPU/meta/non-`uint8` inputs retain Torch paths; valid empty tensors and odd-packing checks are preserved. Standalone fake-CUDA execution is unsupported. Default Blackwell values and scale layouts are unchanged.

## Performance

[Upstream versus this change](https://github.com/triton-lang/triton/compare/5f1539790306a978b8612e268da38facb471fff1...29b130bafe726009befc3111426de01b6aab098b), logical shape `[16,4096,4096]` (128 MiB packed data), H100 RHS MMA v3 and GB300 shuffled tiles `128×256`. Matched Torch 2.10.0+cu130 / [official Triton](https://github.com/triton-lang/triton/actions/runs/32115738800) runtimes; four balanced process pairs, 25 synchronized warm calls each. Peak allocation includes output and excludes existing input; it is not reserved VRAM.
