## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
`relu2` is `torch.square(F.relu(x))`, which runs two elementwise passes and so reads and writes the activation twice. Models with a large relu2 MLP spend a measurable slice of the forward on that extra round trip.

This adds a Triton kernel that does both in one pass, dispatched from `relu2()` when the input is a contiguous CUDA tensor of a supported dtype and falling back to the eager form otherwise. The squaring still happens in fp32 before the store, so results are bit-identical. `TRTLLM_FUSED_RELU2=0` falls back.
