## Summary

Makes the KVCM2 host tier **allocate progressively**: the address range is
reserved up front, a worker thread commits it in the background, and allocation
blocks only on the chunk it actually needs. Serving starts as soon as the first
chunk is resident rather than after the whole tier is.

The tier is populated by faulting pages in through the kernel and handing them
to the driver with `cuMemHostRegister`, rather than allocating them inside the
driver with `cuMemCreate`. That choice is the subject of most of this
description, because it is a deliberate trade rather than a free win.

## Why progressive

A host tier is sized from host memory, so it is routinely hundreds of GiB.
Making all of it resident before the first request is served is time the process
spends doing nothing useful, and it scales with the tier, so the larger the
configured cache the worse the startup.

Committing incrementally needs a base address that does not move while the tier
grows, and a way to make more memory resident without touching what is already
there. The range is reserved once at the tier's `max_quota` and committed as the
