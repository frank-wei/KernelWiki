## Description

The single-pass fused MLA A-projection GEMM (`dsv3_fused_a_gemm_op` /
`fused_a_gemm_kernel` under `dsv3MinLatencyKernels`) was hardcoded to the
DeepSeek-V3 A-projection shape (`hd_in=7168, hd_out=2112`). The GLM MoE DSA
model (`GlmMoeDsaForCausalLM`) has an MLA A-projection `kv_a_proj_with_mqa`
of shape `hd_in=6144, hd_out=2624`, which missed the exact-shape dispatch
gate and fell back to a cuBLAS split-K GEMM plus a separate split-K reduce.

This PR enables the fused single-pass kernel for the GLM shape.

### Why enabling the existing kernel is not enough

The kernel parallelizes only over output rows, so its CTA count is
`gemm_m / tile_m`. At the existing `tile_m=16`, the GLM shape gives
`2624 / 16 = 164` CTAs, which overflows a single wave on any GPU with fewer
than 164 SMs and spills into a second, nearly-empty wave (wave
quantization) — so simply enabling the existing kernel for the GLM shape
yields no speedup. Using `tile_m=32` halves the CTA count to
`2624 / 32 = 82`, restoring a single wave.

`m_iter_cnt = (tile_m + 15) / 16` (previously `static_assert(m_iter_cnt == 1)`).
