## Description

### Why the numerical error occurs

One kernel processes several query positions together. They share token tiles, but each position has its own recent-token window. For a small example, use a window of 3 tokens and tiles of 4 tokens:

- Tile A contains tokens `0, 1, 2, 3`.
- Tile B contains tokens `4, 5, 6` (the final tile is partially filled).

| Query position | Tokens it can attend to | Usable tokens in tile A | Usable tokens in tile B |
|---|---|---|---|
| 5 | `3, 4, 5` | `3` | `4, 5` |
| 6 | `4, 5, 6` | **None** | `4, 5, 6` |

Tile A is needed for position 5, but all its tokens are too old for position 6. The tile contains data; that particular row has no valid attention scores.

For that empty row, the old maximum behaves like this:

```python
m = -100000  # Initial placeholder, not an actual attention score.
for score in []:  # No valid scores for position 6 in tile A.
    m = max(m, score)
# m is still -100000.
```

Softmax uses `exp(score - m)`. If the block responsible for adding the sink has such an empty row, an example sink score of `2` gives

$$
\text{sink weight} = e^{2 - (-100000)} = e^{100002},
$$

which overflows to infinity in the kernel. Rescali
