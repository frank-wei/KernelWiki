## Description

Fixes https://nvbugs/6641268 and addresses the same root cause reported in https://nvbugs/6668773.

Persistent paged-context FMHA consumes complete physical V-cache pages. When the final page is only partially filled, unused V rows can retain stale or NaN values, which may propagate through masked `0 * NaN` operations during BMM2.

Zero the unused suffix of the final paged V-cache block from the unique writer of the last valid context token. The change covers both QKV preprocessing implementations and is limited to non-generation, unquantized paged KV caches.

This PR also removes the SM103 correctness fallback added by #18354 and removes `test_flashinfer_context_fallback_scope`, re-enabling `FlashInferTrtllmGenFmha` on SM103 now that the producer establishes the required V-tail invariant.

The independent #18196 small-BF16 performance fallback remains. The affected three-context BF16 cases therefore still choose fallback under normal registry selection; the direct validation below bypasses only that support-time performance predicate while retaining actual SM103 and restoring the real three-context metadata before preprocessing and FMHA launch.
