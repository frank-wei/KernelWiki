## Description

Ragged verification allows requests in one generation step to verify different numbers of draft tokens. This PR adds the sparse-attention kernel and metadata contracts needed to preserve request ownership and causal KV boundaries for that layout, while retaining the existing uniform path.

- Extend the compressor with optional per-request appended-token counts and Indexer Top-K with optional per-query-row KV extents.
- Present ragged generation queries as token-major attention rows, without changing the request-major metadata used by other consumers.
- Keep context and generation offsets separate, and supply true request prefixes to fused Q/RoPE.
- Allocate persistent ragged buffers only when the feature is enabled; reuse caller-owned workspaces and stable CUDA-graph metadata storage.
- Validate layout contracts at initialization and lifecycle boundaries.
