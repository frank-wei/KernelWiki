## Description

### Problem

Public installations currently use PyTorch 2.13.0 and Triton 3.7.1. Moving to PyTorch 2.14.0 and Triton 3.8.0 requires updating the dependency constraints and vendored kernels together while retaining compatibility with the NGC 26.08 PyTorch alpha build. Triton 3.8 also requires an explicit microblock size when MXFP4 weight scales are supplied to matmul.

### Solution

- Upgrade public PyTorch to 2.14.0, pin Triton to 3.8.0 and NCCL to 2.30.7, and keep the NGC PyTorch alpha admissible. Synchronize installation scripts, package-sanity checks, documentation, security-scanning constraints, and Triton attribution.
- Re-vendor `triton_kernels` from upstream v3.8.0 and set `b_microblock_size=32` in the five MXFP4 matmul configurations used by Triton linear, fused MoE, and AutoDeploy.
- Require CUDA 13.0 or newer, using the CUDA 13.x major version currently covered by TRT-LLM CI as the minimum.
- Harden dependency patch validation: apply forward, discard reject files, then require a reverse dry-run with `--force` so the check cannot switch direction and accept an unapplied patch.
