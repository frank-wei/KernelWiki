## Description

**Problem:** The GLM-5.3-Flash indexer scores pools with `kpool_score`, which launches one program per 64 pools of the block-table capacity (`max_seq_len / index_kpool` columns). A context row can only see `kv_len // index_kpool` of them. Programs beyond every row's bound skip the dot product but still write the FP32 minimum as a placeholder. With `max_seq_len` 131072, a 13K-token prefill launches 426K programs per sparse-attention layer, and about 90% of them only write 1.6 GB of placeholder scores.

**Fix:**
- `Glm5NextSparseAttention.forward_prefill` computes the batch's largest visible length from its host lists (no device sync) and passes it as `max_kv_len`. `kpool_score` then limits its grid to pools that at least one row can see: 44K programs and 0.18 GB written for the same 13K prefill. Columns past the bound are left unwritten. The pool top-k already scans only each row's `kv_len // index_kpool` columns, and the docstrings state that contract. Decode and MTP verification are unchanged and keep the fixed CUDA-graph grid.
