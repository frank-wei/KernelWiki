## Description

On the absorbed MLA context path with an FP8 KV cache (DeepSeek-V3 / GLM 5 family), the attention kernel takes an FP8 Q, so the BF16 `[tokens, heads, kv_lora + rope]` Q produced by the absorb bmm + RoPE is re-read and re-written by a separate `quantizeCopyInputToFp8` pass. On a 16k-token GLM 5.2 prefill (DEP4, GB300) that pass alone is 23.5 ms of an 889 ms step (1.8 GB moved per layer) and is absent from the analytical model; it is purely data movement.

This PR removes the pass on the context path by producing the FP8 Q directly:
- `cute_dsl_bf16_bmm_fp8out_blackwell`: a batched BF16 GEMM (per-head `q_nope @ k_b_proj_trans`) whose epilogue writes `float8_e4m3fn` into a caller-provided strided output — the `[..., :kv_lora]` slice of the final FP8 Q buffer. Built on the existing Blackwell persistent dense GEMM (new `wrapper_strided_c` that accepts an arbitrary C stride so the output can be a slice); autotuned like the other CuTe-DSL runners.
