# [TRTLLM-12214][perf] DeepGemmFusedMoE: skip redundant data expand via fused expand+quant Triton kernel

## Summary

The pre-GEMM pipeline in `DeepGemmFusedMoE` was:

```
moe_permute_op  (writes expanded buffer: ~3.5 MB at bs=32 × topk=8 × hidden=7168 × bf16)
    └── expandInputRowsKernel
  → _masked_index_copy_group_quant_fp8  (reads expanded buffer, writes FP8 + scales)
```

The expanded buffer is a `topk`-x materialization of the source activations that is written by the C++ `expandInputRowsKernel` and re-read one step later by the quant kernel. **Both reads and writes go through HBM.**

This PR:

1. **Adds a Triton kernel `fused_expand_group_quant_fp8`** that re-derives the source row analytically from the permutation map
   ```
   source_row = perm_to_unperm[i] % num_source_tokens
   ```
