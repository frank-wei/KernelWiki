## Description

Two small VisualGen fixes surfaced during Rubin (GR100, sm_107) bring-up, split
out of #17670 (ticket TRTLLM-14645):

- Allow `sm_107a` in the CuTe DSL FMHA arch allow-list (`SUPPORTED_GPU_ARCHS` in
  `attention_backend/cute_dsl/fmha.py`). The kernel already handles SM10x SKUs,
  so this just un-gates it for Rubin.
- Fail fast on an unsupported SAGE attention SM. `AttentionConfig` validation now
  raises a clear error when an int8 Q/K SAGE recipe is requested on a non-sm_100
  SM (no compiled trtllm-gen SAGE FMHA cubin), instead of silently falling back to
  an unfused MHA path that requests an unbounded workspace and OOMs.

## Test Coverage

Config-validation only for the SAGE guard (raises `ValueError` at
`AttentionConfig` construction on a non-sm_100 SM with an int8 Q/K SAGE recipe);
the sm_107a change is a one-line allow-list extension exercised by the existing
CuTe DSL FMHA path on Rubin.
