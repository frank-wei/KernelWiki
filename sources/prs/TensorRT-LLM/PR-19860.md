## Description

I found this issue on personal run and it's not a NVBug. This PR is related to #19501

The Triton GDN recurrent kernels normalize Q/K as `x / (sqrt(sum(x*x)) + eps)`, while prefill uses `x / sqrt(sum(x*x) + eps)`. These formulas can produce substantially different results for small Q/K norms, introducing a numerical mismatch between prefill and decode.

This change moves epsilon inside the square root in the fused-gating, recurrent, and cached-replay kernels, and updates the existing replay test reference accordingly. After change, it aligns the Triton kernels with the other decode paths rather than introducing a new convention.
