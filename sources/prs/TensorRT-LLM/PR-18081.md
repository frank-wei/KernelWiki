## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
in_proj emits token-major and the SSD consumes token-major, so the two transposes around the prefill conv only existed to satisfy the conv kernel's channel-major layout. This lets the CUDA conv read a channel-last `x` and write a caller-supplied `out`, and hands it a strided view of the projection instead. The transposes, not the convolution, were the bulk of that block.

`out` must not alias `x` -- each chunk reads a halo the previous one wrote, so the dispatcher rejects that case.

Outputs stay within one bf16 ulp of the channel-major path and conv_states updates are bit-identical, checked on mixed batches with pad slots, 1-token sequences, and sequences shorter than the conv state. `TRTLLM_MAMBA_TOKEN_MAJOR_CONV=0` restores the old path.
