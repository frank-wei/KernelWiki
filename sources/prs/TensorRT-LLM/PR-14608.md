## Summary

Adds **`MegaMoECuteDsl`**, a new NVFP4 MoE backend (SM100 / SM103) that wraps the fused MegaMoE CuteDSL kernel `Sm100MegaMoEKernel` — dispatch + FC1 + activation + FC2 + combine fused into a single kernel.

The kernel is imported from https://gitlab-master.nvidia.com/bangyus/cutedsl_megamoe/-/merge_requests/8 into `tensorrt_llm/_torch/cute_dsl_kernels/mega_moe_nvfp4/` (lazy-loaded, so non-SM100 / non-cu13 environments still import the backend for capability probing).

## Changes

- **Backend** `mega_moe/mega_moe_cute_dsl.py` — `ConfigurableMoE`-compatible, `FUSED_COMM` scheduler, EP-only; one unified path for single- and multi-rank (only the buffer source branches on `ep_size`).
- **Custom op + runner** `custom_ops/cute_dsl_megamoe_custom_op.py` — standard CuteDSL TunableRunner / torch-op pattern; multi-rank symmetric memory via `torch.distributed._symmetric_memory`.
- **Quant method** `NVFP4MegaMoECuteDslMethod` — NVFP4 weight lifecycle (gate/up interleave + `to_blocked` swizzle + per-expert `fc31_alpha` / `fc2_alpha` / `fc1_norm_const`), EPLB-aware.
- **Wiring** — factory (`create_moe.py`), `FusedCommMoEScheduler` zero-token delegation, MoE developer guide, unit tests
