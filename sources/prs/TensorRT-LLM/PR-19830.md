## Description

In `block_reduce_sum2_for` and `block_reduce_sum2_active_for`
(`cpp/tensorrt_llm/kernels/kdaDecode/kdaDecodeLegacy.cu`, used by `kda_decode_fusion_compact_heads_kernel`):
- the lanes of warp 0 read the per-warp partials `scratch[lane]` / `scratch[kReduceWarps + lane]` and reduce them with
  shuffles;
- lane 0 then stores the block totals into `scratch[0]` and `scratch[1]`, which lane 1 read.

Shuffles do not order shared memory, so lane 0's stores and lane 1's reads were unordered. compute-sanitizer racecheck
reports 32 warnings per run. Lane 0's totals depend on lane 1's loaded value, so results were not affected.
`__syncwarp()` before the stores makes the order explicit.

## Test Coverage

No new test: the outputs do not change, and the order is a racecheck finding.
- **Racecheck:** on extension builds of the original and the fixed .cu it goes from 3 records to 0.
- **Bits:** 0 of 99 runs differ.
- **Existing tests:** `tests/unittest/_torch/modules/kimi_kda/test_kda_decode_op.py` covers the kernel's outputs.
