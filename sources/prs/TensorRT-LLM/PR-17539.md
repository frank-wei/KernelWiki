## Description

vLLM keeps three `tl.debug_barrier()` calls live in its copy of these kernels. Here all three have been commented out since #10754.

Both kernels read the `conv_state` history taps with a 1-D `[BLOCK_N]` layout, then overwrite those same cells from a 2-D `[NP2_STATELEN, BLOCK_N]` tile. The two layouts map a feature to different threads, so nothing orders the overwrite against the read. Today the ordering comes from a layout-conversion barrier the compiler happens to emit at the block shapes the launchers hard-code, so the shipped path is correct only by accident.

This restores the three barriers.
