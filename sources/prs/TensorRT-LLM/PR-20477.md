## Description

`examples/test_gpt.py::test_gpt_oss_20b_lora_torch[gpt-oss-20b-lora-adapter_NIM_r8-gpt-oss-20b]` fails on H100 (L0_PostMerge 3021, DGX_H100-PyTorch-Post-Merge-1) with `CUDA error: an illegal memory access was encountered` at the first CUDA-graph LoRA decode step.

**Root cause.** `loraGroupGEMMParamFillRowReorderFusionKernel` runs with at least 256 threads per block. In the `OUT_SIZES_INDEX` block, every thread reads `module_out_sizes[module_id]`, where `module_id = threadIdx.x / max_lora_count`. That tensor has only `MODULE_COUNT` entries (3 int32 = 12 bytes for fused QKV), so threads past `max_lora_count * MODULE_COUNT` read out of bounds. `BlockStore3` drops their rows, so the result was never wrong, but the read faults whenever the allocation sits at the end of mapped memory. A GPU coredump names this kernel and block (Warp MMU Fault on the `module_out_sizes` load).
