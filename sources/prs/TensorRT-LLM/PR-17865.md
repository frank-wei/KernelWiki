## Summary

- Bring up the nvidia/Kimi-K3-NVFP4 checkpoint in the PyTorch backend with two supported SiTU MoE paths: CUTLASS and MegaMoE CuteDSL.
- Add SiTU gated activation support to the shared Python activation contract and the CUTLASS MoE implementation.
- Handle the Kimi K3 NVFP4 checkpoint layout, quantization metadata, lazy loading, and per-expert streaming from prefixed safetensors shards.
- Preserve an explicitly selected CUTLASS backend in the Kimi K3 production runtime; CUTLASS is supported rather than falling back to another backend.
- Add MegaMoE CuteDSL SiTU kernel support and focused regression coverage.

## CUTLASS support

- Propagate SiTU alpha/beta through the CUTLASS runner, tactic cache key, validation, and gated activation computation.
- Support CUTLASS SiTU for BF16 and streamed NVFP4 experts, including dynamic activation scaling and the Kimi gate/up projection geometry.
- Preserve SiTU through the THOP/C++ binding path and expose CUTLASS in the Kimi K3 routed-expert backend allowlist.
- Add regression coverage that verifies an explicit CUTLASS selection remains CUTLASS and that an unsupported backend is rejected.
