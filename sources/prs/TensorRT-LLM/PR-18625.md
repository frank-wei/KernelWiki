## Description

Self-sampling GVR V2 decode top-k (CuTe DSL, added in #17821 and made the hint-free production default in #18410) could **drop `+inf` from the top-k** in both register-bracket families:

- `reg` / retained legacy `regimg`: original DKG issue 58 reproduction.
- `reg_clus`: follow-up strict reproduction at `B=4, N=32768, K=1024`.

The failure is independent of hint quality, so it is a selection bug rather than a hint-quality issue.

### Root cause

An in-window `+inf` makes the sampled bracket maximum `+inf`. Then `GMAX - Tv = +inf` and `SC = rcp(+inf) = 0`, collapsing values into a finite histogram bin. The existing sentinel did not rescue this because `SENT_HI - SENT_LO = 6e38` also overflows to `+inf`.

- In `reg` / `regimg`, the collapsed histogram could take the whole-bin emit, so #18501's count-crossing escape did not fire.
- In `reg_clus`, the collapsed histogram could set `whole = 1`, which bypassed the existing exact whole-row fallback.

### Fix

- `GvrTopkRegKernel`: reject an infinite bracket width and force the existing full-row key-space escape when the bracket is invalid.
- `GvrRegClusKernel`: apply the same infinite-width guard, clear `whole`, and mark
