## Description

Optimize the Kimi K3 KDA prefill convolution and cache data flow on Blackwell:

- reuse GDN's packed variable-length causal convolution for Q/K/V and update
  the live convolution pool directly;
- consume packed channel-major convolution output directly, fuse the
  post-convolution transpose with Q/K L2 normalization, and pass normalized
  Q/K to both the optimized and FLA recurrence paths;
- store only the committed `W - 1` convolution window in the live cache pool
  and synchronize speculative replay caches from that layout;
- reuse fused QKVG projections without an intermediate Q/K/V concatenation;
- update cache-manager sizing, prefix/continuation handling, disaggregated
  transfer geometry, and packed-cache parity coverage for the `W - 1` layout;
- add `test_kda_decode_op.py`, which also covers the shared convolution-cache
  frontend, to the B200 test database.

KDA single-token decode ABI and direct-pool optimizations were split into draft
PR #18251. This PR is now prefill/cache-layout only.

This is an internal data-layout optimization. It does not add a user-facing API
or an opt-in environment switch.
