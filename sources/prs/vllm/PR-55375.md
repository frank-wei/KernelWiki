## Purpose

Fix corrupted and repetitive output from Qwen3.8-Flash-Next when multiple prefill requests are processed together by the fused PLE short-convolution kernels.

The failure typically appears as repeated tokens such as `Theductductduct...`. It reproduces on the device-resident PLE path and does not depend on PLE CPU offload.

This change keeps the fused kernels enabled. It does not add a PyTorch fallback, disable CUDA graphs, or revert the PLE fusion.

## Root Cause

In Mamba align-cache mode, pure-prefill state indices are obtained from column zero of the Mamba block table:

```python
state_indices_tensor_p = state_indices_tensor_p[:, 0]
```

The result is a **one-dimensional, non-contiguous tensor**. With MTP=3 its logical elements have a stride of four because each block-table row contains the base state plus three speculative states.

The fused PLE convolution and writeback kernels loaded request `r` with `state_idx_ptr + r`, implicitly assuming a contiguous tensor.
