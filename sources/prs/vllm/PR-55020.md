## Purpose

Two latency cuts to the fused q/kv RMSNorm triton kernel (used by the Kimi-K3 and DeepSeek-V4 attention front-ends), which runs PDL-launched behind the qkv-a projection GEMM:

1. The gamma load does not depend on the producer's output, so it now issues **before** `gdc_wait`: the weights stream in while the producing GEMM finishes, leaving one dependent global round trip (the activation row) after the wait.
2. `num_warps=8` for rows >= 2048 wide, so each thread does a single vectorized 128-bit access instead of a serial per-thread chain at the default 4 warps.

Outputs are unchanged (same math, same reduction order).

Not duplicating open work: searched open PRs touching this kernel; #52215 fuses the ROCm module-level norm pair and does not change this kernel's wait/load structure.

## Test Plan

- `pytest tests/kernels/core/test_fused_q_kv_rmsnorm.py` on B300 (SM103), run on a development tree containing this change.
- Kernel timing from Nsight Systems traces of Kimi-K3 TP8 serving (8192-in/1024-out, concurrency 1, fp8 KV cache).

## Test Result

- `13 passed`.
- Kernel mean 4.02 -> 3.55 us (~-12%) across 24 full-attention layers x 145 decode steps.
