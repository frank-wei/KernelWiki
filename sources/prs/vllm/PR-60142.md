## Overview

Fixes #59868. On GPUs below SM89 (the report uses 4 × RTX 3090), Qwen4Exp with an FP8 E4M3FN PLE table and `--engram-config '{"cpu_offload": true}'` crashes in `profile_run`. The crash is a Triton `CompilationError` from `_lookup_ple_embedding_from_pinned_kernel`. This PR makes that kernel copy rows as raw bytes, so the FP8 type never enters its signature.

## Claims

- `_lookup_ple_embedding_from_pinned_kernel` now compiles and runs on sm_86 with an FP8 E4M3FN table, and it copies FP8 rows bit-exactly.
- On an A40, three existing FP8 pinned-lookup tests in `tests/models/qwen4_exp/test_ple.py` failed before this change. They now pass.
- BF16 lookups are unchanged: same bits, same speed.
- The module still imports when Triton is not installed.

## Validation

Hardware: a machine with 4 × NVIDIA A40 (sm_86). The reproducer uses one GPU. Software: vLLM commit `92044241a` (`0.30.1rc1.dev648+g92044241a`), with and without this PR, PyTorch 2.13.0+cu130, Triton 3.7.1, Python 3.12.12.
