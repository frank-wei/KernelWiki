## Purpose

Harden the DeepSeek V3.2 fused Triton kernels against large single-iteration
token counts.

`fused_norm_rope` and the Triton fallback for `fused_q` placed `num_tokens` on
CUDA grid-y. A launch with 65,536 tokens therefore exceeded grid-y's 65,535
block limit and failed with `Triton Error [CUDA]: invalid argument`.

This change swaps the token and task grid axes so the unbounded token count is
on grid-x. Token indices are promoted to int64 for safe address arithmetic. It
does not change the kernel math or the CuTeDSL `fused_q` path.

This does not duplicate an existing PR. Searches for the kernel names, DeepSeek
V3.2 grid limits, and the 65,535/65,536 boundary found no matching open fix.
PRs #52046 and #51915 touch the same kernel file but retain the affected launch
grids.

OpenAI Codex was used.
