## Purpose

With `VLLM_BATCH_INVARIANT=1` the LoRA shrink kernel runs with `SPLIT_K=1`, because split-K normally reduces with float atomics. This PR makes the batch-invariant shrink keep K parallelism without atomics: `_lora_shrink_kernel` stores unscaled FP32 partials for 8 fixed K splits (BLOCK_K=256 for every M) and a small reducer adds them in a fixed order and applies scaling once.

This PR:
- adds a `STORE_PARTIALS` branch to `do_shrink_kernel` / `_lora_shrink_kernel` and a fixed-order reducer, used whenever `VLLM_BATCH_INVARIANT=1` (no new env var);
- allocates the FP32 partials per call with `torch.empty`, so each CUDA graph keeps its scratch in its own pool;
- leaves the non-batch-invariant path unchanged; the split-K path does not use PDL.

Batch-invariant LoRA outputs are still invariant across batch composition, but they change relative to the previous `SPLIT_K=1` path because the reduction order differs.

Not a duplicate: #50278 forces `split_k=1` on the default (non-BI) path; #58533 changes PDL overlap on the dual-stream path.
