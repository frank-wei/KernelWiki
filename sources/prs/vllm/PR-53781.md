## Summary

HiSparse adds a host-resident tier beneath vLLM's normal GPU KV cache for sparse-MLA decode. Unlike the original always-host-resident design in #46326, this implementation keeps as much KV as possible in the normal device cache and spills pages to pinned host memory only when GPU capacity must be reclaimed.

Supersedes #46326.

## Design overview

```text
resident GPU pages
        |
        | spill under pressure
        v
  pinned host pool ---- selected top-k misses ----> per-request GPU hot buffer
        ^                                                     |
        |                                                     v
        +---------------- prefix reuse ---------------- sparse attention
```

The active indexer cache remains device-resident and produces the logical top-k positions needed by sparse attention. A fused CUDA resolver maps each selected position through three possible locations:

1. a normal resident GPU page;
2. an existing row in the request's GPU hot buffer;
3. the pinned host pool.
