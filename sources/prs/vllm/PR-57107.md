## Context
Triton keys its compilation cache on whether each int scalar is 1 and whether it is 16-divisible, so the number of tokens/reqs args re-key as the batch size changes at runtime, causing stalls.

## Summary
Fixed by disabling specialization on `num_reqs`/`num_tokens` for the acceptance estimator kernels.

## Test plan
**Correctness**
`.venv/bin/python -m pytest tests/v1/spec_decode/test_acceptance_estimator.py -v` → 7 passed (NVIDIA GB200)

**Compiled-variant count**
Swept num_reqs/num_tokens over 1, 2, 3, 4, 7, 8, 9, 15, 16, 17, 23, 31, 32, 33, 47, 48, 63, 64, 96, 127, 128, 129, 192, 255, 256
| kernel | before | after |
| --- | ---: | ---: |
| `_accumulate_kernel` | 14 | 1 |
| `_local_max_sumexp_kernel` | 3 | 1 |
| `_predict_kernel` | 3 | 1 |

All collapse to a single variant.

**Lint**
`pre-commit run --files vllm/v1/worker/gpu/spec_decode/acceptance_estimator.py` → all applicable hooks passed, including mypy.

AI assistance was used for this change (Claude Code), and I have reviewed every changed line.
