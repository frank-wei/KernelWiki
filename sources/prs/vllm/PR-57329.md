## Purpose

Bring Kimi-K3's internal prefill checkpoints (#52789, #53614) to Mamba2 (NemotronH, Granite-4.0-H, Falcon-H1, Zamba2).

In `mamba_cache_mode="align"`, the scheduler currently splits a prefill so one step ends on a block boundary, which costs an extra forward pass. With this PR, the whole prompt runs in one step and the boundary state is read out of the SSD scan's per-chunk states.

## Changes

- `_compute_chunk_metadata` splits a checkpointing request at the checkpoint, so a logical chunk ends exactly there, and returns that chunk's index.
- Checkpoint positions come from the existing `MambaPrefillCheckpointBuilder`, so the scheduler, `MambaManager` and backends agree on which rows checkpoint. The only addition is an optional host copy of the offsets, which avoids a GPU→CPU sync when laying out chunks.
