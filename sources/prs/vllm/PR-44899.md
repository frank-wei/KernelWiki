## Purpose
This PR optimizes the DeepSeek-V4 sparse **decode** attention path on ROCm (`_sparse_attn_decode_ragged_kernel`), which is GPU-occupancy-bound at small batch sizes: DSV4's 16 TP-local heads collapse to a single head-block, so the whole decode runs on just `batch` workgroups and leaves most of a 256-CU gfx950 device idle (latency flat at ~277us across batch 4 to 128). The fix rewrites it as a flash-decode split-K pipeline with a wave-aware split-count heuristic, cutting decode attention latency by up to ~8x at low batch. The current split-K path is gfx950-only; other architectures keep the original kernel to prevent any potential regression before verification.
## Test Result
### Single kernel Unit test:
Measured on gfx950 (MI355, 256 CUs), realistic shapes (16 heads,
SWA<=128, topk<=1024, block_size=64), CUDA-graph GPU time

  batch   8:  ~278us -> ~33us
  batch  16:  ~278us -> ~35us
  batch  32:  ~281us -> ~46us

  batch 128:  ~286us -> ~113us
  batch 160:  ~290us -> ~158us
  batch 320:  ~560us -> ~278us
