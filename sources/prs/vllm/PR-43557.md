## Purpose

Fix the E8M0 scale computation in the MXFP4 (W4A4) MOE CUTLASS kernel, which
currently produces severely incorrect quantization results.

Related PR: #37463

## Root Cause

The original code computes the E8M0 scale factor via:

```c++
// Old (buggy):
float SFValue = vecMax * reciprocal_approximate_ftz(6.0f);  // vecMax / 6.0
uint32_t tmp = reinterpret_cast<uint32_t&>(SFValue) >> 23;
fp8SFVal = tmp & 0xff;  // scale_exp = biased_exponent(vecMax / 6.0)
```

This is **mathematically wrong** because:

floor(log2(a / b)) != floor(log2(a)) - floor(log2(b))

Dividing by 6.0 *before* extracting the exponent shifts the mantissa boundary,
causing the resulting exponent to be 1 too small for a large fraction of inputs.
When the scale is too small, `vecMax / scale` far exceeds 6.0 (the E2M1 max),
and the block-max value saturates -- destroying information.

| vecMax | Old: `biased_exp(vecMax/6)` | Correct: `biased_exp(vecMax)-2` | Ratio (old) | Ratio (fixed) |
|--------|-------|-------|------|------|
| 2.7 | 125 (scale=0.25) | 126 (scale=0.5) | 10.8  | 5.4 |
| 5.5 | 126 (scale=0.5) | 127 (scale=1.0) | 11.0  | 5.5 |
| 1.2 | 124 (scale=0.125) | 125 (scale=0.25) | 9.6  | 4.8  |
