## Purpose
This PR adds a two-stage Triton implementation to the DeepSeek-V4 compressor for the prefill path in head_dim=512, cr>=128 to improve TTFT.

On upstream ROCm, the single pass compressor-norm-rope-cache fusion is dispatched one workgroup per token. In HCA where compress ratio is 128, only workgroups that live on the CR boundary (positions % 128 == 0) execute on 128x512 grids, and the others early exit. During perfill, the number of boundaries per step is `num_prefill_tokens / cr`, and for a 8192-token chunk, that leaves 8192/128=64 CUs in action, leaving most of the CUs unoccupied (e.g. 256 total CUs on MI355).

Following the strategy in CuTeDSL CUDA kernel, this PR breaks this path into two stages/kernels:
- Compress: this is the more compute-demanding stage. Instead of compressing the 128 rows for all heads in one single program, split workloads along the head dimension so that each program computes only a `head_dim / num_splits` slice of the output, and more programs can be spawned to fill the CUs.
