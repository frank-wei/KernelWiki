## Purpose

Retune one kernel's launch parameters for sm_90 (H100/H200/H20): `_qsa_sparse_paged_gqa_splitk_kernel`, the Triton split-K kernel that runs the sparse attention of Qwen3.8-Flash-Next's QSA layers over the 2048 selected tokens per query. Its tile width, split count and warps per CTA come from `_select_config()` in `vllm/models/qwen4_exp/nvidia/ops/qsa.py`, a table tuned on GB300 (#55557 added an sm_120 table beside it). Measured on H20, the GB300 entries are the wrong geometry in most decode regions, so this PR adds `_select_sm90_config()` in the same shape as the sm_120 helper. Besides that nothing else changes. Regions where the default entry is already fastest return `None` and keep it.

Each row below is one region of `_select_config`'s key, `base_programs = query rows × kv_heads per rank` (at TP8 with MTP3 that is 4 × concurrency, so the second column shows which serving points land in the region). "GB300 entry" is what runs today, "sm_90 entry" what this PR selects on H100/H200/H20; a tuple is (BLOCK_N, target_splits, num_warps).
