## Purpose

On a P/D decode instance, Model Runner V2 verifies draft slots its drafter never proposed. After the remote KV load the request resumes with one token left, and the scheduler pads that step with `k` placeholder drafts of `-1` (#45237, #55126). MRV2 fills those slots from `req_states.draft_tokens`, which are still zeros, so the rejection sampler verifies `k` real token-0 drafts against a stale draft distribution. With probabilistic drafting at T > 0 and block verification all `k` are accepted: on main, 71/80 MT-Bench responses through 1P1D start with at least 8 NUL tokens (`MiniMaxAI/MiniMax-M3-MXFP8` + `nvidia/MiniMax-M3-DSpark`, `k=8`). MRV1 is not affected (#47029).

Fix: `RejectionSampler` gathers the verified tokens and positions with a Triton kernel that sets the draft rows of any step starting within the prefill (first position < `prefill_len`) back to `-1`, which the rejection kernels already reject. Drafts are only proposed after sampling past the prefill, so these rows are always placeholders. No new request state, and `input_ids` is unchanged.
