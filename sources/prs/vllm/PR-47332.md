### Purpose

Fixes https://github.com/vllm-project/vllm/issues/47300

Gemma4 vision models emit total gibberish on the FlashAttention-4 (CuTeDSL, SM90) backend when the context is long (>=~1k tokens past the sliding window) and contains at least one image. The Triton backend produces correct output on the same input.

Root cause — two bugs in `_make_mm_prefix_mask_mod` (`vllm/v1/attention/backends/flash_attn.py`):

- Missing sliding window constraint. The mask implemented `causal OR mm_prefix` instead of `(causal AND sliding_window) OR mm_prefix`. When `mask_mod` is present, `_resolve_causal_local_window` sets `causal=False, local=False`, which disables the kernel's built-in window enforcement — the `mask_mod` becomes the sole element-level mask. Since it lacked the sliding window term, non-image tokens attended to the full causal context instead of the configured window (1024 tokens for Gemma4), destroying attention distributions on any sequence longer than the window.
