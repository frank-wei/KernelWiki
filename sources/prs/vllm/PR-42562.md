## Motivation

 vLLM already ships a LL router GEMM compatible with DeepSeek-V3/V4-Pro requirements, but it is locked to specific shapes:

 ```python
  DSV3_SUPPORTED_NUM_EXPERTS = [256, 384]
  DSV3_SUPPORTED_HIDDEN_SIZES = [7168]
```

Models that fall outside these dimensions (e.g. DeepSeek-V4-Flash with K=14400, N=256) silently fall back to cuBLAS, leaving performance on the table.

This PR adds a generic cuteDSL router GEMM that is competitive with `dsv3_router_gemm` on its home turf while being flexible enough to handle arbitrary (K, N) shapes without code changes.

This is not only interesting from a performance perspective, but also a new feature for future models.

##  Approach

Dot-product kernel (M≤4): One CTA per expert, fully-unrolled `constexpr` K-loop with 128-bit vectorized loads. Same algorithmic idea as `dsv3_router_gemm`. However, this approach serializes M; each additional token adds a full K-reduction, so latency scales linearly. This is not a problem for K=7168, dotprod is still faster than regular GEMM for M<=16, but it represents an issue for K=14400, and becomes uncompetitive beyond M=4.
