## Purpose


1. Added a new NGram GPU speculator.
The main feature is a new implementation at: `vllm/v1/worker/gpu/spec_decode/ngram/speculator.py`, similiar to https://github.com/vllm-project/vllm/pull/29184.

2. Updated request state storage for NGram GPU.
`vllm/v1/worker/gpu/states.py`
`vllm/v1/worker/gpu/model_runner.py`
This changes how RequestState is initialized so that all_token_ids can stay densely resident on GPU instead of defaulting to UVA when ngram_gpu is active. As discussed in   #29184, the new n-gram speculator repeatedly scans active request token history, doing that from GPU-resident dense storage is much more appropriate than pulling through UVA-backed memory, this is a performance-oriented architectural change supporting the new feature.
The `model_runner.py` also injects req_states into speculators that need direct access to the persistent token store.

3. Added variable-length draft token plumbing
Several files were updated to support draft proposals where different requests may have different numbers of valid draft tokens:

`vllm/v1/worker/gpu/spec_decode/utils.py`
