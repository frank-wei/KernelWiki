## Purpose

The packed GDN decode kernel loads `b` in FP32 and computes `sigmoid(b)` in
FP32, but then rounds the result to the input dtype before converting it back to
FP32:

```python
beta_val = tl.sigmoid(b_val).to(b.dtype.element_ty).to(tl.float32)
```

For BF16 inputs, this perturbs every recurrent state update and the error
compounds over long decode sequences. The standard fused sigmoid decode path
and the fused prefill preparation path keep beta in FP32.

This affects long-context accuracy for models in the Qwen3.5 through Qwen3.8
families when they use the packed GDN decode path. Because the recurrent state
is reused at every decode step, the beta rounding error accumulates with context
length and can eventually degrade generation accuracy and stability.

This change removes the unnecessary dtype round-trip, updates the existing
packed-vs-reference test to use an FP32 beta, and adds a focused regression test
with BF16 activations and an FP32 recurrent state. On the regression input, the
old kernel produces `0.62109375` while the FP32 reference is `0.62245935`.

The fix was first validated downstream in
[flagos-ai/vllm-plugin-FL#385](https://github.com/flagos-ai/vllm-plugin
