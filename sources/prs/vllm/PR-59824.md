## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
**Requires #55504 and #56831.** Both are open, and this branch carries them as separate commits until they merge.
> - **#55504** "Preserve GDN recurrent state on zero-draft speculative decode steps". Without it, the 1-token-per-request varlen capture dummies record the non-spec KDA path, which trimmed verify batches then replay. This PR also contains the fix I'm proposing for #55504: a row is a spec-decode row only if it is no wider than k+1.
> - **#56831** "Synchronize adaptive DSpark decisions across TP ranks". Without it, rank-local confidences can choose different draft budgets or request boundaries on different TP ranks, which leaves the collectives mismatched and can hang. Kimi-K3 runs at TP8, and trimming happens on ~97% of steps at conc ≥ 8.

### Purpose

`speculative_config.enable_adaptive_verification` (#47808) trims each verify request to 1..k+1 tokens on the device, using the DSpark confidence head. #52988 enabled it for Kimi-K3 on NVIDIA only. On ROCm, Kimi-K3 is refused at engine start:

1. `KimiK3ROCmKDABackend` inherits GDN's `is_ssm()`, so `supports_device_cpu_query_lens_mismatch()` returns `False`.
2. The ROCm KDA builder is `UNIFORM_BATCH` and declares no varlen
