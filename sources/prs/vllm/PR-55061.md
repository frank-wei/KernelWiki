## Summary

`dequantize_and_gather_k_cache_cutedsl` launched `grid = (num_reqs, 1024)`. The SWA call gathers 128 rows per request and the compressed call ~1k rows, so most of the 32k CTAs did no work; measured effective bandwidth was 0.35–2.4 TB/s on GB200 (8 TB/s HBM). `grid.y` is now picked per call from the launch shape.

## Where this kernel is hot: batch-invariant (deterministic) serving

The kernel came in with vllm-project/vllm#42236, which profiled **prefill** — one request, thousands to 262k rows per launch. At that shape a fixed `grid.y = 1024` is close to optimal, and this PR changes nothing there (table below). The shape that is badly served by a fixed grid is **many requests × few rows each**, and that is exactly what batch-invariant DSv4 decode produces on every step.
