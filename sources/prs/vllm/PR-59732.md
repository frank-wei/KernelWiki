## Overview

On ROCm, the Qwen4Exp QSA layer's main-attention QK-norm, RoPE, gate split and K/V cache write now run inside the fused QSA prepare launch, as #57097 did for NVIDIA.

## Claims

- MI355X TP2 `amd/Qwen3.8-Flash-Next-Quark-MXFP4`: +0.9% to +2.9% output throughput, faster in all 8 measured cells (4 points × 2 repeats).
- Accuracy neutral: GSM8K 0.9638 → 0.9605 over 6 pairs, a −0.33 point paired difference within run-to-run noise (paired t = −1.8, 5 df).
- Kernel numerics no worse than the unfused AMD chain against an fp64 reference; the gate is bit-identical.

## Validation

**Unit tests** (gfx950): 24 passed, 8 skipped.

```bash
pytest -v -s tests/models/qwen4_exp/test_qsa_amd.py tests/models/qwen4_exp/test_qsa_prepare_amd.py
```

- `test_qsa_prepare_amd.py` (renamed from `test_qsa_pre_indexer_amd.py`): in all 8 bf16 configurations, the indexer outputs match as before, and the main attention matches the AMD layer's unfused chain (split, Gemma RMSNorm, the layer's `rotary_emb`, `reshape_and_cache_flash`): Q and the paged K/V cache within bf16 tolerance, including MRoPE; the gate bit for bit, in the caller's buffer. The 8 FP8 cases skip: the AMD QSA caches are bf16-only.
