## Summary

Unify the `fp8_ds_mla` cache scale contract used by FlashMLA on SM90 and
SM100. The physical 656-byte cache entry is unchanged: 512 FP8 NoPE values,
four FP32 scale fields (one per 128 values), and a 128-byte BF16 RoPE tail.
The value stored in each FP32 scale field is now always:

```text
2 ** ceil(log2(max(amax / 448, 1e-4)))
```

Power-of-two values survive both reader conversions exactly: SM90 converts
the scale to BF16, while SM100 converts it to E8M0. Arbitrary FP32 values can
therefore make the writer quantize with a different scale than the reader
uses. The `1e-4` lower bound matches the FlashMLA UE8M0 reference margin and
maps an all-zero tile to `2^-13` after rounding.

Apply the same rule to all `fp8_ds_mla` writers:

- the native CUDA cache writer;
- the fused DeepSeek-V3.2 Triton writer; and
- the Kimi K3 shared prefill/decode CUDA writer.

The tests enforce bit-compatible native, Triton, and Kimi output and exercise
the real native cache-writer-to-sparse-FlashMLA-reader path. The reader test
uses fixed-width, `-1`-padded indices so it runs with both SM90 FlashMLA V3.2
and SM100.

This is the existing PR for the cache-scale mismatch; no duplicate PR was
