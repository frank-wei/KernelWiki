## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Reorganize PP scheduling and broadcast of sampled tokens so that pipelining works properly for decode and (chunked) prefill.

Decode tokens for a given request are now scheduled every `pp_size` steps, the broadcast of sampled tokens from last stage to prior stages happens using a different stream and process group, so it can happen in parallel with consecutive stage p2p comms. For async scheduling we schedule `pp_size + 1` steps at a time.

Prefill chunks are pipelined in consecutive steps.

[This animation](https://github.com/user-attachments/files/28326807/async_pp_animation.html) shows the data flow between ranks for hidden states and broadcasted sample tokens for decode requests.

<img width="1159" height="865" alt="image" src="https://github.com/user-attachments/assets/a2b0bc26-5b09-4c6e-9c70-eb3e9e5af499" />


#### Benchmarks

  Model: MiniMax-M2.7 (FP8)
  Hardware: Single GB200 node, PP=4, TP=1, DP=1
  Server: vllm serve with `--compilation-config '{"mode":3,"pass_config":{"fuse_minimax_qk_norm":true}}'`, `--no-enable-prefix-caching`
  Client: vllm-bench, random dataset, `max_concurrency=128`, `--ignore-eos`
  Per config: 1 warmup batch + 3 timed runs (mean reported)
