## Purpose

`_fwd_kernel` in `triton_prefill_attention.py` walks every key block from 0 to `end_n` and masks out-of-window keys after loading them. The masking is correct, but the work is not skipped, so a sliding-window pass still costs O(seq_len^2).

For a query block covering `[start_m * BLOCK_M, (start_m + 1) * BLOCK_M)`, only keys in `[start - SLIDING_WINDOW_Q, end + SLIDING_WINDOW_K]` can survive the mask, so the loop is clamped to that range. Nothing else changes, and the non-windowed paths keep their current bounds.

## Test

`tests/kernels/attention/test_triton_prefill_attention.py`, 20 passed, so masked outputs are unchanged.

H100, bf16, 8 heads, head dim 64, window 64, non causal, mean of 20 iterations:

| tokens | before | after |
|--------|--------|-------|
| 512 | 0.078 ms | 0.074 ms |
| 1024 | 0.097 ms | 0.071 ms |
| 4096 | 0.349 ms | 0.080 ms |
| 16384 | 4.657 ms | 0.172 ms |

Before the change the cost grows quadratically with sequence length; after it grows with the window.

AI assistance was used for this change.
