## Purpose

`_expand_page_indices_kernel` in the AITER MLA backend is launched with a grid
of one program per request, and each program walks that request's tokens in a
serial loop:

```python
_expand_page_indices_kernel[(num_reqs,)](...)

    req_idx = tl.program_id(0)
    for i in tl.range(0, num_tokens, BLOCK_SIZE):
```

The parallelism is therefore entirely over the batch. That is fine at high
concurrency and degenerates at low concurrency: with `num_reqs == 1` a **single
workgroup** expands the whole sequence while the rest of the GPU idles. The
bug is invisible in the regime it was presumably tuned for.
