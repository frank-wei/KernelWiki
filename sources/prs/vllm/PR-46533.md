## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
The rejection sampler kernels gathered target/draft probabilities by the draft token id. For a placeholder draft id (-1, used for spec positions that must not be verified -- structured-output grammar-invalid drafts and decode-side padded drafts) this read can be out of bounds in the non-greedy path and could in theory spuriously accept the placeholder, emitting -1 as a real token.

Always reject a negative draft id, masking the prob gathers so they are never indexed by an invalid id, in both the V1 (rejection_sampler) and V2 (rejection_sampler_utils) kernels. The greedy path already rejected -1 via the argmax comparison; the synthetic-rate paths now also reject it.

Note this very rarely causes a problem in practice but I think could in rare cases.
<!-- upstream-excerpt-end -->
