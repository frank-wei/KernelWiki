## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Motivation: https://buildkite.com/vllm/ci/builds/76664/list?sid=019f3900-a887-45a4-bd39-f1e71a7beaee&tab=output

`Language Models Test (Extended Pooling)` failed in `test_openai_privacy_filter` while starting `openai/privacy-filter`. This model exposes the startup bug because it combines token-classification pooling, a GptOss/FusedMoE backbone, ROCm modular MoE workspace allocation, and a post-capture warmup shape larger than the graph-capture shape. The root cause is that graph capture locked the workspace after only the small capture-size MoE allocation, then the later sampler/pooler warmup needed the larger max-request MoE workspace. On ROCm V1 workers, this PR now runs the max-request model warmup before CUDA graph capture, so the workspace is sized before captured graphs take workspace pointers and before `lock_workspace()` freezes growth. The post-capture sampler/pooler warmup remains locked, preserving the no-growth invariant for serving. The PR also threads attention sinks through encoder-only Triton/ROCm prefill attention and aligns ROCm encoder-only sliding-window handling with the other backends for the privacy-filter HF comparison.
<!-- upstream-excerpt-end -->
