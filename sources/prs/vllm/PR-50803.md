## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
- Use explicit Triton FMA operations for the interleaved RoPE calculation before its BF16 materialization point.
- Preserve bit-exact FP8 assertions instead of widening the numerical tolerance around rounding ties.
- Run every FP8 compressor and indexer case on ROCm while skipping only the unsupported MXFP4 sparse-indexer cache parameters.
- Limit those MXFP4 cache cases to CUDA SM100, which is the only currently supported end-to-end consumer path.
- Document that ROCm's existing NVFP4 and MXFP4 linear or MoE emulation does not provide sparse-indexer cache support.
- Confirm that the explicit FMA introduces no measurable latency regression across small and large token counts.

PR #40860 left the common Triton RoPE expression with different contraction behavior from the HIP reference, and PR #41015 added MXFP4 cache cases backed by an NVIDIA-only conversion path. The resulting rounding mismatches and PTX compilation error appear in the [kernel step](https://buildkite.com/vllm/amd-ci/builds/11570/list?sid=019fc12a-ba66-44dc-9e75-3067065271dd&tab=output). This patch fixes the supported FP8 path and accurately gates the unsupported cache feature without reducing ROCm FP8 coverage.
<!-- upstream-excerpt-end -->
