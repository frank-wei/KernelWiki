## Purpose

This affects `thinking_token_budget` with speculative decoding (MTP, on both the V1 runner and Model Runner V2) and any `top_p < 1`, including a model's `generation_config` default. When the budget is reached, the request emits token id 0 (`<unk>` for NemotronH) until `max_tokens` instead of the forced `</think>`. Greedy requests and `top_p=1.0` are not affected.

**Root cause.** The bug is in the split-row top-p pipeline (#54651), not in the thinking-budget code. `_topp_sb_mask_kernel` in `vllm/v1/sample/ops/topk_topp_triton.py` runs on CUDA for batches of 64 rows or fewer, for rows with top-p and without an active top-k. It finds its pivot in probability space but masks in logit space:

```python
pivot_logit = tl.log(pivot) + logZ + M
keep = x > pivot_logit
```
