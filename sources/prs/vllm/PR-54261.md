## Purpose

Make the native CUDA Kimi-K3 AttnRes implementation the default for dense
`hidden_size=7168` inputs on SM100.

This PR:

- extends the existing register/TMEM kernel to cover block counts 0 through 8,
  optional prefix addition, optional output normalization, and block-bank
  writes;
- uses the existing source-chunk schedule for all supported block counts,
  while preserving a compile-time-folded common path;
- makes output normalization a compile-time specialization so the disabled
  path elides its shared-memory buffer, barrier, and arithmetic;
- delays the PDL wait until the first producer-dependent prefix or delta TMA
  for every native shape and triggers dependents after the producer TMAs;
- retains Triton as the fallback for unsupported devices and non-dense row
  layouts; and
- adds a reproducible CUDA-versus-Triton kernel benchmark.

Duplicate-work check: the author of #53524 coordinated moving its AttnRes PDL
handoff into this integrated change; that PR's remaining distinct scope is its
C=1 MoE/router work. #50760 changes warmup profiles only. Neither otherwise
extends the native kernel to all Kimi-K3 AttnRes call variants.
