## Purpose

Decoder-side SWA bounded replay for DeepSeek-V4.1, on top of the encoder side (#56227). The layers past the last KV-source layer (21-39 of 40 on V4.1-Flash) own only sliding-window KV, so in eager prefill steps they run on each request's last 128 tokens, cold prefills included. Simplified re-submission of #56752 (closed); no other open PR implements this.

- `DeepseekV41ModelState.prepare_attn` prepares the kept rows as a sub-batch, the way a microbatch is prepared: one Triton kernel gathers rows, positions, slot mappings and the replay-layer KV start, and the sub-batch gets attention metadata and a forward context of its own. DP ranks agree on whether any rank trims and on every rank's replay token count.
- `DecoderReplayLayers` gathers the layer inputs by those rows, runs the replay layers under that context and scatters the outputs back.
- Only eager steps trim.
