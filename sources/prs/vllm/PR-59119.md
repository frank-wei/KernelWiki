## Summary

`_ring_slot_mapping_kernel` builds the compressor ring slot mapping in `CompressorMetadataBuilder.build()` and runs on every step. Its int args `num_tokens` and `num_actual_tokens` change from step to step, and Triton specializes int args by value (`== 1`, `% 16 == 0`, or neither), so each new combination compiles a new variant while serving. These compiles are not covered by startup warmup because the triggering combinations depend on the live batch (for example, a real token count that is a multiple of 16 padded to one that is not). Under DP/EP, a rank that stops to compile stalls every other rank at the next collective.

This PR marks `block_table_stride`, `num_actual_tokens` and `num_tokens` as `do_not_specialize`, so one variant is compiled at startup and reused for every batch. These args only feed address and mask arithmetic; dropping their divisibility hints narrows some loads/stores, but the kernel is latency-bound on its dependent loads and performance is unchanged (see below).
