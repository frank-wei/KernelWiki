## Purpose

`_compute_cumulative_log_p_kernel` and `_compute_local_residual_mass_kernel` (used when `rejection_sample_method="block"`) multiply int32 logit/request-state indices by vocab-scale strides before int64 promotion. With a GLM-scale vocab (~155k tokens) the byte offset wraps once `logit_idx * vocab >= 2**31` (`logit_idx >= ~13.8k`, reachable with large `max_num_seqs` × `1 + num_speculative_tokens`), or once `req_state_idx * num_speculative_steps * vocab >= 2**31` for the draft-logits buffer. Block verification then reads out-of-bounds logits for requests late in the batch, corrupting acceptance decisions (or crashing with an illegal memory access).

The sibling kernels (`_compute_local_logits_stats_kernel`, `_rejection_kernel`, `_resample_kernel`) already promote these indices to int64 (#46560 fixed the same class of bug in the sampler kernels); this brings the two remaining block-verification kernels in line.

Found while auditing the V2 spec-decode sampling path for #47239 (not the cause of that issue — this path requires the non-default `rejection_sample_method="block"`).
