## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
As we know, each backend can force their own supported block_size and override the one specified by the user at runtime.
Current DCP slot mapping code does not take that into account, and may end up re-using the stale/old block_size value initially set by the user.

Repro with one practical example: set --block-size 128->FlashInfer MLA sets kernel block to 64
```
  VLLM_USE_V2_MODEL_RUNNER=1 \
  VLLM_DEEP_GEMM_WARMUP=skip \
  vllm serve deepseek-ai/DeepSeek-V2-Lite-Chat \
    --tensor-parallel-size 4 \
    --decode-context-parallel-size 4 \
    --block-size 128 \
    --cp-kv-cache-interleave-size 128 \
    --max-model-len 8192 \
    --enforce-eager \
    --no-enable-flashinfer-autotune \
    --trust-remote-code

  Then run:

  .venv/bin/python tests/evals/gsm8k/gsm8k_eval.py \
    --port 8000 --num-questions 100 --num-shots 5 \
    --max-tokens 256 --temperature 0

   you should see a significant drop in accuracy on current main
```
