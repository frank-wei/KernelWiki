## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
`RMSNorm(has_weight=False)` (FlashNorm-folded checkpoints, #40117) only skipped the per-channel multiply on the native path. The CUDA/CPU `_C` kernels required a weight tensor, so the layer substituted an all-ones tensor and ran the weighted kernel — correct, but a wasted load + multiply. Fixes #41430.

This makes `weight` optional on the existing `rms_norm` / `fused_add_rms_norm` ops and templates the kernels on `HasWeight`, rather than adding separate `*_weightless` ops. The weighted hot path is unchanged.

## Changes
- `csrc/{libtorch_stable,cpu}`: `rms_norm` / `fused_add_rms_norm` take `Tensor? weight`; kernels templated on `bool HasWeight` to skip the multiply when `weight` is null.
- `layernorm.py`: pass `weight=None` when `has_weight=False`; removes the old heuristic that guessed whether the native impl would be dispatched (#39370).
- `vllm_c.py` / `xpu_ops.py`: drop the ones-substitution; XPU falls back to native (the weightless `_C` path is CUDA/ROCm only).
- `_custom_ops.py`: `weight: Tensor | None`.
- `test_layernorm.py`: `test_rms_norm_weightless` vs `forward_native`, plus `opcheck` with `weight=None`.

Backends that require a weight (e.g. oink) fall back via IR op prio
