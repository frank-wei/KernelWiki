## Purpose

Fix a start-up crash of GLM-5.3-Flash in data-parallel deployments (TP=1 per rank): `fused_recurrent_gated_delta_rule_fwd_kernel` was launched with `grid = (NK, NV, N * HV)`, and with 64 KDA value heads on one GPU the first CUDA-graph capture batch of 1024 sequences needs `1024 * 64 = 65536` programs — one over the CUDA `gridDim.z` limit of 65535 — so the launch fails with `Triton Error [CUDA]: invalid argument` and `--data-parallel-size 4` (with or without EP) cannot start. TP4 (16 heads per rank) is unaffected.

The kernel now carries `N * HV` in `gridDim.x` (limit 2^31-1) with the `program_id` mapping swapped accordingly. Scope (narrowed in review): only the NVIDIA GLM-5.3-Flash copy under `vllm/models/glm5next/nvidia/ops/third_party/kda/` (`kernels.py`, `fused_recurrent.py`) and its test are changed.
