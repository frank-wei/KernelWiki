## Summary
Cooperative TopK groups FP32 scores into coarse bins before selecting candidates. If too many scores land in the bin containing the TopK threshold, its bounded candidate buffer can drop scores that belong in the result.

This PR detects that overflow before scattering candidates and uses exact FP32 selection for the affected row. The usual path remains in place when the threshold bin fits.

# Context

We need to differentiate three things here:

* Synthetic vs. real score distributions.
* Exact vs. approximate top-K in real NSA/DSA.
* The impact of overflow. Even when overflow occurs (which *is a rare event*) the discarded candidates will have the same high bits as the retained ones. Retained and discarded candidates belong to the same current radix-threshold bin. Therefore, they share the radix prefix examined so far, meaning their values are very close.

For this reasons, even if we can force the overflow with synthetic inputs, that doesn't mean non-exact topK translates into an negative accuracy impact for the reasons above. See https://github.com/vllm-project/vllm/pull/53287 for more context.
