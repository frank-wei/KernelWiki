## Purpose
Fix a Triton attention performance regression affecting Gemma 4 multimodal prompts.
Triton normally prunes KV tiles outside the sliding window. However, when multimodal prefix ranges are present, `compute_tile_loop_bounds` disables that pruning.

The fix is pretty simple in `vllm/v1/attention/ops/triton_attention_helpers.py` and was already planned as TODO:
```python
# TODO(Isotr0py): sliding window pruning with image bidirectional mask
```

This results in up to **3-4x** E2E speed up, measured with <a href="https://huggingface.co/unsloth/gemma-4-26B-A4B-it-NVFP4/">gemma-4-26B-A4B-it-NVFP4</a> on the RTX PRO 6000.

## Test Plan
Added a GPU regression test to:

`tests/kernels/attention/test_triton_unified_attention.py`

The test uses a 4,096-token sequence, a 1,024-token sliding window and a multimodal range wider than the window. It verifies that Triton selects the conservative [3, 72) tile interval instead of scanning the complete [0, 128) interval.
```

  tests/kernels/attention/test_triton_unified_attention.py \
  -k clamped_mm_prefix_prunes_sliding_window_tiles -q -s
```
