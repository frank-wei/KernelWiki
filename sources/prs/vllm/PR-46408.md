## Purpose

Under expert parallelism, dispatch hands the experts a `topk_ids` tensor whose entries can be `-1`, marking invalid / non-local slots (a token's routed expert lives on another rank). The Triton unfused MoE path (`gpt_oss_triton_kernels_moe.py`) mishandled these in two places:

1. **`expert_map[topk_ids]`** (global→local remap) indexed the map with `-1`, which wraps to `expert_map[-1]` — a valid local id — and misroutes the slot. Replaced with a fused `remap_topk_to_local` kernel that preserves `-1` (the skip sentinel `make_routing_data` expects).
2. **`ops.moe_sum`** reduced over all `topk` slots, but `matmul_ogs` leaves the `-1` (non-local) slots **unwritten** in the intermediate buffer, so the sum folded in uninitialized garbage (and was NaN-unsafe). Replaced with a `masked_moe_sum` kernel that skips `-1` slots in the per-token reduction.

Both replace prior multi-op sequences with a single fused kernel. The now-unused `from vllm import _custom_ops as ops` import and the `moe_sum` wrapper are removed.
