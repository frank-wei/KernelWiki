## Summary

- Reuse the existing Qwen4Exp HC combine kernels for MTP input instead of maintaining an MTP-only add-and-norm kernel.
- Treat `injection_logits=None` as unit injection. Triton specializes directly on the optional `inj_ptr`, so the MTP path performs no injection load or sigmoid.
- Pass `fc_embedding` into the normal decoder as a pending HC block output. The existing combine-norm kernel then fuses the BF16 broadcast add and grouped Gemma RMSNorm.
- Generalize both HC combine variants to the same optional-injection contract, and remove `_forward_mtp_layer` plus the duplicated MTP kernel.

This does not duplicate #54560, which targets the general Qwen4Exp `M=1` SM90 decode path; this change targets the MTP entry residual add and grouped RMSNorm for arbitrary token counts.

## Data flow

```text
target / feedback hidden                 new token
          |                                  |
 pre-norm + fc_hidden                embed + pre-norm
          |                                  |
 residual [T, HC, H]               fc_embedding [T, H]
          |                                  |
          |                         pending block output
          |
