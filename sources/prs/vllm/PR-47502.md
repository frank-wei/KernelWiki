## Purpose

Replace the two per-path Triton top-k implementations in the MiniMax-M3 MSA (SM100/Blackwell) indexer with a **single MSA `sparse_topk_select`** over one unified score buffer shared by decode and prefill.

**Before**, the MSA indexer ran two independent top-k paths:
- **decode** → Triton fused `minimax_m3_index_decode` (block-score + split-K top-k) writing `topk_indices_buffer[:, :nd]`
- **prefill** → fmha_sm100 `OnlyScore` → Triton `minimax_m3_index_topk` writing `topk_indices_buffer[:, nd:]`

**After**, both sides only compute **block scores** into one token-major unified buffer `[total_q, H, max_k_tiles]`, then a single `fmha_sm100.sparse_topk_select` selects the top-k for the whole batch (decode `[:nd]` + prefill `[nd:]`) in one call:
- decode scores via the new score-only `minimax_m3_index_decode_score` (split-K, cudagraph-safe) into `unified[:nd]` (transposed strided view; the kernel writes by strides);
- prefill scores via fmha `OnlyScore`, writing `max_score` **straight into** `unified[nd:]` (stride-aware, no copy — the plan's `max_k_tiles` is forced to the buffer's tile dim so the shapes match exactly);
