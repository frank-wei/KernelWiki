## Purpose
- Enable `VLLM_PLE_CPU_OFFLOAD` on the AMD/ROCm path: keep the Qwen4Exp PLE n-gram table in pinned host memory, read through a UVA view on the GPU.
- Free VRAM so `Qwen/Qwen3.8-Flash-Next-FP8` (FP8 table ~51 GiB) / `Inferact/Qwen3.8-Flash-Next-NVFP4` (bf16 table ~102 GiB) serve on one MI300X with the table entirely in host RAM.
- Keep the pinned lookup behind a custom op (`qwen4_exp_amd_ple_ngram_embedding_pinned`) with `mutates_args=["output"]` so the large embedding weight is never materialized by `torch.compile` (Inductor autotuning builds a bf16 copy of the table during compile, which OOMs on AMD setups without enough VRAM) and the op survives aot_autograd/Inductor.
- Move the PLE embedding storage classes to `qwen4_exp/common` so the AMD and NVIDIA paths share one implementation (NVIDIA re-exports).
- Relax the PLE enable gate to `is_cuda_alike()` so ROCm is accepted, matching the existing NVIDIA default (`VLLM_PLE_CPU_OFFLOAD` defaults on for both; `=0` opts out). Also, my local testing shows little to no performance loss for PLE offload while saving a good chunk of VRAM for more KV cache.
