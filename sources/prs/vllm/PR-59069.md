## Summary

Eligible Kimi-K3 AMD AttnRes outputs currently materialize BF16 activations that the next linear immediately quantizes. Fuse that per-token FP8 conversion into AttnRes and pass native `QuantizedActivation` to supported consumers.

```diff
 AttnRes + output RMSNorm
-  store BF16 → per-token FP8 quant → input GEMM
+  store FP8 + scale → input GEMM
```

Enable the path only for `kFp8DynamicTokenSym` and only when all consumers accept the same key. Mixed MoE/router consumers, unsupported linear kernels, and batch-invariant mode retain the original path. Preserve BF16 rounding before quantization and the prefix/block write contract.

This is independent of PD connector work and targets main. Duplicate checks covered #50682, #52968, and #53154: #52968's current diff covers convolution and sigmoid/multiply; #53154 covers MXFP4 output fusions. This PR supplies AttnRes per-token FP8 inputs. The current rowwise Torch FP8 KDA kernel does not expose the required input capability, so this PR does not claim all KDA inputs are fused.
