## Purpose

Hybrid/Mamba models support an align-mode Mamba cache path where the running Mamba state is migrated at scheduler-step / block boundaries. For **DS conv-state layout**, the align path has an intentionally guarded, not-yet-implemented cell: accepted-token tail copies with `num_accepted_tokens > 1` (MTP degree > 1). The scalar
`get_conv_copy_spec` helper rejects this case:

```text
AssertionError: DS conv state with num_accepted_tokens > 1 must be handled by the
fused postprocess kernel, not get_conv_copy_spec
```

**Root cause.** DS conv-state layout stores the conv state as per-dimension rows. When `num_accepted_tokens == 1` the accepted-token offset is zero and the copy path can move the whole conv-state block. When `num_accepted_tokens > 1` the migration must shift by `offset = num_accepted_tokens - 1` along `state_len`; in DS layout that tail copy is row-aware rather than a single contiguous slice, so the scalar helper deliberately asserts that the fused kernel must handle it. #45473 added DS Mamba tail-copy support for MTP align mode and exercised the degree-1 / offset-0 case; this PR extends the same align/DS area to the multi-accept `offset > 0` pre-copy case.
