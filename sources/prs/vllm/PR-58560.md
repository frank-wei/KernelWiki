## Purpose

`_ring_slot_mapping_kernel` (`vllm/models/deepseek_v41/compressor.py`) maps each token to `block_table[req, 0] * capacity + pos % capacity`. Warmup and CUDA-graph capture run dummy batches whose block tables are zeroed, so their compressor state rows are written into **block 0**. That is the null block, and every KV-cache group shares it. The fp32 state bytes therefore land in other layers' pages. On DeepSeek-V4.1-Flash, layer 2's ring overlaps the sliding-window KV of layers 0–13, and layer 8's overlaps layers 0–27.

Why it matters: sparse MLA decode kernels gather the null block for masked candidates and weight it by zero. When the bytes decode to a non-finite value, 0 × NaN is still NaN. On sm_120 (FlashInfer's DSv4 sparse decode) with DSpark speculative decoding and FULL CUDA graphs, this produced wrong outputs on the first request (0 accepted drafts), then `cudaErrorIllegalAddress` / Xid 31 MMU faults on the next prefill.
