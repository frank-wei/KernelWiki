## Purpose

`pre-commit run --all-files` currently fails on `main` (`1085b64425`): three docstrings landed alongside #52136, which selected the whole `pydocstyle` `D` family, so `ruff check` flags them for D209 (`new-line-after-last-paragraph`).

This PR drops D209 rather than reformatting them, and undoes the reformatting the rule already caused.

D209 only moves the closing `"""` of a multi-line docstring onto a line of its own. That costs a line of pure punctuation and buys no readability. Note the repo already ignores D205, so a summary is allowed to run straight into its body with no blank line; enforcing closing-quote placement while ignoring the separator that actually carries meaning is an odd pair of choices.

Three commits:

1. **Ignore D209** — one line in `pyproject.toml`. Fixes `main`.
2. **Rejoin the docstrings D209 split** — 2085 closing quotes go back onto their last content line, recovering the 2085 lines the rule cost when #52136 landed.
