## Purpose

This PR fixes several CUDA architecture build/dispatch gaps found while auditing
the CUDA arch matrix in #45260.

The main theme is making top-level arch requests, per-component CMake arch
filters, and runtime support checks agree with each other. Before this change,
some paths either carried misleading PTX settings that were filtered out, built
for arch families that the runtime never used, or advertised runtime support for
kernels that were not compiled into the wheel.

### What changed

#### PTX handling and release/container arch defaults

- Removed misleading `+PTX` entries from CI, Docker, and component-local CMake
  arch lists.
- Added comments in both `CMakeLists.txt` and `TORCH_CUDA_ARCH_LIST` defaults
  explaining that top-level `+PTX` does not survive vLLM's arch extraction path.
- Kept the intended behavior explicit: if a specific kernel really needs PTX,
  it should be added to that kernel's component-local arch list instead of the
  global `TORCH_CUDA_ARCH_LIST`.

This addresses the class of problems described in #41738, where `12.0+PTX`
