## Purpose

#47972 added per-block (128x128) FP8 for Quark **linear** layers, but
`QuarkW8A8Fp8MoEMethod` still rejects the qscheme, so a Quark checkpoint whose routed
experts are quantized per-block loads every linear layer and then fails:

```
ValueError: For FP8 Fused MoE layers, only per-tensor and per-channel scales for
weights and activations are supported. Found per_block, per_group
```

## Changes

`QuarkW8A8Fp8MoEMethod` now accepts `per_block`, following the `BLOCK` strategy of
`CompressedTensorsW8A8Fp8MoEMethod`. The per-tensor and per-channel paths are untouched;
only the scale layout differs.

- `create_weights` allocates the weight scales on the 128x128 block grid and tags them
  with `FusedMoeWeightScaleSupported.BLOCK`, so `RoutedExperts.weight_loader` shards them
  by block rather than by row.
- The scales are registered as `w13_weight_scale` / `w2_weight_scale`, the names Quark
  exports, so loading them needs no model-specific checkpoint mapping.
- `__init__` reads `block_size` from the weight config and requires dynamic activation
  quantization, rejecting a static input scale.
- `block_shape` is threaded through `_setup_kernel` and `get_fused_moe_quant_config`
<!-- upstream-excerpt-end -->
