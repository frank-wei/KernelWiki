## Purpose
#52606 added a KDA prefill fusion path for ROCm's gfx950, but was reverted in #53294 as its builds failed on gfx90a. This PR adds back the fused path, and guards the kernel builds on gfx950. This PR also adds a few optimizations to further improve the prefill performance, achieving ~5% TTFT reduction compared to the original triton path of the KDA prefill chain.

The bulk of the design follows #52606 in fusing KDA prefill ops into two groups: **"prologue"** that handles the (pre-)processing leading up to the recurrent update, and **"recurrence"** that adopts a two-pass strategy, walking the state update in each group of chunks first from uninitialized states and then from the correct initial states, with a scan in between to work out the true initial states of each groups.

This PR additionally incorporates the following on top of the original kernels:
- The recurrence stage reads from and writes to the recurrent state paged cache directly.
