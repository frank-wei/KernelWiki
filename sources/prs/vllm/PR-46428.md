## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
For DP/EP with CUDA graphs, a batch can contain a large number of padding tokens. Today, these padding tokens are handled the same way as real tokens, introducing unnecessary compute overhead.

For example, if one DP rank has a 512-token prefill while the other ranks are idle, every DP rank pads its input batch to 512 tokens—the maximum across all DP ranks, since 512 falls within the PW CUDA graph bucket. As a result, the model processes `512 * dp_size` tokens instead of the actual 512 real tokens.

This PR enables skipping these padding tokens by marking their `topk` values as `-1`. MoE kernels and A2A kernels, such as DeepEP V2, can then optionally skip sending/computing those tokens and avoid the associated overhead.

This behavior is currently gated behind the `VLLM_MOE_SKIP_PADDING` environment variable, which defaults to `0`, because some MoE kernels may not support `topk = -1`.
<!-- upstream-excerpt-end -->
