## Purpose

`VLLM_BATCH_INVARIANT=1` makes a request's output independent of what else is in the batch. On ROCm the
mode set the flag and then ran ordinary kernels, and the determinism suite skipped itself, so nothing
noticed. This PR makes the mode work on gfx90a, gfx942 and gfx950 and runs the suite there. It builds on #58623
(custom all-reduce under batch invariance).

1. **`[Quantization] Fix FP8 GEMM paths that batch invariance relies on`**
   - `triton_scaled_mm` adds the bias in fp32 before the cast, as CUTLASS does, and no longer raises
     `UnboundLocalError` with `use_heuristic=False`.
   - `TritonFP8ScaledMMLinearKernel`, a scaled-mm linear kernel over `triton_scaled_mm` (per-tensor or
     per-token activations; per-tensor, per-channel or per-token weights), forced under batch invariance on
     ROCm. The block-scaled path takes `TritonFp8BlockScaledMMKernel`. Both warn when they override
     `--linear-backend` and raise, as NVFP4 does, if they can't implement the layer.
