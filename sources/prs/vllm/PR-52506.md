## Summary

This PR adds FlashInfer as an optional ReplaySSM backend for Mamba2. It calls FlashInfer's native `checkpointing_ssu` API, shares replay trackers per KV-cache group, and autotunes a maximum-batch decode through the existing FlashInfer warmup flow before CUDA-graph capture. FlashInfer ReplaySSM supports Model Runner V1 and V2; Triton ReplaySSM remains V1-only.

## Blocked on FlashInfer

> [!IMPORTANT]
> This PR is blocked by [flashinfer-ai/flashinfer#4545](https://github.com/flashinfer-ai/flashinfer/pull/4545), which adds native ReplaySSM autotuning. Do not merge this PR until #4545 is available in a compatible FlashInfer release and vLLM's package and Docker pins are updated together.

Older FlashInfer versions fail capability validation rather than silently using a non-native tuning path.

## Validation

Validation used `nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-NVFP4` on H100 GPUs with MTP disabled.

### GSM8K

Matched 5-shot GSM8K over all 1,319 questions, temperature 0, and `max_num_seqs=64`:

| --- | ---: | ---: | ---: |
| FlashInfer ReplaySSM | 1117/1319 | 84.685% | 0 |
| Triton ReplaySSM | 1119/1319 | 84.837% | 0 |
