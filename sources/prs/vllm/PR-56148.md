## Purpose

Spec-decode verify runs attention with a few query tokens per request (1+K). On `main`, the Triton backend admits only `max_seqlen_q == 1` to the 3D split-K kernel, so verify batches fall back to the 2D kernel, which parallelizes only over Q blocks and gets slow at long context and low batch. This PR lets short multi-query batches use split-K, with a shape-only gate in `unified_attention`: split-K runs when `max_seqlen_q <= 8` and `num_seqs * cdiv(max_seqlen_q, BLOCK_Q) <= seq_threshold_3D` (identical to `main` for `max_seqlen_q == 1`). There is no uniform-decode detection or platform special case; non-causal, per-sequence-causal and mm-prefix masking and the SM100 head-256 path stay on 2D. It also makes split-K exact for fully masked tiles, empty segments and CUDA-graph padding rows.

## Changes

- `triton_unified_attention.py`: the shape-only 3D gate above; launch-time scratch check with 2D fallback.
- `triton_attention_helpers.py`: `softmax_step` no longer clamps a fully masked tile's −inf running max to 0; `reduce_segments` skips empty/unvisited segments and returns early for padding rows and `seq_len <= 0`.
- `triton_attn.py`: split-K
