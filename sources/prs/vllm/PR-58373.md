## Purpose

With the DeepEP v2 expanded layout, recv_topk_ids is (rows, 1) with one row per (token, local expert) pair, so the ep_gather output has as many rows as the permuted input. The output row offset
cur_token * output_tensor_stride0 is computed in int32 and wraps once the output exceeds 2^31 / hidden_size rows (349,525 at K=6144), causing an out-of-bounds store and cudaErrorIllegalAddress.

Widen the offset the same way #53914 widened the matching input read.

Fixes #58365
