## Purpose

Fix a KV-cache corruption in Model Runner V2 speculative decoding under data parallelism: an idle DP rank's dummy batch runs the drafter's multi-step decode, which computes real slot mappings through the *persistent* per-slot block tables using `idx_mapping = arange(num_reqs)` (real request-state slots whose rows are stale), and writes drafter-layer K/V into offsets `1..k-1` of the first block of whatever request last occupied those slots. Those blocks are typically already registered in the prefix cache, so every later request that hits them reads corrupted drafter K/V while the target model's K/V stays intact.

Observed on GLM-5.2 (glm_moe_dsa, MTP k=5, DP=4 EP, prefix caching) as a per-request, exactly-zero MTP acceptance (`p0 = 0.0000`, `acc_len = 1.0`, `drafts == max_tokens`) that latches onto a conversation and disappears after `POST /reset_prefix_cache`; the poisoned rows were NaN (fp8 `0x7F`) in `model.layers.78.self_attn.attn`, with the target layers and indexer cache of the same block clean.
