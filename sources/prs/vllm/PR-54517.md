## Purpose

- Optimizations:
  - Fuse n-gram ID generation, dilated short-conv, and the PLE gate on NVIDIA
  - Merge key/value projections
- n-gram ID generation still has PyTorch fallback for future PLE offload (#53899, not landed in main)
- Original PyTorch implementations of dilated short-conv (prefill, decode, spec-decode) are moved to `test_ple.py` for correctness testing. Production code only contains Triton kernel now.

### Correctness details

**n-gram ID generation**
- Preserve PyTorch int64 overflow behavior. Overflow hashes may become negative, so the kernel explicitly normalizes modulo results to match torch.remainder, guaranteeing every ID remains within its head-specific range: [offset, offset + vocab_size).kernel
- Ragged request boundaries are resolved from query_start_loc, including empty requests and non-power-of-two request counts. Tokens preceding the current chunk come from persistent n-gram context, and crossing EOS replaces all older suffix positions with EOS.

**Dilated short-conv**
- Preserves cache semantics for decode, prefill, and speculative decode. Speculative state is rolled back by num_accepted_tokens - 1, while current candidate inputs are retained
