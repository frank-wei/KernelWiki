# [Kernel][Model] Gemma4: optimize FA4 mm_prefix range lookup and CuTe JIT stability

## Motivation

Gemma4 multimodal models can use FA4 as the backend for all layers, so that both
sliding-attention layers (`head_dim=256`) and global/full layers
(`global_head_dim=512`) use one attention backend. This is required for the
vision `mm_prefix` / PrefixLM bidirectional mask path, and avoids mixing
FlashAttention and Triton attention implementations within the same model.

For video prompts, however, the current FA4 `mm_prefix` implementation scales
poorly when the number of multimodal ranges varies across requests and batches.
In Gemma4 video workloads each frame commonly contributes one range, so batches
may see `max_ranges` values such as 1, 8, 16, 32, 46, or 64 over time.

This is not limited to applications that pre-extract frames outside vLLM. The
native vLLM video ingestion path can also produce variable frame counts. Raw
