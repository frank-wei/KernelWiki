## Purpose

Enable Humming MoE GEMM with **MXFP4 weights + block-FP8 (group-128) activations**. To do this we had to:

## Cap MoE tuning K-block at 128

Small-M tiles can select a K-block of 256 (`block_shape[2]`), whose TMA descriptor the driver rejects at `cuLaunchKernelEx` (`CUDA_ERROR_MISALIGNED_ADDRESS`). It fires in `profile_run`, so `--enforce-eager` does not avoid it. `_cap_tuning_config_k_block` caps `block_shape[2]` at 128 — what Humming already uses for larger M — so the W4A8 MoE runs under CUDA graphs.

### Usage

On an MXFP4-weight checkpoint (e.g. `nm-testing/Qwen3-30B-A3B-MXFP4A16`):

```
VLLM_HUMMING_INPUT_QUANT_CONFIG='{"dtype":"float8e4m3","group_size":128}'
```

The per-token variant `{"dtype":"float8e4m3"}` and BF16 dispatch for non-block schemes are unchanged.
