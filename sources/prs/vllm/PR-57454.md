## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
DeepSeek-V4.1 TP4 MegaAttention can fail startup with a DeepGEMM sparse-slot assertion during dummy prefill/autotuning. The candidate-source logits contain NaNs. Although `torch.topk` selects their block IDs, `value > -inf` discards them, leaving only the pinned newest block. Expanding that underfilled row repeats its last block inside the prefix DeepGEMM expects to be unique (389 copies of block 388 in the captured failing rows).

Exclude only the `-inf` padding sentinel when storing selected candidates. This retains NaN-scored block IDs, keeps the active prefix unique for the observed configuration, and works with the existing DeepGEMM dependency. Finite-score selection is unchanged; this adds no kernel, buffer, fallback, or host synchronization. It does not sanitize logits or fix the upstream numerical source of dummy-run NaNs.

Extend the existing candidate suite with empty/partial rows and aligned/unaligned starts under zero/NaN scores, and update its reference to retain selected NaN entries.

Validation on GB200:

- Both new NaN regression cases fail against the original selector; both finite control cases pass.
- All 13 candidate tests pass on PR commit `707b81b021`; scoped
<!-- upstream-excerpt-end -->
