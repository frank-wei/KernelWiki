## Purpose

Fixes an intermittent `CUDBG_EXCEPTION_WARP_MMU_FAULT` in `hadacore::hadamard_transform_kernel`. Since Oct 15 it has crashed the `(H200 MIG 35GB) Quantization` step on main (nightly 95042, builds 95065 and 95066) and on PR runs (95016, 3 of 3 attempts). The crash happens in `test_per_token_kv_cache.py::test_reshape_and_cache_per_token_head[int4-0-16-128-1-42]` and aborts the whole pytest process.

**Cause:**
- The masked kernel variant (`enable_mask=true`) issues `cp.async` loads for all `num_chunks` chunks of a warp, even when the warp owns fewer (`real_num_chunks`).
- For the int4 per-token-head KV path, 42 tokens × 128 bf16 = 21 chunks of 256 elements, at 2 chunks per warp. So the last warp reads 512 bytes past the end of the input.
- That over-read only faults when the input ends at the end of a CUDA memory segment. Whether it does depends on what earlier tests left in the caching allocator. That's why it showed up when automatic sharding put `test_online.py` in the same process.
- The `cp.async.wait_group` counts further down already assume only `real_num_chunks` groups were committed (`switch(k + diff_num_chunks)`).

**Fix:** skip the loads past `real_num_chunks`
