## Purpose
On ROCm, Kimi-K3's KDA prefill chunk path currently runs a pipeline of nine Triton kernels. This PR adds a fusion path for ROCm that fuses these operations based on the characteristics of their workloads:

**Prologue**: The kernel that prepares the chunks leading up to the recurrent state update. It normalizes `q` and `k`, cumsum gate into `g` and `beta`, builds `Aqk` in each chunk, inverts the transition `Akk`, and produces w and u. Each 64-token chunk can be processed in parallel, so it is dispatched in `(chunk, head)` grids for parallelism.

**Chunk recurrence**: This does the remaining recurrence state update. For each sequence, the state update is sequential, and dispatching workgroups on the number of sequences can lead to low CU occupancy. This path breaks a sequence down into groups of chunks where the number of groups is determined by device capability, and takes a two-pass approach to increase parallelism within sequences:
