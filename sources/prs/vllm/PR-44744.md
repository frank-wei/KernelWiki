## Summary

Fixes https://github.com/vllm-project/vllm/security/advisories/GHSA-8wr5-jm2h-8r4f

When `vocab_size` is not a multiple of `BLOCK_SIZE` (8192), the last Triton tile extends beyond the vocabulary. If all valid entries in that tail tile have zero target probability, the out-of-range masked positions (score 0) could win the `tl.max` tie-break, producing `recovered_id >= vocab_size`. This results in a remote denial of service via invalid token reinjection.

**Fix:**
- Mask out-of-vocabulary entries to `-inf` in `sample_recovered_tokens_kernel` so they can never win the tiled argmax
- Add a belt-and-suspenders clamp on `recovered_id` before store

## Test plan

- Added regression test `test_sample_recovered_tokens_vocab_boundary` in `tests/v1/sample/test_rejection_sampler.py` that forces the zero-tail-tile scenario for non-aligned vocab sizes (8193, 10000, 151936)
- Verified every recovered token ID is within `[0, vocab_size)`
