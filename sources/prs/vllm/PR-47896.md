## Purpose
This PR upstreams the FlyDSL TurboQuant 4-bit KV-cache decode kernel developed and optimized by the AMD team. For background on the TurboQuant algorithm and its role in agentic vLLM serving, see our blog write-up [TurboQuant blog] (https://rocm.blogs.amd.com/artificial-intelligence/turboquant-vllm-agentic/README.html)

This PR adds a custom FlyDSL TurboQuant 4-bit KV-cache decode kernel for ROCm / MI355X (gfx950) as an opt-in alternative to the default vLLM TurboQuant Triton decode, for its supported profile:

1. KV cache quantized to 4-bit (MSE-key centroids + 4-bit value), HEAD_SIZE=128
2. GQA group ∈ {8, 16} → canonical tq_decode kernel
3. GQA group == 6 → tq_decode_gqa6 sibling kernel (MiniMax-M2.5)
4. arch == gfx950 ( gfx950 / CDNA4; the kernel uses CDNA4-only intrinsics and is tuned and validated there)

Selection is automatic (no env flag): on gfx950 with 4-bit TurboQuant KV and FlyDSL importable, eligible decode layers route to the FlyDSL kernel via capability gating (on_gfx950()). Layers with unsupported shapes — or all layers if FlyDSL isn't importable — fall back to the SoA Triton TurboQuant decode.
