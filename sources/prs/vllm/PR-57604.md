## Purpose

Reduce DeepSeek V4.1 MegaMoE/MegaAttention prefill overhead: tile multiple tokens
per MegaMoE staging program for sufficiently large inputs, and size the NVFP4
gather grid by request count and output capacity. Keep conservative launch
choices for small inputs. Both transformations preserve the existing arithmetic
and add no persistent buffers.

Dispatch uses eight-token staging tiles from 64 tokens, otherwise one token.
On GB200 at H5120, forced eight-token tiles regress 2–16-token kernels, tie at
32, and improve from 64 onward (both scale layouts):

| Tokens | Native staging us | Eight-token tile us |
| --- | ---: | ---: |
| 16 | 2.400 | 2.752 |
| 32 | 2.880 | 2.816 |
| 64 | 3.328 | 3.136 |
| 128 | 4.672 | 3.296 |
| 8192 | 175.616 | 32.416 |
| 16384 | 348.993 | 60.736 |

NVFP4 gathers retain 128 workers for short rows and chunks of >=16 requests.
Otherwise use `min(2048 // num_reqs, max(128, compressed_capacity))` workers.
