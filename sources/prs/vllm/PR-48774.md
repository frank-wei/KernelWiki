## Summary

This PR tunes the `ll_bf16_gemm` router GEMM dispatch heuristic for critical models: GLM5.2, DSv3.2, DSv4-Flash, and DSv4-Pro on Hopper and Blackwell GPUs.

Router GEMM has shown up as an expensive kernel if it is not treated carefully. For the most critical models, we have historically used ad-hoc, PTX-based kernels focused on LL scenarios. However, those kernels are usually limited to a
single shape, or to a very small set of shapes. Extending them to new models requires non-trivial kernel work, which is not ideal because each model family tends to bring its own router shape, and new shapes will keep appearing.

PR [#42562](https://github.com/vllm-project/vllm/pull/42562) introduced a generic cuteDSL implementation for this path. This PR is a follow-up that tunes the default configs and gets extra e2e performance on critical router shapes.

Ideally, we should eventually add an autotuner that does this automatically for every router shape. That should be feasible, but PDL support in these kernels has shown (sometimes) non-deterministic behavior when comparing kernel-level and e2e benchmarks.
