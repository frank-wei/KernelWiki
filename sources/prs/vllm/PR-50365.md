## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
The sparse-MLA index remap splits each 2048-wide row into 16 column tiles. On the valid-count path every tile atomic-adds into the same per-row counter, so the row total is built under 16-way contention -- and the DCP compaction path uses that same counter as an atomic slot allocator.

Counting is the only reason the tiles need to talk to each other. Give one program the whole row instead: the count becomes an in-register reduction plus a plain store, the compaction base is statically 0, and the counter buffer no longer needs zero-initialization. Rows without a count keep the 16-tile layout, where there is nothing to contend on.

Measured on GB200 inside a CUDA graph -- decode runs under graphs, so the launcher overhead is captured once and only the kernel work is timed. Per-call, previous kernel -> this one:

```
                              1 token        256 tokens    1024 tokens
  index_topk 512  ( 4 tiles)  2.50->1.67us   4.06->1.84us   5.50->2.54us
  index_topk 2048 (16 tiles)  3.02->1.83us   5.65->2.20us  12.22->3.84us
```
