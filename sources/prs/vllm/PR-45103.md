## Purpose
The ROCm DeepSeek V4 o-projection (rocm_inv_rope_einsum, run once per decode layer) ran the inverse GPT-J RoPE as ~10 small PyTorch kernels  (clone, index_select, 2x repeat_interleave, neg, stack, cat, casts) and re-dequantized the static fp8 wo_a weight every step (fp8->fp32->*scale ->bf16), which showed up in the decode profile as the two largest copy/mul kernels.
    - Add `_inverse_rope_gptj_kernel` (Triton): single-launch inverse GPT-J RoPE writing bf16 directly. Guarded for the non-neox, even-rope_dim, contiguous layout; the PyTorch path is kept as fallback.
    - Cache the dequantized bf16 wo_a weight on the module  (`_dsv4_wo_a_bf16`) so the dequant runs once instead of per step.
