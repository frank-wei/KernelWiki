## Purpose

On main, `--kv-cache-dtype fp8` is silently ignored for MiMo-V2.6-Flash: its decoder and MTP layers build `Attention` without `cache_config`, so the KV cache stays BF16. Forwarding `cache_config` alone would turn this into a startup error on GPUs without FA3/FA4, where MiMo runs `TRITON_ATTN_DIFFKV`, which rejects quantized KV. This PR fixes both:

- `TRITON_ATTN_DIFFKV` accepts `fp8`/`fp8_e4m3` with per-tensor K/V scales and FP8 queries on CUDA. K and Q scales fold into the softmax scale; V scaling is applied once before writing the output or split-KV partials. Query quantization uses the existing Attention quantizer.
- The MiMo decoder and MTP layers (`mimo_v2.py`, `mimo_v2_mtp.py`) forward `cache_config`. Decoder layers clear `sliding_window` on the shared cache config, since MiMo's model-wide `sliding_window` (128) would otherwise be applied to its global layers.

On FA3/FA4 GPUs, the forwarding also enables FP8 through `FLASH_ATTN_DIFFKV` (untested here).

No other open PR covers DiffKV FP8 or the MiMo KV cache dtype; #54341 (fp8_e5m2 in triton_attn) doesn't touch either.
