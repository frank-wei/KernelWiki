## Summary

The native attention-residual programs (`native_m128`, `native_k8`) are grid-stride kernels; the host admitted them
only on 148-SM devices and fell back to the persistent programs elsewhere. They now route on the qualified SM counts
`{148, 152}` with one CTA per SM (`grid_x = num_sms`); on a 152-SM GB300 this is 2-17 % faster than the fallback
(same-GPU ABBA, CUPTI, cold L2). No new kernel family; 148-SM routes unchanged. The runner carries the device SM
count; the policy tests enumerate (arch, SM count) including (sm_100a, 152).

The generated-program registry (`cake_jit.py`) is regenerated for the (arch, SM count) configurations; no program
source changes. The regenerated package is byte-identical across the three hardware export stages.
