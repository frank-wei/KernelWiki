## Summary

Re-export of the Cake MiniMax-H3 MLP kernel sources (`csrc/cake_minimax_h3_mlp_sm100a.cu`, `csrc/cake_minimax_h3_mlp_sm103a.cu`) for the BF16 / MXFP8 / NVFP4 operators `flashinfer.diffusion_ops.minimax_h3_mlp{,_mxfp8,_nvfp4}` (follow-up to #6176). Python bindings, JIT spec and tests are unchanged.

- **FC2 BF16 epilogue 8 -> 4 warps.** The FC2 BF16 kernel drains its 256-column accumulator with 4 epilogue warps (two 128-column drains, the full row drained before the epilogue-done arrive, split-K hand-off counter re-armed after the stores). The CTA shrinks from 320 to 192 threads; the host-side thread constant follows. Executed warp instructions drop ~13 % (spin warps 8 -> 4); the in-trace FC2 kernel time is 0.3-0.4 % lower on B200 / B300 at the production shapes.
- **Bit-identical output.** Operator output, FC1 activations and the FC2 output compared as integer views against the previous kernel at M = 1 / 127 / 128 / 129 / 255 / 256 / 257 (P = 8), M = 4824 (P = 8) and the production tiers on both architectures; identical tail-split decisions. No tolerance, rounding point or precision change.
