## Summary

The Cake warp-decode expert GEMM carried host code and data that nothing used:

- a 1.06 MB JSON pair that the loader parsed whenever it generated the JIT spec
- three workspace-preparation FFI exports and a `run` alias with no callers, plus the owner-tensor paths that only they fed
- manifest predicates and spec fields that are compile-time constants or never read
- a per-launch shared-memory check whose result the binding threw away

Two test gaps also existed. The parity test never launched some of the kernels, and part of the correctness coverage could only be reached through the benchmark.

This PR removes the unused code and data and adds parity rows so the test launches every kernel of each target. It also moves the correctness cases from the benchmark into `tests/moe`. No device kernel source (`*.cu` under `generated/`) changes. The SASS gate against `main` is under Validation. The remaining FFI exports keep their names and argument order.
