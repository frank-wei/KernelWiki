## Summary

`mm_fp4(..., backend="cake")` per-token NVFP4: the static 2-CTA persistent GEMM now shares its partial last wave. Each tail tile is cut into `S` equal K slices held by `S` consecutive CTA pairs; every holder publishes the output subtiles it does not own (FP32, coalesced), bumps a per-slot generation flag, waits for its siblings to reach the same generation and sums its owned subtiles in fixed K-slice order (`((P0 + P1) + ...) + P_last`, own slice straight from TMEM). No atomics, no arrival-order dependence, no flag resets. The host (`stream_k_tail`) runs the sliced program only where at least three slices fit; every other row keeps its previous program and key (bitwise identical output).

Changes to the public API: none (no new operator, parameter, default or backend semantics).
