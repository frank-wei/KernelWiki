## 📌 Description

Publish the frozen Cake MegaMoE TopK reducer for **SM103a (B300)** next to the existing SM100a (B200) drop, and let the SM100 NVFP4 CuTeDSL MegaMoE backend use the native reducer on compute capability 10.3 as well as 10.0. Follow-up to #5431, where @yzh119 asked why the reducer was sm_100a-only: the kernel uses no SM100-specific instructions (plain vectorized `ld.global.L1::no_allocate` loads, ordered no-FTZ `fma.rn.f32x2` accumulation, `__launch_bounds__(256)`), so the limit was the B200-only validation boundary, not the code.
