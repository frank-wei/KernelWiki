## 📌 Description

Follow-up to #5592 (fused MoE gate_up projection for Blackwell SM100a: pair + tail kernels, routing-aware route rule,
wide activation kernel).  The prepared API
`flashinfer.gemm.prepare_group_gemm_fp8_nt_groupwise_contiguous_silu_quant(a, b, a_scale, b_scale, m_indices).launch()`
and its contract are unchanged.  Two changes, both bit-identical to the three-kernel chain on every routing tested:

- **Paired BF16 conversions in the fused epilogues (pair and tail kernels).**  The SwiGLU + quantization epilogue rounds
  the gate, up and `silu(g) * u` values to BF16 through `cvt.rn.bf16x2.f32` (two values per instruction, 1.5 instead of
  3 conversions per output) at the same rounding points, so the outputs stay bit-identical to
  `silu_and_mul` + `per_token_group_quant_8bit`.  The epilogue is issue-bound on the SM's conversion unit; on the
  wide-EP32 gate_up shape `[M=4096, 2H=2048, K=4096, G=16]` the fused route runs 1.07
