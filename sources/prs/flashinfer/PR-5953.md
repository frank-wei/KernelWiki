## Summary

Closes #5807.

`csrc/generated/ulysses/sm_100a/` shipped 60 files (17.7K lines) for the NVLink Ulysses all-to-all: 24 kernels plus 36
`*_binding.cu` files (12.7K lines, 72 %) that nothing calls. The dispatcher launches the generated kernels directly through
`cudaLaunchKernel`, so the TVM-FFI entry points, their `ScopedCudaDevice` helpers and the per-binding device-attribute caches
were dead weight compiled into every build. The loader selected the generated module only when the build-target list was
exactly `10.0a` or exactly `10.3a` (multi-arch builds silently fell back to the portable kernel), and the test imported its
fixture from `examples/`.

- One kernel unit per (dtype, world size, direction) directly under `csrc/generated/ulysses/` (24 files, same kernel text as
  the sm_100a copies they replace; the sm_103a build compiles the same sources). The `sm_100a/` directory and the 36 binding
  files are removed.
