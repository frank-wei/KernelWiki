> Developed by the **CAKE team**, the kernels in this PR **outperform** the relevant **SOTA baselines at the time of merge** on the **vast majority of performance benchmark shapes**, matching them otherwise.

This PR does the mechanical steps of #6639 for the Cake KDA root files in `csrc/kda` and the PTX host code: steps 1, 2, 3, 6 and 7 of the issue's list, and the exact-text part of step 8. Every change is one of four kinds. It deletes text that no caller can reach. It simplifies a table or loader, and the compile inputs stay the same. It renders host text that is byte-identical to the deleted files. Or it merges sources, and a compile gate requires the SASS of every (member, architecture) pair to be byte-identical. The `csrc/kda` root files go from 228 files / 299,834 lines to 149 files / 222,316 lines (this excludes the separately tracked `bf16/`, `tf32/` and `ptx/` subtrees). The PTX host code in `flashinfer/kda_kernels/ptx/{scheduler,static_runtime}.py` goes from 1,500 to 1,315 lines. No kernel behaviour, selected program, public signature, default or error type changes.
