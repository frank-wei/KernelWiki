## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
`cake_all_gather_matmul` all-gathers each rank's row-sharded activation and multiplies it by a contiguous `[N, K]` weight. Cake ships it in bf16 and fp16, K-major and N-major weights, world sizes 2, 4 and 8, two main-tile widths and two transport routes (copy engine, SM push). This PR delivers one SM103a (B300) variant: for world-size-4 bf16 K-major calls with 128 padded rows and N = 14336, the main GEMM program walks its (peer, B-panel) output tiles in peer-outer order (`_po`) instead of the previous order. Same tiles, same instructions, bitwise-identical outputs; one program is added for that one shape and no other program changes. The table compares it with the previous Cake version of this kernel, the programs of #6761, whose branch this one is built on.

| Shape per rank, M × N (world size 4, K = 8192) | Previous version (µs), node 1 / node 2 | This PR (µs), node 1 / node 2 | Speedup, node 1 / node 2 |
|---|---:|---:|---:|
| 125 × 14336 (padded to 128 rows), bf16, K-major weights (Llama-3.1-70B TP4 fused gate/up) | 187.4 / 191.0 | 171.8 / 174.9 | 1.098 / 1.112 |

NVIDIA B300 (SM103a), CUDA 13.3, two B300 nodes, four ranks with one rank per GPU; latency = median over calls of t
