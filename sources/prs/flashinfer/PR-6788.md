## 📌 Description

Two changes to tile selection for the trtllm-gen FP4 block-scale fused MoE, aimed at large-batch MXFP4 x MXFP8 shapes on Rubin (SM107).

1. **Advertise the 192-token tile on Rubin.** `FP4BlockScaleLauncher` excluded tile 192 under `#ifndef TLLM_RUBIN_FEATURES` because the earlier, separate Rubin BMM pin shipped no 192-tile FP4 kernels. The consolidated multi-arch BMM pack used by `TRTLLM_GEN_BMM` ships sm_107a 192-tile NVFP4 and MXFP4 x MXFP8 kernels, so Rubin now enumerates the same tiles as Blackwell.

2. **Offer the tuner two tiles below the covering tile.** `computeSelectedTileN` offered the covering tile, up to two tiles above and one tile below. With 192 in the ladder, a 9216-token NVFP4 case (covering tile 256) got the window {192, 256} and lost tile 128, which is the best tile for some shapes. The tuner candidates now include two tiles below (`tiles_below = 2`). The default tactic (`selectDefaultTileN`, used without autotuning) keeps one tile below, so untuned behaviour is unchanged.
