## 📌 Description

Fixes an illegal memory access in `flashinfer.mega_moe_v3.prepare_pipeline` when `topk_idx` contains -1.

A -1 in `topk_idx` means the slot is routed to no expert. Routing gates write it for masked tokens, and
`source_mega_moe` already skips it with `if (expert >= 0)`. Upstream DeepGEMM MegaMoE skips a negative
expert when it reads `topk_idx`, and its combine ballots `topk_idx >= 0`. The nine mega_moe_v3 pipeline
kernels instead used the -1 as an expert index:

- the dispatch histogram ran `atomicAdd(&expert_counts[e_h], 1)` with `e_h = -1`, and the slot list was
  written at `expert_scatter_offsets[-SLOT_CAP + slot]`;
- the expert-ordered pull walks pair ordinals `[0, num_tokens * top_k)` against the cumulative expert
  counts. With -1 routes, the counts sum to less than that, so the walk ran past the last expert;
- combine loaded `token_to_permuted[token * 6 + k]` for all six slots and added that row.

The host preparation also counted -1 as expert `E - 1`.

On main, a masked token (all six slots -1, weight 0) fails on every pipeline route:
