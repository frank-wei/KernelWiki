## Summary

Follow-up to #5914 / #5949 (`backend="cake"` SM120 DeepSeek-V4 NVFP4 sparse-MLA decode). Two changes, both exact (fp32 accumulation order per split and pair unchanged, bit-identical output on every row):

- **Split-count-guarded batched merge.** `csrc/cake_dsv4/sm_120a` is regenerated: every head count now also carries a batched merge kernel (`*_merge_batched`) that loads all split LSE slots up front with a clamped index and keeps four partial groups in flight; the generated binding selects it for `num_splits >= kMergeBatchedMinSplits` (8). Every call with fewer splits launches the previous kernels byte for byte. The decode kernels are unchanged.
- **GB10 head-tile planner refinement** (48 SMs only; RTX 5090 / RTX PRO 6000 decisions unchanged): the H = 64 sub-wave two-tile band is inclusive at `ctas == 2/3 SMs`, and the full-wave two-chunk one-tile band is `2 waves < ctas <= 8 waves` (beyond eight one-tile waves the head-tile pair wins again). `flashinfer/mla/_spar
