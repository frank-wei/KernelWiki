## 📌 Description

Optimize FP4 V-scale dequantization in the h512 FA2 NVFP4 paged prefill path.

On SM86, the h512 FP4 prefill kernel spends most of its time on V-scale dequant inside `vosplit_compute_pv` — a bypass probe showed about 57% of the kernel time. This PR loads 4 scale rows as one `uint32_t` on SM8x and converts them with the existing `fast_dequant_f8f16x4` helper, instead of doing 4 scalar byte loads and conversions per MMA tile. The scalar path is kept for the non-aligned case, for non-FP4 dtypes, and for SM90+.

The SM90+ gating is based on the SM120 result reported by waynehacking8: the ungated vector path was correct on RTX PRO 6000, but showed a small 1-2.6% regression on some 4K cases. So this revision keeps the measured SM86 speedup while leaving newer architectures on the existing scalar path until there is positive data for them. The KV cache format and smem layout are not touched.

Also added bf16 h512 test cases (with and without RoPE), because bf16 takes a different branch in `fast_dequant_f8f16x4`.

No new kernel instantiations — only the inner loop of the existing FA2 kernel changes. h512 is excluded from the default AOT config anyway, so there is no wheel
