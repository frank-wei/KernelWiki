## 📌 Description

Resolves item 11 of the SM121 support audit (#3170): re-verify the SM121 `xfail` on
`tests/utils/test_jit_example.py::test_dump_logits`, added in #1951 when the cause was
unknown.

Re-verified on DGX Spark hardware: the test still fails, but not because of SM121
numerics. The cause is a split-KV bug in the FA2 kernels that Spark's SM count happens
to expose:

- With split-KV, a CTA's kv chunk can end in the middle of a KV tile. For the lanes
  past the chunk end, the kernel invoked the attention variant's `LogitsTransform`
  hook before the mask discarded them. Attention output stays correct, but a variant
  with side effects (such as the `DumpLogits` JIT example, which writes logits to
  global memory) publishes stale values for kv positions its CTA doesn't own.
- Most GPUs get tile-aligned chunks, so those lanes never exist and CI never saw this.
  Spark's 48 SMs produce a misaligned chunk size for the test shape.
