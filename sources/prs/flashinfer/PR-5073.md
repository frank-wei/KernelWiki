## 📌 Description

Adds `gdn_prefix_materialize`: reconstruct a request's GDN SSM state at a chosen token from its u-cache checkpoint + ring, and write it to a separate state-pool slot. Sources and rings are read-only; `count == 0` is an exact copy; rows with negative slot/count are skipped.

**Use case: prefix caching.** A cached prefix is only reusable if its state sits at a fixed boundary (e.g. every 128 tokens), but the u-cache decode kernels checkpoint wherever their flush lands.

Example: a request's last flush checkpointed the state after token 120, and decoding has since accepted tokens 121..129 into the ring. Token 128 is a boundary, so the scheduler calls this kernel once with `count = 128 - 120 = 8`: it replays ring entries 121..128 (not the 9th, token 129) onto the token-120 checkpoint and writes the exact token-128 state to the prefix cache's slot. Decode continues undisturbed.

The call must happen before the next flush moves the checkpoint past 128; per-request `src`/`dst`/`count` means one launch serves a whole batch in which different requests cross different boundaries (and most cross none: rows are `-1`).
