## 📌 Description

Add an experimental BF16 paged GQA decode path whose work scheduling is owned by the kernel
(the "kernel-owned length-aware work scheduler" discussed in #4832) through
`flashinfer.decode.prepare_balanced_batch_decode_with_kv_cache(..., backend="cake")`.

Semantics: paged GQA decode with exactly eight query heads per KV head, head dimension 128,
16-token `HND` pages (`kv_cache=(k_cache, v_cache)`), BF16 Q/K/V/O, `q_len_per_req` query tokens per
