## 📌 Description

Fixes an exit race in the Cake dense projection GEMM (`flashinfer.experimental.dense_projection_gemm`).

**Cause.** The CTA-pair programs whose exit is the cluster barrier (every program without bit 8 of `pro`) stop waiting on the stage-release barrier `mma_done` in each CTA's load warp after the last refill. The leader's MMA warp releases every stage of both CTAs with a multicast `tcgen05.commit`. The last `min(stages, K steps)` of those arrivals can still be in flight to the follower's shared memory when the follower CTA exits. The PTX ISA requires a CTA to ensure that its peer has not exited before an operation on the peer's shared memory completes. Neither existing synchronisation orders these arrivals:

- the exit `barrier.cluster` completes no asynchronous operation;
- the epilogue's wait on the later accumulator commit does not order an earlier commit's arrival (commits are not pipelined with one another).
