## What

Expose trtllm-gen block-sparse attention through `trtllm_batch_decode_with_kv_cache` via a new `enable_block_sparse_attention` flag (decode/generation phase only). Each KV head attends to its own subset of KV cache pages:

- `block_tables`: `[num_kv_heads, batch_size, max_num_pages_per_seq]` — selected page ids packed densely at the front of each row, ascending original order.
- `seq_lens`: `[num_kv_heads, batch_size]` — surviving KV token count per (kv head, sequence).

The KV cache layout is unchanged. `mUseBlockSparseAttention` is a pure runtime parameter of the existing paged-KV generation cubins (added in trtllm-gen), so **no new cubins / kernel-selection changes are required** — this PR only wires the flag (previously hardcoded `false` in `kernelParams.h`) through the runner params, FFI launcher, and Python API.

Also fixes `csrc/fmhaReduction.cu` to index the per-KV-head sequence lengths in the multi-CTA-KV reduction when the flag is set.

Rejected combinations (validated with clear errors): context/prefill phase, sliding window, sparse MLA, skip-softmax, and the non-shared paged-KV index layout (kernel supports it; deferred).
