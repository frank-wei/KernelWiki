## Summary

Regenerates `csrc/experimental/deepgemm_kgroup_gemm` and its host module so the
K-grouped FP4 GEMM family accepts any group layout at runtime instead of
keying programs on the exact per-group K list and SM count.

- Kernels read M, N, the grid, the group count and the group layout at launch;
  nothing about the group list is compiled in.
- The host (`kgroup_gemm.py`) selects one of six schedule tiers from M, N,
  the group count, the output mode, the device SM count and the largest group's k-block count:
  N128/S7 with one or two TMA store stages, N256/S6 with one store stage, BM128/BN16 for small problems whose groups stream many k-blocks (with an
  exact-geometry program for the 2 x 8 x 3 tile geometry the previous programs
  compiled statically, selected from the tile counts alone), and
  the BM240 multicast schedule for the M5120/N2304 geometry. It derives the
  kernel-side group metadata from `group_ks`, `k_alignment` and
  `use_psum_layout`.
- One source per program serves SM100a and SM103a (`__CUDA_ARCH__` guards fold
  the per-arch lowering); the bindings are thin TVM-FFI launchers; the JSON
  catalog is replaced by a compact module/route table in the host modul
