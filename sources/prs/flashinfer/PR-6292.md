# Fixes #5139 : accept the TC-decode ultra FC2 tile in the SM12x W4A16 `force_tile_config` re-pin

Branch: `b12x_w4a16_kernel_fix` (on upstream main, 0.7.2) · Target: `main`

## 📌 Description

### Why this is needed

vLLM is adding W4A16 (NVFP4 weights, BF16 activations) support to its `flashinfer_b12x` MoE backend ([vllm-project/vllm#56535](https://github.com/vllm-project/vllm/pull/56535)) so that weight-only NVFP4 checkpoints such as `nvidia/Qwen3.6-35B-A3B-NVFP4` run through `B12xMoEWrapper(quant_mode="w4a16")` instead of being silently quantized to W4A4. That path goes through `moe_w4a16_kernel.py`. On every FlashInfer release since the TC-decode re-pin landed (0.6.18 through 0.7.2, including this tree) the W4A16 kernel crashes on the first decode-sized launch, so vLLM currently has to refuse W4A16 on those versions. This PR removes the crash.

### The issue

With `nvidia/Qwen3.6-35B-A3B-NVFP4` (hidden 2048, expert intermediate 512, top-k 8) on a GB10 (SM121):

```
vllm serve nvidia/Qwen3.6-35B-A3B-NVFP4 --max-model-len 4096 --moe-backend flashinfer_b12x
...
ValueError: force_tile_config fc2 tile (tile_k=32, tile_n=512) does not fit
problem N/K=2048/512 at moe_block_size=8
```
