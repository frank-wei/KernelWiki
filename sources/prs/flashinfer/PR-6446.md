### What changed

The DeepSeek sparse-attention indexer top-k scan kernels (`csrc/cake_dsa_indexer_topk/*.cu`, selected per architecture by
`flashinfer/experimental/cake_dsa_indexer/cake_jit.py`) hand a per-unit "verdict" word set from the math warps to the MMA warp
through shared memory guarded by an mbarrier.  Two reads of that hand-off were performed by all 32 lanes after a single lane's
release: the MMA warp's read after its mbarrier wait (every program) and, in the paired-unit programs, the math warps' read after
the named barrier.  `compute-sanitizer --tool racecheck` reports both as hazards because it credits only a thread's own
arrive(release) -> wait(acquire) edges.

This change makes both hand-offs single-lane:

- the MMA warp: lane 0 performs the verdict-word loads with a plain, non-speculable `ld.shared.b32` (`asm volatile`, no memory
  clobber, no acquire) and broadcasts the OR-ed verdict with `__shfl_sync`;
- the paired-unit programs' math warps: lane 0 reads the verdict words the same way, broadcasts, and the same lane performs the
  `mbarrier.arrive` on the verdict barrier (reader == releasing lane).
