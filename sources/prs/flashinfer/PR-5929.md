## Summary

Closes #5808.

Deslop of `flashinfer/experimental/sm110_gqa_decode` (SM110 / CC 11.0 GQA decode): one registry, thin launcher bindings, no per-call host synchronization. Device code is unchanged.

- **backend**: the convenience API no longer runs `torch.aminmax` + two `.item()` host synchronizations per call; sequence lengths are a device-side precondition (`[1, capacity]`), exactly as in the prepared API, and the launch enqueues without a synchronization.
- **jit**: one registry (`MODULES` / `ROUTES` / `PREPARED_ROUTES`) replaces the two manifests and the two loaders; no source-digest re-verification at import.
- **bindings**: the five launchers share `csrc/sm110_gqa_decode_launch.cuh` (TMA encoders, one-time dynamic shared-memory opt-in) and `tvm_ffi_utils.h` (checks, `CUDADeviceGuard`, `get_stream`). The private device-guard class, duplicated tensor checks, mutex/static caches and the unused SM-count query are gone. Kernel translation units are byte-identical to `main`.
