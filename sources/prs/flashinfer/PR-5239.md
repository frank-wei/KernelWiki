# Remove the SM100+ gate on the NVFP4 KV tile repack

## What this is

`#4769` added the NVFP4 KV tile repack and, in the same PR, gated it to targets below SM100. I wrote both. The gate's premise was that the repack exists to pay for the software E2M1 -> 16-bit conversion, so a part whose `cvt` is a single instruction has nothing to gain and would only lose the shared memory the staging buffer costs. I had no Blackwell hardware and said so in that PR.

Two independent measurements since then say the premise is wrong. @qsang-nv reproduced them and suggested opening the PR.

## Why the gate was backwards

@TensorRaya measured sm_120 first (`#4769` comment): forcing the repack on saves 30-34% of NVFP4 prefill wall time across kv 32k-400k, and `ncu` showed the in-loop path executing 4.1x the instructions of bf16 KV for the same tensor work.

@qsang-nv then reproduced on two parts with CUDA 13.2, both bf16 and fp16 Q:

| target | shape | repack off (current `main`) -> repack on |
|---|---|---|
| sm_120 | head_dim 128/256, kv/qo 32k/8k to 128k/128k | 12-21% faster |
| sm_100 | head_dim 128 | 1.61x faster |
| sm_100 | head_dim 256, kv 131072 / qo 8192, bf16, causal | **3.04x faster** |
