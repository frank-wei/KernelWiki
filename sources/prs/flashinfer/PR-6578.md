## Summary

Re-exports the SM100 / SM103 DeepSeek-V4 NVFP4 sparse-MLA decode family (`backend="cake"`, `kv_cache_format="nvfp4"`)
with one change, in the split-KV **merge** kernel and its launcher. The merge now waits on the decode grid with
`griddepcontrol.wait`. It is launched with programmatic stream serialization, so it can be scheduled while the decode
grid's tail is still running. The 16 decode kernel variants are regenerated byte-identically (same generated source as
the previous delivery). The member set, the host route, the loader registrations and the public API are unchanged.

- **What changes in the kernel.** The merge kernel's first statement is now
  `asm volatile("griddepcontrol.wait;" ::: "memory");`. It runs before the kernel reads the decode partial outputs
  (`partial_O`, `partial_lse`). This line is the only difference in the merge's generated device source compared with the
  previous delivery. SASS on SM100: `ACQBULK` +1, `NOP` -1, 288 -> 288 instructions. The generated binding launches the
  merge with `cudaLaunchAttributeProgrammaticStreamSerialization` (`programmaticStreamSerializationAllowed = 1`), so the
  merge grid may be scheduled while the decode grid
