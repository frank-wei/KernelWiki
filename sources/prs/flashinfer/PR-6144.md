## 📌 Description

EAGLE speculative decoding verifies draft tokens with a prefill attention call in which every request has exactly `draft_token_num` query rows. FlashInfer's FA2 CUDA-graph planner cannot see that and sizes its query tile for the ragged worst case, so on H200 with fp8 KV it uses the 64-row tile for a 16-row problem. At long context each verify launch runs 2-3x slower than it needs to, 15 times per decode step.

Two changes:

1. **Planner hint.** `BatchPrefillWithPagedKVCacheWrapper.plan(..., uniform_q_len=N)` (also the ragged wrapper and `workspace_size`) lets the caller promise that every request has `N` query rows. The FA2 scheduler already supports this internally; the Python wrapper now exposes it. The promise is checked against `qo_indptr` on the host and dropped with a one-time warning if it does not hold. Trailing keyword, default `None`; existing calls are unchanged; no C++ change.
