## 📌 Description

Compute capability 10.0/10.3 (B200/GB300) had no NVFP4 route for MiniMax Sparse Attention: msa_sparse_attention and msa_sparse_decode_attention rejected packed uint8 K/V and tensor block scales on these parts. This adds that capability behind the existing public API. The only signature change is a new optional out= argument on the decode entry point.

Supported inputs (both routes)
- A packed NVFP4 paged KV cache: one planar 73,728 B page per block laid out as [K data | K scale | V data | V scale], passed as four strided views of the same allocation -- uint8 (num_pages, 4, 128, 64) data and (num_pages, 4, 128, 8) block scales. The kernels read the page in place and never materialize a dense or dequantized copy in global memory.
- e2m1 values with one e4m3 block scale per 16 elements. K scales are stored linearly, V scales in the cache writer's (4, 4) swizzle. Scale views may be uint8 or float8_e4m3fn. k_global_scale and v_global_scale are required.
- BF16 queries and BF16 output. The kernel bodies are built for 64 query heads, 4 KV heads, head_dim 128 and page_size 128; the guard enforces that geometry and the page layout
