## 📌 Description
@humansand

Adds an explicit `quant_mode="w4a16"` path to the SM100 CuTe DSL NVFP4 MoE APIs.

### Design walkthrough

- **Interface:** Explicit `quant_mode="w4a16"` mirrors the existing SM12x CuTe DSL MoE quant-mode dispatch instead of inferring the path from tensor dtype. W4A4/NVFP4 remains the default; W4A16 requires BF16 `x`, `x_sf=None`, `fc2_input_scale=None`, and no per-token scale. The unified runner uses the existing `MoEConfig.quant.variant`, `RoutingInputMode.PackedPrecomputed`, `TunableRunner`, `use_fused_finalize`, and `enable_pdl` contracts.
- **Weight decode:** NVFP4 E2M1 values and E4M3 scales are decoded online to BF16. CUDA 13.2+ uses direct explicit-RN BF16 PTX; earlier compilers use explicit-RN FP16 conversion/multiply followed by FP32-to-BF16 widening.
- **Weight layout:** TMA loads the unchanged public packed layout into SMEM. The transform assigns contiguous complete NVFP4 blocks to two decode warpgroups and writes BF16 in MMA/TMEM layout, so each E4M3 scale is decoded once and packed reads stay contiguous.
