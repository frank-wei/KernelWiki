## 📌 Description

<!-- What does this PR do? Briefly describe the changes and why they’re needed. -->

Adds `RoutingMethodType::TopKSigmoid` (= 9): expert selection ranks the raw routing logits, then sigmoid is applied to only the top-K survivors. The existing `Sigmoid` (= 8) does the reverse — sigmoid, then TopK. Sigmoid is monotonic, so the two orders agree on nearly all inputs. They diverge once logits saturate: past roughly |17|, fp32 sigmoid returns exactly 1.0 and ranking the squashed scores degenerates into a tie-break by expert index, while TopKSigmoid still orders experts by raw magnitude. No kernel changes are needed. It is a new `SigmoidPostprocess` policy paired with the existing `NoOpPreprocess`, plus a `PolicyTraits` tier entry for <=128 and <=256 experts, so all existing routing kernels pick it up via the generic policy dispatch. `Unspecified` moves from 9 to 10 so it remains the numerically largest member.
