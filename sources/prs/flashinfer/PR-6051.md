## Summary

Cake Mamba2 SSD combined prefill (`SSDCombined(backend="cake")`) regenerated from Cake `b4f2007fd640d841b81da36f51359c847a2f41e4` (MR branch `averyh/cake-956-ssd-combined-prefill`, tip `93b72942db9`) through the export front door `tools/export_cake_mamba_ssd_combined.py --draft` / `--check` (no hand edits of generated files):

- one kernel family: exact scan × {bf16, f16, **f32**} state × {batched, varlen}, plus one segment preprocess; the prefix and direct programs are retired (the prefix route produced NaN on single-chunk calls — `rcp(exp2)` overflow);
- per-token delta carried in **FP16** (accuracy: fraction of outputs outside atol=rtol=1e-2 of an fp64 recurrence drops from 1.4 % (CuTe / old Cake) to 0.5–0.6 %);
- **token-major `out [B, S, H, 64]`** written by the kernel, **any `seqlen`** (trailing partial chunk in-kernel), **varlen `initial_states=None`** with `num_seqs`, **FP32 state**;
- one launcher call per `run()` (the preprocess publishes the sequence→chunk prefix sum; the Python `SeqChunkCumsum` JIT kernel is gone);
- loader: `_SCAN_MODULES` program table from the export summary, 22 + 41 kernel arguments bound by name, `check_dtype` brace-initialised state ch
