## 📌 Description

Humming weight preprocessing naturally produces one residual scale per expert.
However, the CUTLASS fused MoE Humming interface previously required
quant-scale slots 1 and 4 to contain one value per routed row (`M * top_k`),
already reordered into FlashInfer's internal expert-permuted order. This leaked
an internal runtime layout into the API and forced callers to duplicate the
token-to-expert permutation before every fused MoE invocation.

This PR changes the two Humming residual inputs to use rank-local expert order:

- Slot 1: FC1 residual scale with shape `[num_local_experts]`.
- Slot 4: FC2 residual scale with shape `[num_local_experts]`.

The fused MoE runtime reuses its existing expert-permuted token map to select
the correct local-expert residual for each routed row:

- FC1 performs the lookup while expanding and dynamically quantizing routed
  input rows.
- FC2 performs the lookup while applying the activation and dynamically
  quantizing the GEMM1 output.
- In both cases, the selected residual is folded into the row's dynamic FP8
  activation dequantization scale before the combined scale is consumed by the
  GEMM epilogue.
