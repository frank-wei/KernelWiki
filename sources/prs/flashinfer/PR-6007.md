## Summary

Follow-up to #5737 for the native 64-query-head DSA sparse-attention training kernels (`flashinfer.experimental.cake_dsa_train`):

- **Per-target key-range-pass rule in the registry record.** The backward's key-range passes (L2-resident fp32 dK/dV slices for
  long key rows) are now chosen per architecture from the module table's `key_pass_policy` (`tail_rows`, `fixed_passes`,
  `min_kv`, `tail_min_kv`, `tail_cap`), measured with paired sweeps on SM100, SM103 and SM107. `KeyPassPolicy` evaluates the rule
  next to the L2 formula and the token chunk: a one-segment row takes the pass path when it is one launch chunk or — where the
  rule admits tail rows — when `2 T <= S`, with the rule's pass count; multi-segment rows and causal single documents stay
  single-pass. Records without the fields keep the first-release rule.
- **Token-chunked pass launches.** A multi-pass backward runs token chunk by token chunk, every chunk through every pass (launch
  keys `(stage, chunk, pass)`), so the pass scratch holds one chunk and rows longer than one chunk take the pass path exactly as
  the generator's own launcher does.
