> Developed by the **CAKE team**, the kernels in this PR **outperform** the relevant **SOTA baselines at the time of merge** on the **vast majority of performance benchmark shapes**, matching them otherwise.

## Summary

This PR cleans up the SM100/SM103 part of `csrc/cake_dsv4`, which backs `flashinfer.mla.trtllm_batch_decode_sparse_mla_dsv4(backend="cake")`.

- BF16/FP8 KV caches go through `run_cake_dsv4`. There are 27 variants per architecture, each a generated kernel and binding pair under `sm_100a/` and `sm_103a/`.
- `kv_cache_format="nvfp4"` goes through the NVFP4 decode templates in `common/`.
- The registry is `flashinfer/jit/cake_dsv4.py` (`_ARCH_REGISTRATIONS`). The host code is `flashinfer/mla/cake_dsv4.py`.

The PR has four commits:

1. Delete a host shim header that nothing includes, and bring the SM100/SM103 README up to date.
2. Delete the dead host descriptor pool and the retired host paths.
3. Move the 13 BF16/FP8 kernel pairs that are identical on both architectures into `common/`, so each is stored once instead of twice.
4. Give each NVFP4 decode template one launcher that takes its knobs as launch arguments. Decode modules per architecture drop from 16 to 7.
