## Summary

Regenerates the experimental `deepgemm_sparse_mqa` family (DeepGEMM PR432 sparse MQA indexer: metadata + logits kernels) as ten programs (six architecture-neutral, four exact-geometry metadata programs compiled per device SM count) with a registry-driven JIT loader and a lean host path.

Closes #5836

## What changed

- **Metadata kernels: one runtime program per KV layout plus one exact-geometry program per (layout, device SM count).** The runtime program takes the SM count, sparse-block capacity, split width, block size and page size as kernel arguments (fast integer division constants are computed on the host) and validates `1 <= num_sms <= 160` and `capacity <= 2048` against compile-time ceilings. The exact-geometry program compiles the production geometry in (capacity 2048, 8-token blocks, 64-token pages) together with the device SM count (`#define NUM_SMS`, 148 on B200 and 152 on GB300, the counts the shipped copies were compiled for): the SM count is used only by the last CTA that builds the per-SM schedule, a serial section where the shipped kernels' compile-time division is what the runtime-geometry build was missing. `metadata_route_key` selects the exact prog
<!-- upstream-excerpt-end -->
