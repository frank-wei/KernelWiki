## Summary

Structural cleanup of the SM100 / SM103 DeepSeek-V4 NVFP4 sparse-MLA decode delivery (#6103): same kernels, same host
Python path. No behavior, numerics or launch change: all fifteen device programs compile to the SASS they compiled to
before -- the eleven template instantiations against the per-knob programs they replace, the four standalone kernels
against their previous units (proof below).

- **Knob clones folded into kernel templates.** The eleven per-knob device units of three schedules (`swap` x6 =
  `tile_n` 16/32 x `o_chunks` 1/2/4, `tile` x3 = `o_chunks`, `pv` x2 = `tile_n`) become one translation unit per
  schedule (`common/cake_dsv4_nvfp4_decode_{swap,tile,pv}_kernel.cu`): the `__global__` kernel is the template
  (`__launch_bounds__` kept on it) with one explicit instantiation per knob cell. The loader still registers one
  entry and one binding per variant; a variant's module compiles the unit with its own `-D` selection and
  instantiates only its kernel. `persistent`, `cluster`, `t64` and the split merge stay one program each.
