## 📌 Description

Extend TMEM accumulator overlap in the Prims-TS NVFP4 dense GEMMs to the fused QKV + QKNorm + RoPE epilogue. Previously it was available for the linear epilogue and, with #6255, for SwiGLU.

**Depends on #6255 (approved).** The first two commits are #6255 unchanged; only the last commit is new. I will rebase once #6255 is merged.

TMEM overlap lets the MMA for the next output tile run while the current tile's epilogue is still writing results, hiding epilogue time.

QKNorm reads the whole head before normalizing, so this epilogue needs a small change to its store schedule: it keeps the first accumulator subtile in registers, releases the accumulator after the norm reduction, and then stores. This is supported for BF16 output with MMA-K 64. Overlap remains opt-in (`tmem_overlap=True` in `prepare_fp4_qkv_qknorm_rope`, also offered to the autotuner); defaults are unchanged and results are bit-identical to the non-overlap kernel.

Performance (GB300, NVFP4 QKV+QKNorm+RoPE GEMM, N=9216, K=3072, BF16 output): 1.34x faster at M=8832 (195 → 146 us) and 1.44x at M=33408 (765 → 533 us).
