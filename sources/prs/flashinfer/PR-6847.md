<!-- upstream-excerpt-start -->
**Proxy fence.** In the MiniMax-H3 dense attention kernel (`csrc/cake_minimax_h3_dense_attention_sm120a.cu`), the epilogue stages O in the Q shared-memory buffer through the generic proxy. The Q scaling writes that buffer too, and the epilogue reads it back for the output stores. The next work item's elected thread then refills the same buffer with a TMA load, which writes through the async proxy. The kernel did issue `fence.proxy.async.shared::cta`, but only at the start of the next work item, after the end-of-item `__syncthreads()`. A thread's proxy fence orders only that thread's own earlier accesses, so the other warps' generic accesses were never ordered before the TMA refill. Every thread now issues the fence after its last access of the buffer and before the end-of-item barrier, and the fence at the start of the item is removed.

**Ping-pong close.** The dense, FP8 varlen and NVFP4 varlen attention kernels alternate two warp groups on named barriers 1 and 2.
