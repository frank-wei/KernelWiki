## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
**Issue.** The FP8 page-32 decode program of the Cake Blackwell MLA backend (`csrc/cake_trtllm_mla_blackwell/cake_trtllm_mla_blackwell_79e49e216298d59fce33_kernel.cu`, route `mla_fp8_p32_qk_l2`, sm_100a and sm_103a) runs its softmax and correction roles on all four warps of a warpgroup. A `tcgen05.ld` / `tcgen05.st` from warp *w* of a warpgroup may access only TMEM lanes 32·(w mod 4) … 32·(w mod 4)+31, and the lane comes from bits 31:16 of the address (PTX ISA, tcgen05 memory-access restrictions). The softmax warps' `.16x256b` score loads and statistics stores, and the correction warps' statistics and output loads and stores, addressed TMEM from the allocation base (lane 0) in every warp, so warps 1–3 issued out-of-quarter accesses. GB300 serves such an access from the warp's own quarter, so results were correct on current hardware, but the code relied on behaviour that PTX leaves undefined.

**Change.** Every one of these accesses now adds the warp's lane base: `(tid & 96) << 16` in the two softmax roles, and the row offset the correction role already computes (`tmem_row_c`). No other program of the family uses `.16x256b` accesses.
