## 📌 Description

Add a CuTe DSL NVFP4 W4A4 routed-MoE backend for SM120/SM121 that consumes the same prepared NVFP4 expert weights and scales as the cuTile NVFP4 path and the SM12x W4A16 backend of #5735, **without additional weight preparation or a second weight copy**. With both SM12x backends reading one expert layout, a serving framework can pick W4A4 (prefill) or W4A16 (decode) per call over a single set of weights.

**Stacked on #5735**: the new runner subclasses `SM12xNvfp4Bf16Runner` (weight-view validation, per-bucket workspace). Until #5735 merges, the diff here includes its commits; the commits new to this PR are e270c166 (the backend) and b0f73fd0 (ReLU2 shape guard), plus merges of the #5735 branch.

Use it through the unified MoE API with `SM12xNvfp4Config` (runner `SM12xNvfp4Runner`, backend key `sm12x_nvfp4`). `prepare_weights` returns the cuTile NVFP4 view (`CuTileNvfp4Config` / `CuTileNvfp4Bf16Config` / `SM12xNvfp4Bf16Config`): packed E2M1 weights, 128x4-swizzled E4M3 block scales and per-expert FP32 global scales, which the kernels read in place. BF16 hidden states are quantized to NVFP4 inside the op with 16-element E4M3 block scales and a per-layer activation
