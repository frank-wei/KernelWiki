Follow-up to #6238 (merged). Same backend family as #5467 (@Vinnie6167, FYI). Cake GDN decode on SM107a (Rubin, CC 10.7) only; SM100a / SM103a kernel text is unchanged.

## What this PR does

Every Cake GDN decode kernel scales q by `(float)((double)x * SCALE)`. On SM107a that FP64 multiply is now lowered to an exact FP64-free helper, `cake_f32_mul_f64const_rn` (defined through `cake_gdn_device_common.cuh` from a content-addressed `csrc/cake_device_helpers/` file): bit for bit the same result as the FP64 form for every input, with no FP64 instruction on the normal-input path (the FP64 reference form stays out of line as `__noinline__` and is reached only for subnormal / NaN / infinite inputs or a non-normal result). The decode records therefore carry one kernel body per architecture view: the shipped SM100a/SM103a body stays byte for byte as `outputs[0]` and the SM107a view is a second output of the same record (same symbol, launch and host shim); SM107a-only records (`_vpre`, `_pro`, the SM107a band instances) get their re-derived body (the previous body files are replaced). No SM100a/SM103a kernel text or behaviour changes; outputs are bitwise identical on SM107a.
