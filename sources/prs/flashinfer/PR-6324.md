## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Developed by the **CAKE team**. FlashInfer's existing fused low-rank path, `mm_nvfp4_svdquant`, computes `alpha * (A @ W^T + D @ l1^T) + bias` and needs the LoRA-up weight pre-divided by `alpha` offline (a fold that re-rounds it to bf16); it has no SM90 or FP8 variant. This PR adds a sibling, not a replacement: the adapter is read as given at run time with its own `lora_scale`, for NVFP4 and FP8 bases. The per-shape tables below compare the generated programs loaded through FlashInfer against the Cake production launcher of the same kernels (the export's source arm) on real devices; they are not a comparison against other libraries.

## Update 2026-10-12 — R2-opt re-export (Cake `6808d3494681c5bd2d373af6301fd01c54ed9dfb`, export protocol p7)

This revision re-exports the family from Cake `6808d3494681c5bd2d373af6301fd01c54ed9dfb` after an optimization round on every performance row whose
fastest-baseline / candidate ratio was below 1.00, and rebases the branch onto upstream `main` (`f63b2e7cbfb9a008a3880ebf00f2bbf3721176fe`).
Everything is schedule-only: the kernel math, tolerances, fp32 accumulation and the per-row denominator are unchanged.
