## Summary

Re-renders the two Cake-exported Kimi-K3 W4A8 MXFP4 SiTU routed-MoE backends (`flashinfer/fused_moe/cake_mxfp4_situ_moe/` for `backend="cake"` and `cake_cute_mxfp4_situ_moe/` for `backend="cake_cute"`) from Cake revision `acf3ba642c1` (manifests pin `producer_revision` `acf3ba642c1039f44b4b86709b897ef4ab1a62cc`; previously `9316cbf49bd21548735f2d9720f2375b883a5c69`). Export + evidence only; no FlashInfer API change.

What the re-render brings (one Cake kernel-IR change lowered to both backends):

- **Device-side GEMM2 path gate on the tp8 long-prefill chain (T ≥ 16384)**: a one-warp gate kernel (`gemm2_gate`, PDL) launched right after `moe_sort` replays the dense GEMM2 kernels' own raster vote over the sort tables and selects the split or the dense GEMM2 path on the device. The plan runs a fixed 12-launch chain with both finalize paths bound to the gate words; the unselected path's launches exit with zero items, so CUDA-graph capture keeps one launch list. Before this change the path was fixed per row by the host.
