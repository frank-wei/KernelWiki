## 📌 Description

<!-- What does this PR do? Briefly describe the changes and why they’re needed. -->
Add `nvfp4_quantize_append_paged_mla_kv_cache`, the cache-write path for 512+64 MLA latent rows, as an MLA analog of `nvfp4_quantize_append_paged_kv_cache`.

The API quantizes `ckv` directly from FP16/BF16 to packed E2M1 with one FP8 E4M3 scale per 16 channels. The `kpe` part is stored as FP8 E4M3.

Cache layout:

- `ckv_cache`: `uint8 [num_pages, page_size, 256]`
- `ckv_sf_cache`: `float8_e4m3fn [num_pages, page_size, 32]`
- `kpe_cache`: `float8_e4m3fn [num_pages, page_size, 64]`

This uses 352 bytes per token, compared with 576 bytes for an all-FP8 layout, reducing the footprint by 39%.

We keep `kpe` in FP8 because DeepSeek-V2-Lite latent measurements show approximately 6x higher RMS energy in the RoPE channels than in the compressed-KV channels. In the same experiment, the selected `ckv-FP4/kpe-FP8` layout had relative L2 error against a BF16 attention reference of 0.092-0.102, compared with 0.074-0.078 for the FP8 baseline. Quantizing all 576 channels to FP4 increased the error to 0.174-0.193 and was rejected.
