## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Regenerated export of the Cake all-gather matmul backend from the same generator as #6254, rebased on `main`.
Two routing changes for the small-shard shapes, with the per-architecture constants they need in the JIT loader:

1. **128-wide main tile.** Every main program keeps its 256-wide tile; the five (world size, dtype, weight layout)
   classes with a routed inventory row also ship a 128-wide twin (`main_n128`, six pipeline stages, the same
   operand pool). A call uses the twin when the narrow tiles fill the SMs with fewer idle slots and the call has at
   most `N128_MAX_WAVES_BY_ARCH[arch]` 256-wide waves: **two on SM100a, one on SM103a** (the one-wave rows carry the
   gain on SM103a; the two-wave M=512 rows regressed there, so the cap differs per architecture). The host sequence
   takes the tile width as a positional `block_n` argument and rejects a width its route class does not ship.
2. **Wide SM push.** The SM push launch is chosen per call from the per-peer payload: below 4 MiB the existing
