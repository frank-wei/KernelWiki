Closes #5833

## What

The fused BF16 routing gate (`flashinfer.mega_gate.prepare_mega_gate`, `csrc/experimental/deepgemm_mega_gate`) shipped one ~900-line kernel per exact token count (M in 1, 3, 16, 128, 512, 1024, 2048, 4096, 8192 plus two M=16 feature routes) per architecture: 22 kernel + 22 binding files, ~32K lines, with the token count folded into each program and sm_103a copies that differed only in two address-lowering lines and one SM-count-derived stride.

This regenerates the family with the token count as a runtime argument:

- `num_tokens`, the SM-count-derived worker stride (`num_workers`) and the physical-map / logical-output flags (`route_flags`) are kernel arguments; the tail token tile keeps the source's geometry (the runtime programs set the MMA instruction's N field per tile from the 16-aligned valid token count, so they have one MMA site) and only valid tokens are ranked and written.
- The small physical-map token counts and the 2-16-token logical-output route keep an exact-shape program of their schedule (tile geometry, route and worker stride compiled in; five programs: 1 token, 2-16 tokens with a physical map, 2-16 tokens with a logical output, 97-128 token
