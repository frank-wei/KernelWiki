## Summary

The generated BF16 prefill portfolio behind `recurrent_kda(..., backend="cake")` on SM100/SM103 shipped one selector translation unit per module and per architecture under `csrc/kda/` (104 files) and a 17,208-line / 712 KB `flashkda_generated_variant_metadata.json` that re-hashed every generated source on first use. The two architecture copies of every selector differed only in `static_assert(FLASHINFER_FLASH_KDA_TARGET_MINOR == 0 / 3)`. This PR renders each selector from Python with the target define at JIT-spec creation, replaces the metadata with a compact module table (schema 2, 2,087 lines / 101 KB), resolves selectors through a tuple-keyed dictionary built once, derives the JIT/AOT cache keys from the compiled content instead of a hand-maintained ident table, and deletes a header that was byte-identical to an existing one.
