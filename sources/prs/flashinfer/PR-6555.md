## 📌 Description

`routingCustom::run` takes the split topK path (block-per-token scores kernel + post-topK pipeline, PDL-chained) instead of the fused single-cluster kernel whenever `numExperts >= 160` in the single-cluster batch range. A routing-only sweep on current kernels shows that rule is wrong in both directions:

- **Non-sigmoid-bias policies with E >= 160:** the fused single-cluster kernel is faster up to 64 tokens (the scores kernel + PDL handoff cost more than the cluster kernel's idle warps). Exception: E >= 512 with 10 <= K <= 16 from 32 tokens.
- **E < 160:** splitting is up to 2.4x faster once K >= 8 and tokens * K >= 1536. Today this range never splits.
- **Sigmoid+bias policies (DeepSeekV3 nGroup=1, MiniMax2) with E >= 160:** splitting stays best, so they keep the current behavior.

This PR replaces the `numExperts >= 160` condition with that rule. The `FLASHINFER_ROUTING_FORCE_BLOCK_PER_TOKEN` override, the static-block boundary, and all kernels are unchanged.
