## Summary

`deepgemm_fp8_gemm` shipped four raw PTX programs (13K lines) plus four 583-line
bindings for a single shape (M4096 / N7168 / K4096, forward and wgrad), assembled
at import time through a private `ptxas` subprocess pipeline (`ptx_builder.py`)
outside FlashInfer's JIT, with `csrc` resolved relative to the source checkout
and a catalog (`fp8_gemm_1d1d.ptx.v2`) pinning one SM count per architecture.

This PR regenerates the family as Cake CUDA source with runtime shapes and
removes the assembly pipeline:

- one generated kernel source + thin TVM-FFI binding per route (`forward`:
  BF16 output, `wgrad`: FP32 accumulate in place), shared by sm_100a and
  sm_103a; problem sizes, tile counts and the persistent CTA count are launch
  scalars, so any `M` / `N` and any `K` multiple of 128 run on the same
  programs (the previous programs refused everything but the one shape);
- `cake_jit.py` registers the programs and compiles them through
  `gen_jit_spec` with
