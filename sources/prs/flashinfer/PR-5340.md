## 📌 Description

`TopKSamplingFromProbKernel` and `MinPSamplingFromProbKernel` read their per-request threshold with the output position (`top_k_arr[bx]`, `min_p_arr[bx]`) and only afterwards resolve `row_idx = indices[bx]`. With `indices`, an output therefore gets the threshold of whichever row happens to share its position, not the row it samples from, and when `len(indices) > probs.size(0)` the lookup runs past the end of the tensor (its length is validated against `probs` in `csrc/sampling.cu`).

`TopPSamplingFromProbKernel` and `TopKTopPSamplingFromProbKernel` already index by `row_idx`; this makes the other two consistent with them. The change is the order of two lines in each kernel.

Before / after on the repro from the issue (RTX 4090 D, CUDA 12.8):

| case | expected | before | after |
|---|---|---|---|
| top_k, `k=[1,1,4]`, `indices=[2,2,2]` | all classes ×3 | `[0]`, `[0]`, all | all ×3 |
| top_k, `k=[1,4,4]`, `indices=[0,0,0]` | `[0]` ×3 | `[0]`, all, all | `[0]` ×3 |
| min_p, `min_p=[0.9,0.9,0.05]`, `indices=[2,2,2]` | all classes ×3 | `[0]`, `[0]`, all | all ×3 |
| top_k, `len(indices)=3000`, 3 rows | per-row k | reads past `top_k_arr` | per-row k |
