## Summary

Re-export of the `deepgemm_dense_mqa` family (dense 32-head and 64-head FP8 / FP4 MQA logits, paged FP8 MQA logits) from the producer tip that closes the current DeepSeek-V3.2 lightning-indexer performance round on SM100a / SM103a, onto `main`. The `cake_dsa_indexer` programs regenerated at the same producer tip are delivered separately. Catalog schema `dense_mqa.v8` -> `dense_mqa.v9`; 7 new kernel programs, 1 retired, 33 carried unchanged (40 catalogued programs; dense routes 27 -> 34, paged routes 13 unchanged).

### `deepgemm_dense_mqa`

1. **32-head FP8 / FP4 dense logits -- single-launch routes for every bounded query count.** Seven new routes (`fp8:{full,partial}:le32:short`, `fp8:{full,partial}:le768:short`, `fp4:q1:short`, `fp4:le32:short`, `fp4:le1024:short`) derive the ScheduleMeta partition (cost-balanced (q_block, split) assignment per CTA + per-block span words) in the logits kernel prologue instead of running the metadata kernel first: a warp-0 inclusive scan for up to 32 query blocks and a 384-thread CTA scan with carry above that, whose prologue-only scratch aliases KV stage 0 (dead until the pipeline roles start; `fence.proxy.async.shared::cta` + a CTA
