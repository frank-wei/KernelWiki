## What changes

The 32 `csrc/cake_router_gemm/cake_router_gemm_m{1..16}_k{6144,7168}_device.cu` programs are unchanged (byte-identical, same
compiled code); the loader, binding, dispatch and validation around them are replaced.

- **Standard JIT path.** `flashinfer/jit/cake_router_gemm.py` no longer shells out to `nvcc` and `load_inline`s a 150-line host
  stub string per (M, K, arch) (up to 64 builds that bypassed `JitSpec`, `FLASHINFER_CUDA_ARCH_LIST` and AOT). It is one
  `gen_jit_spec` module (`cake_router_gemm`) over the static 32-file source list plus one TVM-FFI binding
  `csrc/cake_router_gemm/cake_router_gemm.cu` on `tvm_ffi_utils.h`; the `-gencode` list comes from `CompilationContext` (every 10.x
  build target in one fatbin). The binding declares the 32 `extern "C"` programs, selects one from `mat_a.size(0)` / `mat_a.size(1)`
  and launches through `cudaLaunchKernelEx` with PDL as a launch attribute.
