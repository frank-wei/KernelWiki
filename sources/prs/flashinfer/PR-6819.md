## Upstream PR description (verbatim excerpt)

**Race.** These are 2-CTA (`cta_group::2`, cluster of 2) tcgen05 GEMMs. The leader CTA's MMA warp releases each stage of the TMA load ring with `tcgen05.commit.cta_group::2.mbarrier::arrive::one.shared::cluster.multicast::cluster` (mask `0b11`) on the stage-release mbarrier of both CTAs. The peer CTA's load warp waits that barrier only before a refill, so after its last refill it can leave the tile loop and the CTA can exit while the arrive-ons for the last ring-depth stages are still in flight toward its shared memory; an async arrive on the shared memory of a CTA that has exited is undefined (PTX ISA §2.2.2). PTX gives no ordering between two `tcgen05.commit` operations (§9.7.18.6), so the later accumulator-ready commit that the epilogue waits for does not cover the earlier stage releases, and the teardown cluster barrier does not either.

**Change.** After its tile loop the load warp (the same lanes that wait in the main loop) now waits the stage-release barrier for the last ring-depth stages, advancing its stage index and phase exactly as the main loop does (a producer tail, as in CUTLASS's `producer_tail`).
