## What changed

The Cake Kimi-K3 MLA FP8 paged-attention route behind `trtllm_batch_decode_with_kv_cache_mla(backend="cake")` is regenerated through its export adapter. No kernel schedule changes; the generated device code for each (kernel, architecture) is the same program as before (see SASS table below).

**Generated sources (`csrc/cake_kimi_k3_mla/`)**
- One source per kernel for both architectures: 9 of the 10 kernels (`main_rt16` .. `main_rt96`, `reduce_w1` / `reduce_w2` / `reduce_w4`, `reduce_cta`) are one program each; the shared-memory base conversion is an `#if __CUDA_ARCH__` guard inside the one source and each architecture's preprocessed text is its previous text. The wide decode kernel (`main_wide`) keeps one program per architecture: its sm_103a variant computes the row max with the TMEM reduction load, the sm_100a variant with a three-input max tree, and the two lowerings differ in too many statements to fold under architecture guards. 11 programs
