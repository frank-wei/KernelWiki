## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Adds the missing `__syncthreads()` before `AdvanceRadixGroupBarrier` at the two multi-CTA histogram-accumulation sites in `topk.cuh` (`RadixSelectOneRound` and `RadixSelectFromSharedMemory`).

**What the sync guards against.** Each CTA's threads accumulate their local histogram into the shared global histogram with per-thread `atomicAdd`, and the leading CTA's threads clear `next_hist`, immediately before the group barrier. The barrier's release is a thread-0-only `red_release`, whose fence — per its own comment — "releases data that was weakly-written by other threads **prior to the last syncthreads**". There is no `__syncthreads()` between those per-thread writes and the barrier, so the release does not cover them:

- a peer CTA can pass the barrier and read `current_hist` before some contributor's `atomicAdd` lands → undercounted histogram → wrong or CTA-divergent pivot → silently wrong renorm probabilities in top-k sampling;
- a peer CTA can start the next round's `atomicAdd`s into `next_hist` before the leader's lagging threads finished clearing it → contributions wiped by a late clear.
