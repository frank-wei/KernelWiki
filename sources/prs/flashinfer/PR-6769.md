## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
`cake_quant_lora_gemm` fuses a quantized GEMM (FP8 E4M3 or NVFP4) with a runtime BF16 low-rank LoRA term and BF16 output. The family ships 11 program variants: 6 FP8 and 5 NVFP4. This PR updates one SM90 FP8 variant, `fp8_sm90_hint` (form `acc2_hint`), with a weight-resident strip raster. The persistent tile walk now visits strips of 5 weight n-tiles across all activation m-tile pairs (n-tile fastest, serpentine between strips). A strip's weight tiles stay in L2 while the activation streams once per strip, and the TMA L2 cache policies follow that order (weights evict_last, activations evict_first). Only the tile order changes, and the output is bit-identical to the previous version. The baseline is the previous Cake version of the same program, already shipped in FlashInfer. The gain is small and limited to one row. The one shape that dispatches to `fp8_sm90_hint` (131072 x 8192 x 32768, rank 64) reads 56.54 vs 57.06 ms back to back (new / previous 0.9937; per-round range 0.9785 to 1.0214) and 50.23 vs 51.00 ms cooled (0.9848; per-round range 0.9743 to 1.0000). The other 59 of 60 shapes dispatch to the unchanged `fp8_sm90` program (form `acc2`) and are listed with the same measure
