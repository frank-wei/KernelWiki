## 📌 Description

This PR adds a UMMA (`tcgen05.mma` / TMEM) kernel for the GDN ReplaySSM decode step (verify + u-cache flush) on SM100 and serves it behind the existing `gated_delta_rule_mtp_ucache_flush` API. One kernel covers multi-token steps (T = 1..8), any value:key head ratio from 1:1 to 4:1, and a bf16 or fp16 u ring. The HMMA (`mma.sync`) kernel stays as the fallback for everything else (SM90, the other dtype arms, block-strided pools, `pdl_trigger`).

On B200 the new kernel is up to 1.46× faster than the HMMA kernel at the 4:1 geometry; at serving batch sizes (B ≥ 128) the speedup is 1.16–1.44× at T = 4 and 1.06–1.39× at T = 8 (tables below). The 3:1 geometry and standard decode (T = 1) run on the same kernel under the same contract; their UMMA numbers are in their own sections.

Co-authored with @Johnny-Liou.

### Why UMMA

- The HMMA kernel copies every operand tile from SMEM into registers with `ldmatrix` and accumulates in registers. At T = 4 only a quarter of each B tile is useful, so the kernel is bound by L1TEX / LSU rather than by memory.
