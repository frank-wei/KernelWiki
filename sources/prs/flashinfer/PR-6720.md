## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Cake ships the MiniMax-H3 fused RMSNorm + AdaLN + FC1 + SwiGLU operator in `flashinfer.diffusion_ops` (`minimax_h3_fc1_swiglu`) in three data-type variants: BF16, MXFP8 and NVFP4. Each variant is an activation norm/AdaLN(+quantize) prologue kernel plus an FC1 GEMM with a fused SwiGLU epilogue. This PR regenerates all three variants for SM100 (sm_100a) and SM103 (sm_103a). MXFP8 moves to a 256x448 GEMM tile with a new FC1 weight-scale preparation (`prepare_minimax_h3_fc1_swiglu_weight_mxfp8`). All three variants get programmatic dependent launch and packed BF16 epilogue rounding, and the MXFP8/NVFP4 prologue kernels (shared with `minimax_h3_mlp`) get cheaper scale arithmetic. The baseline is the previous Cake version of the same kernels, shipped in #6474. Latency is measured per operator call (norm/AdaLN kernel + GEMM) as the median over at least 2 s of CUDA-graph replay, in two independent rounds (r1 / r2) on the same GPU, over 24 production shapes (M = token rows, P = number of prompts sharing the AdaLN index).

**Geomean speedup (previous ms / this PR ms) over the 48 ratios per table (24 shapes x 2 rounds), with [min, max]. CUDA 13.1, PyTorch 2.10 (NVIDIA container 26.01).**
