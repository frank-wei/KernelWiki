producer:

  `chain_blocks(kmax) + 0.3 * (max_nsplit - 1)`. KMAX 3 has the same two-block chain as KMAX 4 and never fewer slices,
  so it is never selected (0 of 1,015,875 swept masks on 78/114/132 SMs). KMAX 1 was selected only on a band of ragged
  masks whose grid sits at the sliced-route edge (`2 * tiles` within two of the SM count) with one 13..31-block outlier
  selection, where KMAX 3/4/6 all exceed the one-wave item budget (28 of 1,015,875 masks); those masks now run the
  persistent kernel. The split table is `SPLIT_KMAX_VARIANTS = (4, 6)`; `plan_small` refuses a split plan for a variant
