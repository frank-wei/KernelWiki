## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
The Cake backend of FlashInfer's Mamba2 SSD combined chunk-scan prefill, `SSDCombined(backend="cake")`, ships three state data types (bf16, f16, f32) x two sequence layouts (batched, varlen) x these program forms: exact-scan (fused one-launch, preprocess+main two-launch, metadata+main two-launch, in-kernel-table one-launch, tail-wave pair, plus the no-ring exact-scan forms a route can select), look-back chunk-parallel and three-phase chunk-parallel. Since #6739 removed unreachable programs, the loader has 56 program entries, and the 45 entries on `sm_107a` are backed by 40 generated device sources. This PR re-exports the 13 `sm_107a` varlen exact-scan device sources (fused, two-launch ring and no-ring, one-launch; bf16/f16/f32). In the new sources, the X/dt loader passes each chunk's segment bounds through the input stage, so the three consumer roles read those bounds instead of loading the chunk table again. On capability (10, 7), the loader also sends full-grid two-launch calls to the tail-wave pair program when the saved wave beats the pair render's measured penalty (chunk floor: batched 16, varlen 8).
