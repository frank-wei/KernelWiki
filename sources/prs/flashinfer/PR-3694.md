## 📌 Description
## Summary

Add native FP8 e4m3 KV cache support to the Hopper SM90 MLA kernel (closes #2144). Eliminates SGLang's per-layer `.to(q.dtype)` cast workaround on FP8 KV deployments, saving one HBM round-trip per layer on DeepSeek-V3/V4.

## Approach

Hopper WGMMA has no BF16×FP8 mixed instruction, so the kernel keeps KV in FP8 through HBM/L2/shmem and dequants to BF16 in a shared-memory staging buffer just before WGMMA. WGMMA stays BF16×BF16 — bit-identical to the existing BF16 fast path. The dequant uses `vec_cast<bf16, fp8_e4m3>` (`fast_dequant_f8f16x4`) and applies the per-tensor scale in-kernel via packed `__hmul2`.

Shared-memory budget is tight (~225KB / 228KB) — FP8 KV halves the per-stage KV footprint, but the cross-stage BF16 staging buffers add it back; tracked by a defensive `static_assert`.

## Scope (locked)

- `q_data_type = torch.bfloat16`
- `kv_data_type = torch.float8_e4m3fn`
- `backend = "fa3"` (SM90 only; FA2 / CUTLASS rejected at plan time)
- `head_dim_ckv = 512`, `head_dim_kpe = 64` (DeepSeek-V3 shape; enforced by C++ `static_assert` + Python plan-time check)
