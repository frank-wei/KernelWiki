## Motivation

TileLang needs its own target layer above TVM Target so TileLang-specific hardware kinds, presets, driver-based auto detection, and execution backend preferences can be represented before TVM target validation. This lets TileLang add a new user-facing hardware target without first adding a TVM TargetKind, as long as the TileLang target kind can normalize to a TVM target input consumed by the current lowering/codegen path.

## Changes

- Add `TargetKind` plus a target-kind registry for hardware-owned normalization and auto detection.
- Add a target preset registry for aliases such as `h100` and `mi300x`.
- Register CUDA, ROCm, CPU, and Metal target kinds from their own packages instead of from `tilelang/backend/`.
- Move `auto` target resolution to registered driver detectors. CUDA, ROCm, and Metal now own their availability checks.
- Keep `execution_backend` as TileLang-only metadata and unwrap it before TVM sees the target.
- Add tests for target parsing, custom target kinds that do not require TVM TargetKind registration, registered auto detectors, and ROCm auto priority behavior.
