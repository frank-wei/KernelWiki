## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
`sync_grid()` currently selects every thread with `tid.x == 0`. With a 2D/3D block, multiple threads therefore publish the same block's arrival, allowing the grid barrier to release before another block has written its data.

Elect only physical thread `(0, 0, 0)` by combining all three thread coordinates. The counter/generation protocol, fences and cooperative launch remain unchanged.

The regression delays block 1 using a finite device-clock loop, then checks the cross-block result for `32`, `(32, 2)`, `(32, 1, 2)` and `(16, 2, 2)` threads, including repeated barrier reuse.

Validation on RTX 5090, Python 3.12, Torch 2.11.0+cu130 and CuTeDSL 4.7.0:

- Actual proposed test file, native CuTeDSL compilation and cooperative GPU launch: baseline **1 passed / 1 failed** with `-x` (2D result `[1, 3]` instead of `[3, 3]`); fixed helper **4 passed**, repeated in a second fresh process.
- Both arms used TileLang 0.1.15's native compiler/runtime; its unchanged `grid_sync.py` is byte-identical to main at `994b44e`. The candidate selected only the changed native Python DSL helper; this is not a full current-main C++ rebuild.
