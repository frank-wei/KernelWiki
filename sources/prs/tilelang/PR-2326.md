## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
HIP `cumsum` and `cummax` default to 64-lane segments, causing incorrect results on Wave32 GPUs. Make the existing `run` entry point select the target wavefront width, capped by the block's thread count. Preserve explicit `run<T, SEG>` calls and exclude the 64-lane template at compile time for 32-thread blocks.

Extend scan coverage with 32-thread forward/reverse scans and distinct source/destination strides. Update the gfx950 MXFP4 example and tests to use `{"kind": "hip", "mcpu": "gfx950"}`, since CLI target strings are no longer supported.

Validation:

- CUDA scan suite: 17 passed on NVIDIA B300.
- CuTeDSL scan source-generation tests: 2 passed with `nvidia-cutlass-dsl==4.7.0`.
- Scoped `./format.sh --files ...` and `git diff --check` passed.

AMD runtime validation remains for ROCm CI; no AMD GPU or HIP compiler was available locally.
