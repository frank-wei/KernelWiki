## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
A CUDA graph kernel node keeps the same `%gridid` on every replay. The `mega_mhc` split barriers tag executions with `%gridid`, so after a replay a barrier line still holds `encode_state(grid_idx, kNumSplits)` — exactly what the next replay waits for. A Mix or Norm waiter whose m-block init CTA has not started yet proceeds at once and reads the previous replay's split partials (the graph-pool scratch is the same memory). `wait_init` only protects producers.

This tags each execution with an epoch instead of `%gridid`. The epoch and an exit count live in the unused tail of the first barrier line, so the host-side barrier buffer and the compiled extension are unchanged (JIT headers only). Every CTA reads the epoch after `cudaGridDependencySynchronize()`; the last CTA to retire resets the exit count and advances the epoch.

The MegaMoE combine readiness has the same stale-tag problem and is addressed separately in #451.

Validation on B200: one graph node is replayed while alternating two input sets, and every replay is compared bit for bit with eager results (fresh JIT cache per run). Measured on 66081d4, whose versions of these headers differ from `main` only by an added `#include`.
<!-- upstream-excerpt-end -->
